## 学校专业招生计划数据体系
### 作用
- 建立 `Major` 专业主数据与 `EnrollmentOffering` 招生计划明细，学校、专业、层次、专业代码、总费用等业务事实进入数据库。
- `/courses` 课程列表显示总费用；有明确价格时显示 `¥总费用`，无价格时显示 `--`。
- 课程详情页展示招生院校与费用明细，包括学校、招生类型、层次、专业代码、年学费、总费用、缴费说明、报考费/免考费说明。
- 首页热门专业不展示价格，避免将 `HotMajor` 展示配置表作为价格事实源。
### 价格规则
- 同一专业多所学校有价格时，取最低总费用。
- 一个学校有价格、另一个学校无价格时，显示有价格的最低总费用。
- 全部无价格时显示 `--`。
- 表格层次为 `/` 或空白时，按同学校上一条明确层次继承；不得跨学校继承。
### 数据导入边界
- 当前项目文件中未找到完整招生表原文，因此本轮只完成结构、后台维护入口和现有课程/热门专业回填，不虚构招生明细价格。

## 2026-05-06 学院风采上传后无效与自动回种修复
### 作用
- 收口“后台学院风采上传成功但前台列表页不实时显示”以及“删空后自动恢复默认内容”的组合问题。
### 实证结论
- 后台两条上传链路均可成功：
- 编辑校区弹窗内的 `ImageField -> tempImages -> POST/PUT /api/campus`
- 图片管理弹窗内的 `ImageField -> POST /api/campus/[id]/images`
- 上传文件真实落盘到 `public/uploads/202605/...`，图片 URL 访问返回 `200`。
- 首页 `src/app/(web)/page.tsx` 中的学院风采会实时显示新图，说明上传、入库、首页消费链路正常。
- 更深层失效点在展示区读取链路：`src/app/(web)/page.tsx`、`src/app/(web)/campus/page.tsx`、`src/app/(web)/gallery/page.tsx`、`GET /api/campus`、`GET /api/campus/[id]`、`GET /api/gallery` 都会先调用 `ensureShowcaseSeedData()`，导致删空校区或证书风采后再次访问即自动回种。
- `npm run start` 使用 `scripts/start-next.mjs`，历史逻辑仅在 `.next/BUILD_ID` 缺失时才自动构建，因此代码更新后可能继续复用旧 build。
### 修复要求
- 首页、列表页、后台管理页与公开接口都必须只读取当前数据库真实记录，后台清空后前台显示空态，不允许运行时回种。
- `npm run start` 必须在检测到源码变化后自动重新 build。
- 不修改数据库结构，不改上传协议，不改后台管理交互。
### 隔离复测结果
- 使用临时数据库副本启动独立生产实例后，删除前 `campus=4`、`certificate=8`；删除后后台接口与公开接口均为 `0`。
- 在 `0/0` 状态下继续访问首页、`/campus`、`/gallery`，后台接口计数仍保持 `0/0`，证明读取页面不会再次触发自动回种。
