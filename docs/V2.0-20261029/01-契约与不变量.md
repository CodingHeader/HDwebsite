## 二、N-1 的唯一例外（本轮要处理的核心问题）

### 2.1 已发生的例外：88e72d69

该提交改了 `src/components/web/**` 的 `className` 值，**技术上违反 N-1**，但有用户 2026-10-29 的口头裁决。

**本轮的处置不是"回滚"，而是"补登记"**：

| 做法 | 说明 | 采纳 |
|---|---|---|
| A · 回滚 88e72d69 | 恢复 className 与 main 一致 | ❌ 用户要的移动端修复会消失 |
| B · 补 ADR 追认 | 记录例外范围、理由、影响 | ✅ **采纳** |
| C · 沉默处理 | 不记录，下轮验证自然会撞上 | ❌ 违反"行为留痕" |

**ADR-01 卡的产出就是这条追认记录。**

### 2.2 例外的边界（ADR 必须写清的 5 项）

补 ADR 时，例外必须**有界**，否则 N-1 事实上失效。ADR 须明确：

1. **文件白名单**：`src/components/web/FloatingContact.tsx`、`src/components/web/Navbar.tsx`、`src/components/web/data/home.ts`（仅此 3 个）
2. **改动性质**：仅允许「移动端响应式类」（`md:` 前缀的差异），桌面端渲染结果须与 main 一致
3. **理由**：用户 10-29 裁决的移动端遮挡/竖排问题
4. **不可外推**：不得据此认为其他前台文件可自由改 className
5. **后续任何前台改动**：须重新裁决，不得引用本条 ADR 作为通则

### 2.3 验证手段（可机检）

```bash
# 桌面端渲染一致性：只允许 md: 前缀的差异行
git show 88e72d69 -- 'src/components/web/**' | grep -E "^[-+].*className" \
  | grep -vE "md:|:md" | grep "^-" | head
# 期望：剩余差异均为非响应式类 —— 若有，说明超出「仅移动端」边界，须在 ADR 中额外说明
```

## 三、本轮各卡的契约边界

### E2E-01 · 只改测试断言

改动限于 `tests/e2e/hub-content.spec.ts` 的两行断言。

**风险**：若把 `getByText("草稿已入库")` 改成 `getByText("已入库")`，是**放宽**（更短子串可匹配更多）。必须用与新文案**语义等价**的定位。

### M3-01 · 可能触碰管理端令牌

改动对象是 `src/components/manager/ui/button-class.ts` 的 `sizes` 映射，或各页局部 className。

**契约判断**：
- `button-class.ts` **不在** `src/contracts/**`，属组件实现，**不触发 CCR**
- 但它影响 42 个管理端页 + 全部 manager 组件，**影响面等同一次令牌变更**
- 若改为 `h-11 md:h-9`，须验证**桌面端渲染零变化**（375px 才生效）

**`input` / `Select` 的同理**：搜索框 `343×36` 也需处理，涉及 `src/components/manager/ui/` 下的输入类。

### LCP-01 · 只改判据，不改代码

纯文档裁定。**禁止**为达模拟指标而改前台（冻结面）。

### ADR-01 · 只写文档

纯文档。**禁止**改代码或重建基线图。
