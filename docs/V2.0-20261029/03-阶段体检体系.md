# 03 · 阶段体检体系

> 原则（沿用 V1.8/V1.9）：**每张卡只跑它改到的检查**，全量回归只在 E1 跑一次，不新增门禁。

---

## 一、验收口径（重要）

**本轮的"通过"按逐项独立结果判定**：

即使本卡验收命令的一次整体执行返回非零（例如 `A && B && C` 中 C 失败），**只要逐项分别 exit 0 即算通过**。证据中必须写清每条命令的独立结果，不得只写整体退出码。

理由：`&&` 链会掩盖前置命令的真实结果；且部分命令（视觉、e2e）有已知环境噪声，不宜拖垮整卡。

---

## 二、逐卡定向检查

### ADR-01 · 前台冻结例外追认

**不做代码检查**，做文档完整性检查：

```bash
# 1) ADR 五要素齐全（文件白名单 / 改动性质 / 理由 / 不可外推 / 后续须重裁）
grep -cE "^## (背景|决策|影响|边界|不可外推)" docs/design/03_solution/decisions/ADR-*-*.md | tail -1

# 2) 例外范围与实际改动文件一致
git show 88e72d69 --name-only --format="" | grep -E "components/web|app/\(web\)"

# 3) 无代码改动
git status --short src/ | head
```

**PASS 标准**：ADR 含 5 要素 ∧ 白名单与实际改动文件一致 ∧ `src/` 零改动。

### E2E-01 · 断言同步

```bash
# 1) 只改了这个文件
git status --short tests/ | head

# 2) 跑该 spec
npx playwright test -c tests/e2e/playwright.config.ts hub-content
```

**PASS 标准**：`hub-content` spec 全绿（原 2 FAIL 归零）∧ 只改该文件 ∧ **断言未被弱化**。

**断言弱化检查（人工必看）**：
```bash
git diff tests/e2e/hub-content.spec.ts
# 若把 "草稿已入库" 改成 "已入库"，须确认「已入库」不会误匹配其它 toast
```

### M3-01 · 命中区

```bash
# 1) 类型与构建
npx tsc --noEmit
npm run build

# 2) 桌面端零变化（关键）
# 375 视口才提升，桌面必须仍 36px
npx playwright test -c tests/e2e/playwright.config.ts mobile-375

# 3) 尺寸复测
npx tsx .cache/v20-m3/measure.mjs
```

**PASS 标准**：
```
375px 视口下：核心控件 getBoundingClientRect() ≥ 44×44
桌面端（≥768px）：控件高度仍为 36px（h-9），无变化
M3 的 40 FAIL → 0（或明确记录剩余 + 原因）
```

**必测控件**（`evidence/V19/B3/defects.md:22-28`）：
- `新建` 按钮（CrudPage 页头）
- 搜索输入框
- `content-hub 新建内容`、`notify-rules 编辑`、`collect-items 审阅`
- `login` 输入框与登录按钮

### LCP-01 · 测量口径裁定

**不做代码检查**，做文档检查：

```bash
ls docs/design/06_validation/evidence/V20/LCP-01/
grep -nE "口径|模拟|真实|以.*为准" docs/design/06_validation/evidence/V20/LCP-01/*.md | head
```

**PASS 标准**：裁定文档明确「以哪个口径为准」∧ 说明为何排除另一口径 ∧ 不改代码。

### E1 · 收口

**唯一一次全量（串行，逐项记录）**：

```bash
npm run lint        ; echo "lint exit=$?"
npm run typecheck   ; echo "typecheck exit=$?"
npm test -- --no-file-parallelism ; echo "test exit=$?"
npm run build       ; echo "build exit=$?"
npm run test:visual ; echo "visual exit=$?"
npm run test:e2e    ; echo "e2e exit=$?"
```

**必须逐条记录 exit code**，不得用 `&&` 串联（见 §一）。

## 三、环境陷阱（沿用 V1.9 经验）

| 陷阱 | 处置 |
|---|---|
| `npm test` 多 worker 抢 SQLite → 假红 | 加 `--no-file-parallelism` |
| 登录限流 `10/60s` | 用 `storageState`，登录 ≤2 次 |
| 手工起服务缺 `JWT_SECRET` | 复用 `tests/e2e/global-setup.ts` |
| win32 视觉像素差异 | 不采信，记 UNKNOWN，靠 CI |
| 基线 stale（`ad4cf70e` < `88e72d69`） | 视觉 FAIL 中需区分「字体差异」与「基线陈旧」，见 ADR-01 |

| 时点 | 动作 |
