# HDwebsite upgrade 剩余工作并行规划包（2026-10-13）

**基线**：`upgrade@bb2c0e5`（P0~P06 已完成并通过独立校验）。**范围**：原 P07 组件 ~ P15 资源 9 个方向 + P02~P06 留下的全部承接项，重排为 **Wave 0（串行冻结）→ Wave 1（5 条执行线并行，默认由 3 名执行者承担）→ Wave 2（集成、守卫与终审）**，共 60 张原子任务卡。

## 已定执行方式（2026-10-13 你的裁决：D8 推送分发、执行者 2 名）

- **执行者 Y**：先当契约员做 Wave 0，再依次做 B → C → D。交给他：`prompts/执行者Y说明-契约与后端平台线.md` + 其中列出的 4 份提示词。
- **执行者 X**：Wave 0 期间验收 Y，然后依次做 A → E，最后主持 Wave 2。交给他：`prompts/执行者X说明-管理端UI线.md` + 其中列出的 3 份提示词。
- 两人互为独立验证者（只看对方的 diff 与命令结果）。计划工期约 **36.5 人天**（Wave 0 5 天 → Wave 1 约 24.5 天 → Wave 2 约 7 天）。

## 通用用法（其他人数时）

1. 先把 `prompts/提示词-W0-契约员.md` 交给 1 名执行者，完成 Wave 0（约 5 人天），产出 tag `w1-base`。
2. 然后**同时**开工（彼此不需要沟通）。默认 3 名执行者：UI 执行者依次做 A、E 两份；平台执行者依次做 B、C；运维执行者做 D。你批准 5 名时，下面 5 份各给一人：
   - `prompts/提示词-A-管理端组件库.md`
   - `prompts/提示词-E-管理端页面与功能.md`
   - `prompts/提示词-B-API与响应平台.md`
   - `prompts/提示词-C-AI与知识库.md`
   - `prompts/提示词-D-运维性能配置存储资源.md`
3. 每个工作包结束，用 `prompts/提示词-独立验证者.md` 另开会话验收（只看 diff + 命令结果，输出 PASS/FAIL/UNKNOWN）。
4. 五线全部 PASS 后，用 `prompts/提示词-W2-集成与终审.md` 合并、回归、终审、推送、打包。

两种模式的工期（35.0 / 29.5 人天）与启动顺序见 `12-前提局限与启动顺序.md`。
