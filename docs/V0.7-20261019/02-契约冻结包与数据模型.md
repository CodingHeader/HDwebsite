## 2. Identity 补充规则（M-15，V7-SEC 的验收依据）

记调用者为 C，目标角色为 R，目标用户为 U：

1. **R1 授权子集**：C 非超管时，写入的 `permissions ⊆ C.permissions`，否则 403。
2. **R2 超管标志**：只有超管能把任何角色的 `isSuper` 从 false 改为 true 或反之；`slug=super-admin` 内置角色不可改（现有规则保留）。
3. **R3 不改自己的角色**：C 非超管时，不得修改 `C.roleId` 对应的角色定义，也不得修改自己的 `roleId`。
4. **R4 角色分配**：C 非超管时，分配给 U 的角色 R 必须满足 `!R.isSuper ∧ R.permissions ⊆ C.permissions`。
5. **R5 超管账号保护**：C 非超管时，不得对 `U.role.isSuper` 的用户做任何 PUT/DELETE（含重置密码、停用）。
6. **R6 最后一名超管**：任何人不得让活跃超管数变为 0（停用、删除、改 roleId 三条路径都拦）。
7. 判定一律以 `isSuper` 字段为准，不以 slug；权限比较在服务端从数据库取 C 的当前角色，不信任 JWT 中可能过期的 permissions。
