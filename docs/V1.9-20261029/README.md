## 六、执行协议

1. **按 §4 关键路径顺序取卡**，每卡开工前 `git pull --ff-only origin upgrade`。
2. 只在本卡「允许修改」路径内写入；越界即 FAIL。
3. **每卡只跑定向检查**（见 `03-阶段体检体系.md`），全量只在 E1 跑一次。
4. 每卡完工：小提交 → 推送（**须用户批准**）→ 回填 `state.json` → 写证据。
5. **同一张卡连续 2 次 FAIL 即熔断**，改写卡片或标 `blocked` 上报。
6. **发现新缺陷不自行扩范围**：记入 `05-风险与待裁决.md`，交规划者排卡。
