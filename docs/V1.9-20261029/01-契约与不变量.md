## 二、本轮涉及的契约边界

### 2.1 FIX-01（空态动作）—— 不碰契约

改动限于 `src/app/manager/*/page.tsx` 的 `emptyAction` 传参与 `src/components/manager/CrudPage.tsx` 的空态渲染。

**判据**：`CrudPage` 的 `CrudPageSpec` 接口**已有** `emptyAction` 相关能力（走 `DataTable` 的 `emptyAction?: ReactNode`，`DataTable.tsx:93` 已定义）。**属接口内实现，无需改契约。**

⚠️ 但若某页需要新增 spec 字段（如 `emptyActionLabel`），则**超出接口**，须先写 CCR 并停止该页。

### 2.2 FIX-02（toast 实体名）—— 可能触碰 `src/contracts/common.ts`

`toastCopy` 定义在 `src/contracts/common.ts:88-100`。

**这是冻结面（N-2）。** 三种可选路径：

| 路径 | 做法 | 是否需 CCR |
|---|---|---|
| A | 不改 `toastCopy`，在各页 `toast.success()` 的 **description** 参数传实体名 | **否** |
| B | 扩展 `displayName()` 候选键（`CrudPage.tsx:128` 的数组） | **否**（属组件内实现） |
| C | 修改 `toastCopy` 文案本身 | **是** |

**裁决：只允许 A 和 B。C 一律禁止**——`toastCopy` 是跨 52 路由共用的文案契约，改它等于改全站措辞。

F-02/08 的根因是 `displayName()` 取不到名称（候选键无命中 → 回退 `#id`），**路径 B 正好对症**：
```ts
// CrudPage.tsx:128 现有
for (const k of ["title", "name", "username", "label", "nickname", "code", "email", "elementId"])
```
`banners` 与 `enrollment-offerings` 的 labels 里无这些键（banners 只有 image/link/sort/status），需按页确认是「补 spec 的 `primary` 列」还是「扩 `displayName` 候选键」。

### 2.3 FIX-03（`collect-tasks` 搜索）—— **可能触碰后端契约**

根因：`src/lib/crud-resources/collect.ts:32` `searchFields: []`。

`searchFields` 是 `src/lib/crud-resources/` 的**资源注册配置**，不是 zod 契约，**但它决定 `/api/collect-tasks?keyword=` 的行为**（等于 API 契约的一部分）。

**三种可选路径**：

| 路径 | 做法 | 是否需 CCR | 风险 |
|---|---|---|---|
| A | `searchFields: ["source"]`（关联字段名） | 否 | 需确认 Prisma 能否对关联字段做 `contains` |
| B | 前端对该页隐藏搜索框（`searchFields` 空则无搜索语义） | 否 | 改 UI，属"绕开"而非修复 |
| C | 不动，改判据为 N-A | 否 | 承认"该页不支持搜索"，但 `CrudPage` 仍渲染搜索框 → UX 误导 |

**裁决：优先 A。** A 不成立时退 B（隐藏搜索框，因为 `searchFields: []` 本就表示"不可搜"）。**C 不采纳**——搜索框还在页面上，用户输入无效却无反馈，这是真缺陷。

**若 A 需要改 Prisma 查询构造逻辑（`src/lib/crud-*.ts` 的通用过滤器），则超出 FIX-03 范围**，须拆新卡。
