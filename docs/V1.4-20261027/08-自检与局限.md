## 二、局限与如实说明

### 2.1 一处刻意偏离规划模板（并说明理由）

**模板要求**：「第一刀必须是步行骨架（健康检查 + 一个鉴权过的写接口 + 一张表 + 一次迁移 + 前端能打到真实 API 的页面 + 统一错误响应）」。

**本轮未照做**，理由：
- 该项目已有 126 个 API 路由、48 个模型、79 个 e2e 用例在跑 —— 骨架在 V0.5~V1.1 阶段早已建成。
- 若强行造一个"新骨架"，等于**为满足模板而新建无用代码**，直接违反「不得为凑数伪造任务」。

**替代方案**：本轮第一刀设为 `V14-BASE-01`（基线固化），其作用是**让后续每刀的验收有可信基准**——功能上等价于骨架的"可观测性基座"。

### 2.2 未做的事（明确边界）

| 项 | 原因 |
|---|---|
| 真实微信/SMTP/Coze 联调 | 凭证缺失（`AGENTS.md §2` 已授权 mock + UNKNOWN） |
| 126 个 API 路由逐行审计 | 抽样审计；全量逐行不在单轮可行范围 |
| Lighthouse 数值 | 无浏览器 CI 环境；装包属依赖变更需 CCR |
| 前台 a11y 现状 | 从未扫描，属 `V14-A11Y-01` 交付物 |
| visual 非 Linux 环境表现 | 字体渲染差异，无需（只认 Linux CI） |
