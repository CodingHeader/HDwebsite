## 二、三条口径纪律（有实测教训）

### 2.1 构建时间戳（V13 教训）

任何 e2e 结论必须附：

```
BUILD_ID mtime = <ISO>
src 最新 mtime = <ISO>
关系 = fresh / stale（stale 则结论作废）
```

`tests/e2e/global-setup.ts` 已硬校验（stale 直接抛错）。

### 2.2 串行执行（V13 教训）

**禁止**并行跑 `npm run build` 与 `npm test`。实测并行会造 `Hook timed out in 10000ms`（2 文件），单跑/串行全绿。

### 2.3 visual 只认 Linux CI（V0.7 起）

- 参照图在 Linux/CI 生成（45 张）。
- Windows 字体渲染差异无法与真实样式差异分离。
- 基线重生成只能 `workflow_dispatch` + `visual_update_ref=true`。
- **新增（V14）**：单次绿不算数，须**连续 ≥2 次**普通 run 全绿（`V14-VIS-STAB-01`）。

## 四、REQ-F-015「顶级体验」的可验收量化（消歧 A1/A3）

原文「顶级设计」「极度友好」不可验收，本轮量化为 8 条可查项：

| # | 可查项 | 检查方式 |
|---|---|---|
| Q1 | 每页有 PageHeader（标题/描述/主操作） | 代码审阅 + 矩阵 |
| Q2 | 无原生 `<table>/<input>/<select>/<button>` | `grep` 空输出 |
| Q3 | 无 `window.confirm` / `alert(` | `grep` 0 命中 |
| Q4 | 五态组件化（空/加载/错误/无权限/成功） | e2e `ux-states` |
| Q5 | 键盘可达（焦点陷阱/Esc/⌘+S） | 组件代码 + e2e |
| Q6 | 375px 核心操作可完成 | 375 e2e + 命中区 ≥44px |
| Q7 | axe serious/critical = 0 | CI a11y 步骤 |
| Q8 | 只用 `mgr-*` 令牌，无全局污染 | `globals.css` 审阅 |

## 五、完成定义（全项目唯一口径，摘自 AGENTS.md §6）

```text
Done = 所有权内 diff 符合任务
     ∧ 验收条目逐条有结果（PASS / FAIL / UNKNOWN）
     ∧ 自动测试或脚本可复现
     ∧ evidence 能让一周后的人复现，不用问原作者
     ∧ 守卫通过（契约测试 / 边界检查 / 根目录污染 / 密钥扫描 / 相关单测）
     ∧ 无新增同类错误记录
     ∧ 未修改冻结契约（除非本任务就是改契约）
```

## 六、防自证循环

| 角色 | 职责 | 禁止 |
|---|---|---|
| 规划（本轮） | 写定验收标准 | — |
| 执行 | 完成实现 + 写证据 | 不得改本卡验收标准 |
| 独立验证 | 只看 diff + 运行结果，出 `verify.md` | 只输出 PASS/FAIL/UNKNOWN，不写长篇解释 |

**执行者 ≠ 判定者**。每卡完成后须由另一会话/Agent 出 `docs/design/06_validation/evidence/V14/<卡号>/verify.md`。

## 七、失败分级

| 级别 | 定义 | 处置 |
|---|---|---|
| P0 | 主门禁（1~9）任一 FAIL | 阻断交付，立即修 |
| P1 | visual / a11y / 冻结面守卫 FAIL | 阻断该方向收口 |
| P2 | 性能未证明 / 需求台账未对齐 | 本版内解决 |
| P3 | UNKNOWN（凭证/环境） | 登记原因，不计入完成 |
