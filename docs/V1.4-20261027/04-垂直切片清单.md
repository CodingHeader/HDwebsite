# 04 垂直切片清单与排序（V1.4）

> 切片是**端到端可演示行为**，不是技术层。每一刀结束后，用户主路径必须多一个可演示的行为。
> 本项目已过"步行骨架"阶段（126 路由 / 48 模型 / e2e 79 已在跑），故本轮的切片全部是**质量闭环切片**——
> 每刀交付的是"一个此前无法证明的能力，现在可以证明了"。

## 1. 为什么本轮不是"功能切片"

**事实**：`parity-matrix.md` 对等主表 57 行 = present 50 + replaced 7，**missing 0 / partial 0**（本轮复核未发现无代码的功能项）。
**推论**：再切"功能刀"只会重复造已有的东西。真正的缺口在**"实现正确性"与"需求可证明性"**（V1.3 已确认 12 条缺口 G1~G12，其中 6 条未处理）。

因此本轮切片按"**把不可证明变成可证明**"来切，每刀都要产出一个新增的、可复跑的守门证据。

## 3. 排序与理由

```text
        ┌─ S4 visual 稳定性（只读，随时可跑）
        │
S 起点 ─┼─ S1 a11y 门禁 ──┐
        │                  ├─ S7 冻结面守卫（同改 ci.yml，串行于 S1）
        ├─ S2 UI-HUB ──────┴─ S3 一致性抽检（同碰 components/manager）
        │
        ├─ S6 性能基线
        │
        └──────────────────── S5 需求台账（需全部证据）── S8 收口
```

| 排序 | 切片 | 理由 |
|---|---|---|
| 1 | **S2 UI-HUB** | 唯一涉及**设计判断**的刀，不确定性最高，应先暴露风险；且它解锁 S3 |
| 2 | S1 a11y | 解锁"质量守卫"能力，且与 S2 文件不相交可并行 |
| 3 | S7 冻结面守卫 | 与 S1 同改 ci.yml，必须串行在其后 |
| 4 | S4 visual 稳定性 | 主要是等待 CI，越早启动越好（可与 1~3 并行） |
| 5 | S3 一致性抽检 | 依赖 S2 完成 |
| 6 | S6 性能基线 | 独立，随时可做 |
| 7 | S5 需求台账 | **必须最后**（引用全部证据） |
| 8 | S8 收口 | 最后 |

## 4. 可并行组（附机械依据）

| 组 | 切片 | 满足的规则 |
|---|---|---|
| **G-A** | S2、S1、S6 | ①无共享可变状态（S2 改 manager 页面/组件；S1 改 ci.yml + tests/a11y；S6 只写 evidence + 可选 scripts）②契约已冻结且机器可校验（zod）③文件所有权不相交 ④不共用迁移版本号（本轮 0 迁移） |
| **G-B** | S4 | 只读 + 等 CI，与任何组并行 |
| 串行 | S1 → S7 | 同改 `.github/workflows/ci.yml` |
| 串行 | S2 → S3 | 同碰 `src/components/manager/**` |
| 串行 | 全部 → S5 → S8 | S5 需引用所有证据 |

**不满足任一条即串行**，不允许"应该可以并行吧"这类判断。

## 5. 关键路径

```text
S2 (UI-HUB，最不确定) → S3 (一致性抽检) → S5 (需求台账) → S8 (收口)
```

S2 是关键路径起点：它既是唯一需要设计判断的刀，又阻塞 S3，而 S3 的结论要被 S5 引用。
