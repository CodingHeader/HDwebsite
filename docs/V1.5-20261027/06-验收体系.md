# 06 · 验收体系与阶段体检

## 一、本轮体检策略（用户指令落地）

### 1.1 原则

```text
单张卡只跑它改到的测试。
每个阶段做完，只给这个阶段动过的模块体检一次。
全量回归等全部完成或发版前统一跑一次。
```

### 1.2 为什么本轮可以这样（不是偷懒，是有依据）

**依据 1**：V1.4 的 BASE-01 已把七道门禁全跑过一遍并留证（`evidence/V14/BASE-01/execution.md`）。基线是绿的。

**依据 2**：V1.5 的 7 张卡里，**6 张不碰 `src/**`**（只写 docs/evidence 或一个 scripts 文件）。对不碰业务代码的改动跑全量门禁，边际收益接近零。

**依据 3**：成本实测量级 —— `test:e2e` 单轮约 3 分钟（V1.4 实测 79 例）。7 卡 × 3 分钟 = 21 分钟纯等待，而期间无任何 `src/**` 变化，跑出来必然还是绿。

**反向风险（自我否定）**：如果某张卡意外改了 `src/**` 导致回归却因没跑全量而漏掉？
→ **防守**：每卡验收条目里都有"`git diff --name-only` 必须只含允许路径"这一条。越界即 FAIL，不依赖测试发现。

## 三、完成定义（全项目唯一口径）

```text
Done =
  所有权内 diff 符合任务
  ∧ 验收条目逐条有 PASS/FAIL/UNKNOWN 结果
  ∧ 自动测试或脚本可复现
  ∧ evidence 能让一周后的人复现，不用问原作者
  ∧ 守卫通过（本轮为：check:root + check-frozen + 各卡专项）
  ∧ 无新增同类错误记录
  ∧ 未修改冻结契约
```

## 四、三张验收卡的判据定义（本轮最需要写清的部分）

### 4.1 五态覆盖（V15-UX-STATES-01）判据

对 42 页逐页判：**运行时能否通过 UI 触达该态**。

| 态 | 如何判定"可触达" | PASS 的最小证据 |
|---|---|---|
| 空态 | 列表筛到 0 条 / 用空数据条件 | 截图或文字描述 + 看到"下一步动作"文案 |
| 加载态 | 网络限速（DevTools Slow 3G）后刷新 | 看到骨架屏，非白屏 |
| 错误态 | 阻断 API（DevTools 或停服务）后操作 | 看到错误说明 + 重试按钮 |
| 无权限态 | 用 VIEWER 账号访问 EDITOR 功能 | 看到 `Forbidden` 说明 |
| 成功态 | 完成一次写操作 | 看到 toast 文案（非"操作成功"泛词） |

**降级规则**：若某页是纯只读（如 `logs`），写操作态记 `N-A(纯只读页)`，但必须写依据。

**不得**：仅在代码里 grep 到 `EmptyState` 就判 PASS —— 那是"有代码"不是"可触达"（历史坑 H4）。

### 4.2 键盘可达（V15-KEYBOARD-01）判据

按 `01 §B1` 默认方案 A（**最小集**）：

| 项 | 判定 | PASS 条件 |
|---|---|---|
| K1 Tab 顺序 | 从页面首元素 Tab 到末元素，顺序符合视觉顺序 | 无明显跳跃/回跳 |
| K2 主操作可聚焦 | 新建/保存/提交按钮可 Tab 到达并 Enter 触发 | 焦点可见 + 触发成功 |
| K3 Esc 关闭 | 弹窗打开后按 Esc 关闭 | 弹窗消失，无副作用 |
| K4 焦点可见 | 每个可聚焦元素有可见 focus ring | 目视可见 |

**明确不在本卡范围**（列入 07 §待裁决 B1）：
- 焦点陷阱（`grep -c "FocusTrap"` = 0，全站未实现）
- ⌘/Ctrl+S 提交（`grep -rn "metaKey\|ctrlKey.*KeyS"` 需核实）

**若按完整集判，42 页会全 FAIL** —— 那等于要求重做管理端，超出验收轮范围。故按 A。

### 4.3 375px 可用（V15-MOBILE-375-01）判据

| 项 | 判定 | PASS 条件 |
|---|---|---|
| M1 无横向溢出 | `document.documentElement.scrollWidth <= 375` | 无横向滚动条 |
| M2 核心操作可达 | 列表页：搜索 + 新建 + 行操作；表单页：提交 + 取消 | 均能点到并生效 |
| M3 命中区 ≥44px | 主要按钮/链接的可点区域 | DevTools 量测或视觉估计 ≥44×44 |
| M4 卡片模式 | 列表页在 375 下切卡片布局（`CrudPage` 注释第 6 行声明） | 非表格横向滚动 |

**前置条件**：必须先 `npx tsx prisma/seed-visual.ts` 或 `prisma/seed.ts` 固定数据 —— 否则空库页面高度不稳定，判定不可复现（V1.4 实测事故：3389 vs 6204）。

## 五、防自证循环

| 角色 | 谁 |
|---|---|
| 写验收标准 | 规划阶段（本文，main-agent） |
| 执行实现 | 外部助手（S0/S1/S3）+ main-agent（S2 验收） |
| 判定 PASS/FAIL | S2 由 main-agent 判定（V1.4 的代码是外部助手写的，符合"非同一人"） |

**S2 的特殊处理**：三张验收卡由 main-agent 执行。这不是自证 —— 因为 V1.4 的 `src/**` 代码由外部助手完成（`f9854f7`、`49aaf04` 等），main-agent 是独立判定方。且判定结果需外部助手在 S3 交叉核对证据完整性。

## 六、证据要求（每卡必含）

```text
docs/design/06_validation/evidence/V15/<卡号>/
  ├── execution.md     5W1H + 改动文件 + 验收逐条 + 命令输出 + UNKNOWN
  └── <专项产物>       如 matrix.md / whitelist.md
```

**验收条目必须写"判据"不只写"结论"**：
- ❌ `| articles | PASS |`
- ✅ `| articles | PASS | 空态：筛选"不存在关键词"→ 显示"没有匹配结果 + 新建按钮"；加载态：Slow 3G 刷新 → 看到 3 行骨架 |`
