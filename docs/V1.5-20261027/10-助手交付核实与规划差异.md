## 二、两处偏差的根因

### 偏差 A：台账未回填

**现象**：五卡证据齐全、提交齐全，但 `state.json` 未改。

**根因**：`V14-REL-01` 卡的任务定义（`tasks/V14-REL-01.md`）只要求"V1.3 六卡标 superseded + changelog + parity + 双端"，**没有要求回填 V1.4 自身的五卡状态**。助手严格照卡执行，故未做。

**这是任务卡缺陷，不是执行失误。** 已在 V1.5 的 `V15-LEDGER-01` 中补上。

### 偏差 B：PageHeader "缺失 29" 被当作成果

**现象**：助手把 `PageHeader 缺失 29 页` 写进交付清单，作为审计发现。

**根因**：`scripts/audit-manager-ui.mjs:28` 的判定

```js
const PAGEHEADER = /<PageHeader\b/;
```

只匹配页面文件里的字面量。助手按脚本输出如实汇报，**没有义务怀疑自己的工具** —— 但作为规划方，我必须指出脚本错了。

**量化误判规模**：

```bash
# 未直接引用 PageHeader 的页面
for f in $(find src/app/manager -name page.tsx); do
  grep -q "PageHeader" "$f" || echo "$f"
done | wc -l
# → 29

# 其中使用 CrudPage 的
# → 27

# 真正无 PageHeader 的
# → 2（news 是 redirect、login 用 h1）
```

**真实缺口 = 0。**
