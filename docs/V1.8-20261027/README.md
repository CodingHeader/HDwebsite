## 三、为什么是这 16 个阶段（去重逻辑）

四套台账的待办有大量重叠。归并规则：

| 来源 | 原始待办 | 归并后 |
|---|---|---|
| V1.4 state | 9 卡全 done | **0 项**（无遗留） |
| V1.5 state | 4 卡 ready（UX-STATES/KEYBOARD/MOBILE/CLOSE） | **B1/B2/B3 + E1** |
| V1.6 state | 同上 4 卡（V1.5 的执行细化） | 与 V1.5 完全重复 → **去重** |
| V1.7 state | WP1/WP2/WP3/WP4 ready + DEFERRED | **A1~A8**（WP1 拆 5 阶段，WP2/3/4 各 1）+ DEFERRED 保留 |
| V1.7 退化清单 | P2 两项（showcase / API 缓存） | **C1/C2** |
| REQ-LEDGER UNKNOWN | 12 条 | 7 条真实凭证依赖（不做）+ Lighthouse + 部署演练 → **D1/D2**；2 条"独立验证者未执行"→ **B1~B3** |
| backlog.md | 12 项 | **全部已实现**（核实见 00 §三）→ **0 项** |

**关键判断：V1.5 与 V1.6 的 4 卡是同一批工作**（V1.6 只是 V1.5 的执行细化），不能算两份待办。

## 四、执行原则（用户明确要求）

```text
每张卡只跑它改到的测试。
每个阶段结束做一次体检。
全量回归只在最后跑一次。
不设门禁。
```

**落地方式**：

| 原则 | 怎么落 |
|---|---|
| 单卡只跑改到的测试 | 每阶段 README 的「验证命令」只含本阶段相关项 |
| 阶段结束体检 | 每阶段 `steps/` 末尾有 `STEP-*-Z 体检` 步骤 |
| 全量只跑一次 | 只有 `E1-V18收口` 跑 `lint+typecheck+test+build+守卫` |
| 不设门禁 | 不在 CI 加新检查、不改 `ci.yml` 的必需项 |

## 五、三级凭据的格式

本文档树中每个要点都按以下三级引证：

```text
① 代码位置   file:line 或 组件:props
② 实测证据   命令 + 输出
③ 规划落点   哪份文件哪一节 / 哪个阶段哪个步骤
```

示例（取自 `01-契约总表.md`）：

> **`settingGroups` 缺 `display`**
> ① `src/contracts/setting.ts:18-35` —— 17 个分组，无 `display`
> ② `node -e "SELECT key,group,type FROM Setting WHERE key='showImageOverlays'"` → `display | boolean | public=1`
> ③ `A1-契约补齐/README.md` AT-A1-1
