# 12 本次规划的前提与局限、建议的第一刀与启动顺序

## 1. 前提

- 以 upgrade@bb2c0e5 为唯一事实源；P0~P06 的独立校验结论（visual 46/46、e2e 8/8）被引用而非本次复跑。
- 执行者（开发 CLI，默认 3 名，用户批准可为 5 名）能力相当、互不通信、各自能 `npm ci` 并安装 Playwright 依赖；另有至少一个独立验证会话与一个集成者会话。
- 用户对 D6~D11 无异议时按默认值执行；D8、D11 在 W0-08 前确认。
- 人天为单人连续执行的计划值，用于排序与关键路径，不是承诺工期。

## 2. 局限（已知且显式）

- 审计由三个只读子代理完成、主线程抽查复核；行号以 bb2c0e5 为准，Wave 0 的结构切分（W0-02）会让 crud-resources 相关行号失效——任务卡引用的是“文件 + 函数/语义”，执行者应以 w1-base 实际位置为准。
- 未在线核对 Coze 知识库接口（C-04 要求实现前核对）；未运行 visual/e2e；`npm start` 的重建耗时未重测（只测了直接启动 standalone 7.3 s）。
- 并行带来的额外成本：Wave 0 约 5 人天的冻结工作、一个中途合并点 M1、Wave 2 约 4.25 人天的集成。若只有 1~2 名执行者，按 current-plan 原有串行顺序反而更省。
- `sonnect`、`haiku`、`opus`、`fable` 沿用规划总指令中的档位名，未映射到具体模型版本。

## 3. 建议的第一刀与启动顺序

### 3.1 第一刀

**Wave 0 = 第一刀（治理刀 + 步行骨架补强）**。步行骨架（健康检查、鉴权写接口、表、迁移、前台打真实 API、统一错误响应）已在 M1/P03 落地；本轮第一刀的可演示行为是：
“在冻结点 `w1-base` 上，错误码契约可被测试证明（429/409/502/503 各有用例）、知识库两张表与默认库存在且迁移可回滚、五条线的所有权被脚本证明零重叠。”
