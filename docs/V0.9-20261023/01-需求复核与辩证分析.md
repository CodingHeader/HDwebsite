## 2. 5W1H（针对本轮第一刀 V9-CI-01）

- **What**：CI 9 连败；gate 死于构建库未迁移，visual 死于 seed 外键。修复 = workflow 两处 + seed 脚本自足 + 新增 docker job。
- **Why**：V0.8 的 4 张剩余卡全部以"CI 结果"为输入；CI 不绿则 VIS-03 无产物可分诊、V-01 无运行结果可验、REL-02 无法宣布完成。深层原因：两处"本地能跑"的环境假设从未在干净环境验证过——这正是防自证循环要抓的盲区。
- **Where/When**：`.github/workflows/ci.yml`（gate Build 前、visual Prepare DB、新增 docker job）；`prisma/seed-visual.ts`（写入前确保外键锚点存在）。时序：CI-01 推送 → CI 绿 → VIS-03 分诊 → V-01 → REL-02。
- **Who**：本轮执行者=本代理（单主线连续执行）；独立验证=子代理（与执行者身份分离，满足 V8-V-01 的"无验证者与执行者同一身份"——子代理只看 diff+运行结果出具 verify.md）。
- **How**：见 03 大纲与各卡 Execution Steps。
- **What if**：
  - 若 docker job 在 CI 也因网络失败 → REL-01 维持 blocked，升级为「CI runner 环境限制」，写 08 返工清单；不阻塞其余卡（VIS-03/V-01/REL-02 均不依赖 docker job 绿——V-01 对 REL-01 出 UNKNOWN 结论即可）。
  - 若 visual 在 seed 修复后仍因数据量差而 fail → 属预期（VIS-03 正是干这个的），分诊处理。
  - 若 gate 修后 build 仍炸在别的页 → 说明还有未 migrate 依赖的查询点，回到 V9-CI-01 继续修（失败 1 次内不熔断）。

## 3. 苏格拉底式追问（对两个关键判断）

**判断 A："gate 修复应该是加 migrate 步骤，而不是给 settings 查询加 try/catch。"**
- 凭什么？错误是 `no such table`（数据库不存在），不是单点代码缺陷；静态导出每个查库页都是暴露面。
- 反方：try/catch 回退默认值能让 build 更健壮（生产库抖动不至于炸构建）。
- 再反驳：生产构建期 DB 不可用时报错失败**是正确行为**（fail-fast），静默回退会把"库挂了"伪装成"网站没内容"上线；且 try/catch 方案要覆盖 N 个查询点、每个页面的 generateMetadata/generateStaticParams，改动面大还漏兜 `unstable_cache` 内部。CI 加一行 `prisma migrate deploy` 与 visual job 现有做法一致（先准备库再构建），改动面最小、语义最诚实。**判断 A 成立。**

**判断 B："seed-visual 自足化优于在 workflow 里补 `prisma db seed`。"**
- 支持方：`prisma db seed` 一行也能让 User#1 存在。
- 反方（为什么仍不选它）：① seed.ts 会创建 Role×3 + admin + **ManagerMenu + Setting + 可能的业务样例数据**——这些会直接改变前台渲染内容与页面高度，visual 比对基线是按"仅 seed-visual 数据集"生成的（VIS-01 口径），混入 seed.ts 数据会让高度差无解释；② seed.ts 用 ts-node，visual job 需要额外安装路径；③ 隐式跨脚本契约正是本次事故根因，自足化把契约显式化在脚本内部。
- 结论：**判断 B 成立**，seed-visual 在写入前确保 `Role(super-admin)` 与 author 用户存在（幂等：已有任何活跃用户则直接复用其 id，绝不重复创建）。

## 4. 钢人论证（对"V-01 用子代理当独立验证者"）

- 支持方：V8-V-01 卡要求"无验证者与执行者同一身份"；本环境里执行者=主代理，子代理有独立上下文，只被喂 diff+运行结果，满足防自证的实质（不同上下文、只见证据）。
- 反方：子代理也是同一个模型、同一个我派出去，算不算"同一身份"？
- 再反驳：该卡的本意是防"执行者既当运动员又当裁判"的信息自证——子代理不被允许读执行者的结论性文字，只读 git diff 与命令输出，从机制上隔离了结论污染。项目无第二个人类/代理可用，这是当前环境下最强的隔离手段；同时 V-01 的 verify.md 必须附可复现命令，任何第三方可重跑推翻。**成立，但在 verify.md 里注明验证机制与局限。**
