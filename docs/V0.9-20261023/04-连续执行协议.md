# 04 连续执行协议（V0.9，执行者必读）

> 承接 `docs/V0.8-20261022/04-连续执行协议.md` 的主循环、不阻塞规则、状态机、提交纪律、异常处理、收尾条件，仅改以下三点：
> 1. 所有 `docs/V0.8-20261022/` 路径替换为 `docs/V0.9-20261023/`；
> 2. state.json 台账 = 本目录 `state.json`（V0.8 台账只读，作为历史）；
> 3. 本轮验证者角色由子代理担任：verify.md 只准引用 git diff、命令原始输出与 CI 结论，不得引用执行者的总结性文字。

## 主循环（与 V0.8 相同）

```text
LOOP:
  1. git -c http.proxy=socks5://127.0.0.1:10808 fetch origin && git pull --ff-only origin upgrade
  2. 读 docs/V0.9-20261023/state.json 与 08-风险与待裁决.md 的「裁决结果」栏
  3. 选卡：status ∈ {ready}，按 05-任务索引顺序取第一张
     ├─ 有卡 → 4
     └─ 无卡 → blocked 卡若阻塞已解除则改回 ready 回 3；否则 §6 收尾
  4. 认领：status=running、started=<ISO+08:00>，提交 chore(state): claim <ID> 并推送
  5. 按 cards Execution Steps 执行；只改「允许修改」路径
  6. 跑卡片验证命令 + 全量门禁；原始输出入 evidence
  7. 通过 → done + commits SHA + push + 后继卡置 ready；失败 1 次修正重试；失败 2 次熔断 blocked；
     遇阻塞条件 → blocked + 原因，立即回 1 取下一张
  8. 心跳：EXEC-log.md 追加 "<时间> <ID> <状态> <SHA>"
  GOTO LOOP
```

## 本轮特有的不阻塞细则

| 情况 | 动作 |
|---|---|
| CI 排队/运行中（约 15-25 分钟） | **不空等**：转做 V9-V-01 的旧卡 verify（S3-T1 与 CI 无依赖），CI 结论回来后再收口 |
| docker job 失败 | REL-01 维持 blocked（原因改记 CI 证据），**不阻塞** VIS-03/V-01/REL-02 |
| visual job 失败但 gate/docker 绿 | 正常进入 VIS-03 分诊流程（visual 在 continue-on-error=true 期间不阻断） |
| 凭证类（微信/SMTP/Coze） | 沿用 V0.8 裁决：真实联调维持 UNKNOWN，不影响收尾 |

## 推送与凭据纪律（沿 AGENTS.md 安全铁律）

- PAT 仅写入 600 权限临时文件（`~/.git-credentials`、`~/.api-header`），用后即删；remote URL 不含 token；任何输出/文档不得出现 token 值。
- 每次推送前 `git pull --rebase origin upgrade`；被拒只 rebase，禁止 force。
- 提交格式 `<type>(<卡ID>): <摘要>`；state 变更独立提交。
