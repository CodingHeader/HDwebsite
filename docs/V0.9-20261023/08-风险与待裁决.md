# 08 风险与待裁决（V0.9）

## 裁决项

### V9-Q1：visual"合理演进"类残差允许更新基线截图？

- **背景**：参照图入库于 W0-08（main@94dbbbb 口径，用户批准偏差）。VIS-01 之后数据面已换成本轮确定性数据集；分诊时"upgrade 新增能力导致的合理差异"无法靠修代码消除。
- **默认方案（A，本轮采用，`assumed-default`）**：允许更新 `tests/visual/reference/**`，**每张必须有一行理由**（这是 V0.8 VIS-03 卡 Execution Steps 第 3 步的原文授权）；"样式回归"类绝不改基线、必须修代码；"数据差"类优先补数据面（seed-visual 增量）而非改基线。
- **反方案（B）**：一律不改基线，差异全部人工裁决 → 在无人值守执行环境下会把 VIS-03 卡死在分诊步，违反连续执行协议。
- **风险**：A 方案下若分诊者把样式回归误判为合理演进，会掩盖真实回归。缓解：VIS-03 的分诊表必须附前后对比像素数据；V9-V-01 子代理对基线更新逐张复核理由。

### V9-Q2：docker job 若在 CI 仍失败，REL-01 如何处理？

- **默认方案（A，本轮采用）**：REL-01 维持 blocked，blocked_reason 更新为 CI 证据摘要；V9-V-01 对其出 UNKNOWN；其余卡照常收口（VIS-03/V-01/REL-02 均不硬依赖 docker job）。
- 若失败原因是 Dockerfile 缺陷（非环境）→ 记入返工清单，V9-CI-01 熔断规则内修正重试。
