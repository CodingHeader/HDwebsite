## 2. 机械并行判定（规划总指令 §7.1）

可并行 ⟺ 无共享可变状态 ∧ 依赖的契约已冻结且机器可校验 ∧ 文件所有权不相交 ∧ 不共用同一迁移版本号。

| 线对 | 无共享可变状态 | 契约已冻结 | 所有权不相交 | 迁移版本 | 结论 |
| --- | --- | --- | --- | --- | --- |
| 任意两线（A/E/B/C/D） | ✅ 共享模块 json-field/http-client/cache-tags/storage 的**签名**在 W0-03 冻结，实现文件各归一线（storage/cache-tags 归 D，其余归各调用方的替换）；数据库 schema 冻结 | ✅ `src/contracts/**` 在 w1-base 冻结，zod 可执行校验（W0-04/05 测试） | ✅ gen.py 对 1142 个已跟踪文件 + 计划新增文件做 glob 匹配：重叠 0 处，任务允许路径越出本线 0 处（07-所有权矩阵.md） | ✅ Wave 1 新增迁移 = 0 | **可并行** |
| A ↔ E 的 E-05/E-06 | ✅ | ✅ | ✅ | ✅ | 可并行，但 E-05/E-06 **依赖 A 的代码**（DataTable/ResourceForm）→ 通过唯一中途合并点 M1（A-07，tag w1-ui-kit）解除；E-01~E-04 不依赖 M1 |
| A-08 ↔ E-08 | ✅ | ✅ | ✅ | ✅ | 串行（A-08 依赖 E-08 的问题清单） |
| B-06 ↔ D（jobs/index.ts 注册 flushDeferred） | ⚠️ 需要 D 所有文件中的一行注册 | ✅ | ✅（不越界，走请求） | ✅ | B-06 只导出 `flushDeferred()`；notify.scan 的注册在 W2-08（CCR 收尾）完成；**不阻塞 B-06 验收（单测直接调用）** |
| C-08 ↔ D-12（collect-engine） | ✅ C-08 只改 kb-sync（内部读 CollectSource.knowledgeBaseId），不碰 collect-engine | ✅ | ✅ | ✅ | 可并行 |
| B-02 settings PUT ↔ D-06 cache-tags | ✅ B 只调用 W0 冻结的 `invalidateWebContent()`；D 改其实现 | ✅ | ✅ | ✅ | 可并行 |
| C-06 ↔ D-09 kbDir | ✅ C 只调用 `storage.kbDir()`；D 改实现（W0 默认 = `<cwd>/data/kb`） | ✅ | ✅ | ✅ | 可并行；W2-05 回归验证路径 |

守卫与实现不并行（§8.1）：全路由契约测试、ESLint 边界规则、资源/根目录守卫全部放在 Wave 2（W2-02、W2-08、W2-09），Wave 1 内无任何线修改守卫。

写入者数量（§8.1“同时最多 3 个写入 Agent”）与用户“3~5 个并行子任务”的取舍见 01-需求基线复核.md K17：**默认 3 名执行者**（UI = A→E、平台 = B→C、运维 = D，所有权并集仍不相交），用户批准后可扩为 5 名。

禁止并行（写进每份提示词）：同时改 contracts；同时改同一张表；一边改错误码一边让前端猜字段；任何线“独立完成整个数据库”；在别线文件里“顺手修一下”。
