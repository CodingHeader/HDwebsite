## 2. 辩证分析：两个门禁天然要求两个环境

- **矛盾**：visual 的真值在 Windows（参照图在 Windows 生成，F7）；e2e 的真值在 Linux（standalone 是生产形态，F1/F2/F4，global-setup 是按 POSIX 写的，F5）。要求“同一台 Windows 拿到两份官方输出”，本身就自相矛盾。
- **统一**：门禁的本质是“同一个提交在它应当运行的环境里通过”，而不是“同一台机器”。用 **SHA 一致**把两份输出绑定成一个证据，统一就成立了。
- **相对性**：Windows 是开发与参照环境，Linux 是生产与 E2E 环境。门禁环境应跟着被测对象走。

## 3. 五个选项逐一裁决

| 选项 | 裁决 | 理由（证据） |
|---|---|---|
| C 提交 CCR，改 next.config.ts 为无条件 standalone | **否决** | ①解决不了挂起（F8 与 standalone 无关）；②改完 global-setup 仍会死在 F5 的 3 处；③与 start-next.mjs:20 的设计冲突，会让 Windows 的 `npm start` 和 `build` 行为分叉；④改的是生产构建配置，属 D 线（F6），不是 W0 的事 |

| 取消 | — | — |

**最终裁决（D16）**：W0-08 门禁改为**双环境矩阵**——
1. 参照机（Windows）：`lint/typecheck/test/build` + `npm run test:visual` 46/46；
2. Linux（GitHub Actions / Hark 沙箱 / WSL2 任选）：对同一 SHA 跑 `npm ci && npm run build && npm run test:e2e` 8/8；
3. 两份输出都带 `git rev-parse HEAD`，SHA 必须一致；任一 UNKNOWN 不打 tag。

## 4. 参照机 visual 挂起排查（不改任何配置，只取证据）

1. 先另开终端起被测服务：`npm run build && npm start`，确认 `curl http://127.0.0.1:6789/api/health` 返回 200（test:visual 没有 webServer，服务没起会表现为长时间等待）。
2. `npx playwright --version` 与 `node_modules/@playwright/test/package.json` 版本一致；`npx playwright install chromium`。
3. `set DEBUG=pw:api,pw:browser* && npx playwright test tests/visual --workers=1 --reporter=line -g "首页"`，日志存入 `evidence/W0/W0-08/visual-debug.log`。
4. 常见根因：浏览器未安装或版本不匹配、杀毒软件拦截 `chrome-headless-shell.exe`、`.cache/visual` 被占用、端口 6789 上是旧进程。
5. 任何修复如需改 `playwright.config.ts` 或测试代码 → W0-08 无权改，转 E-12 或 CCR。
