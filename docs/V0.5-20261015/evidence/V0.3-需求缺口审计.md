## 3. 代码与文档矛盾

1. **60s 发布间隔**：`src/lib/wechat.ts:183` 注释称"发布间隔 ≥60s 由 publishScan 串行 + sleep 保证"，`src/lib/publish-executor.ts` 中无任何 sleep/间隔逻辑（仅 :64 退避、:194 超时回收）。
2. **ChatScene.baseIds 假生效**：schema 注释"绑定的本地知识库 id 列表"、管理表单可填（`crud-specs.tsx:389`），但检索 `chat-service.ts:62-65` 只用 knowledgeTags，baseIds 完全未读。
3. **kb-adapter 头注释**（`src/lib/kb-adapter.ts:1-5`）称有"CozeClient：Coze 数据集检索"，实际只调 `cozeChat`（智能体对话），无数据集 API；`registerKbRemoteAdapter` 无注册方，远端同步队列恒为 pending。
4. **LLMProvider.dailyQuota / rateLimit**：可在后台配置并保存（providers 路由），网关不读取，配置无效。
5. **NotifyRule.quietHours**：字段存在、契约冻结，`src/lib` 零引用，配置无效。
6. **公众号外链回写**：`publish-executor.ts:156` 写 `result.url`，而 `publishDraftToWechat` 永不返回 url → externalUrl 恒为空，与 REQ-F-001 AC62"全链路可查"不符。
7. **parity-matrix 过期**：头部仍对照 `upgrade@5b72fb7`；A1–A16 标 partial、A19 标 missing，但当前前台页行数与 main 持平、public 150 文件齐全；汇总（present16/partial21/missing11）与 W2-06 卡引用的"present 17/partial 24/missing 3"互相也不一致。
8. **知识库模型口径不一**：REQ-F-007 AC62/67 与 new-features §7.4 要求"三级模型 + Chunk 级检索"，ADR-020/025 改为外部 Coze；W0-06 规划只建 KnowledgeBase/KnowledgeFile 两表并以 Knowledge 行充当 chunk（baseId/fileId/chunkIndex）。需在 W2-06 MUST 结论中明确以 ADR-025 口径验收，否则 AC62/67 将判 FAIL。
9. **llm-gateway 唯一入口**：REQ-F-008 AC62 要求 0 处直连，但 `kb-adapter.ts:8-10` 直接 import `cozeChat`（C-01 只清 llm-gateway/api 中的 coze 分支，未点名 kb-adapter）。
10. **C-07 限频范围**：C-07 验收只覆盖 `/api/chat/stream` 的 429，未覆盖公众号回调；16-新增设计 §8.2 要求每用户限频 + 黑名单 + 敏感词，规划遗漏（G5）。
