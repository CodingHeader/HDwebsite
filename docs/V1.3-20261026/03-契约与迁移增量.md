## 三、两条需要用户/治理层注意的"冻结面碰撞"

1. **`package.json` scripts 是冻结项，但 a11y 门禁需要新 script**
   - `V13-GATE-A11Y-01` 若新增 `"test:a11y": "playwright test -c tests/a11y/playwright.config.ts"`，即**触碰冻结的 `package.json`**。
   - **规避方案（不改冻结面）**：CI 步骤直接写全命令 `npx playwright test -c tests/a11y/playwright.config.ts`，scripts 不变。
   - 若后续确需 script，按 `AGENTS.md` §4 走**契约变更请求（CCR）**，编号接续 `V13-CCR-1`。

2. **`.github/workflows/ci.yml` 不在冻结清单内**
   - 该文件可改（V0.9/V1.1 均改过 visual gate 的 `continue-on-error`），故 a11y 步骤接入合法。
   - 但接入会**增加 CI 时长**（a11y 本地 33s），需在 PR/推送前评估是否与 E2E 并行 job。

## 四、若发生契约变更需求（流程）

1. 停止该子项，写《契约变更请求》到 `docs/V1.3-20261026/ccr/V13-CCR-<n>.md`（含：为什么必须改、影响面、回滚方案）。
2. 由契约员在 `upgrade` 上最小提交，提交信息前缀 `feat(CCR-n)`。
3. 本包所有依赖该契约的卡暂停，标 `blocked`。
4. **本轮预期：不会发生。**
