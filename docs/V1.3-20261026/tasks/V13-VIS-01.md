## 目标
把 CI `visual` job 从 **failure** 归因到"真样式回归"或"基线/数据漂移"，并按归因结果归零，使 `test:visual` 重新成为可信门禁。

- CI run `40303786917`：`gate=PASS`、`docker=PASS`、**`visual=failure`**
- 基线提交 `0728c46`（2026-10-24）之后 **33 个提交**
- `git diff 0728c46..HEAD -- "src/app/(web)" "src/components/web"`：**className/style 变更行数 = 0**
- `src/components/web` 仅 `ChatWidget.tsx` 变更（+29/−8，会话逻辑，无 JSX 结构/类名改动）
- artifact 匿名下载 **401/403**（需 admin 权限）→ 无 diff 图可判
- 本机 Windows 不可判（字体渲染差异，V0.7 实测）；本会话两次 `next start -p 6789` 均未在 80s 内就绪

## 输出
- `docs/design/06_validation/evidence/V13/VIS-01/triage.md`（45 图逐组判定表）
- （视归因）`tests/visual/reference/**`（**只能经 CI `visual_update_ref` 重生成**）
- 或 `src/components/web/**` 的真回归修复（**不得改 className**，只改逻辑/数据）

## Execution Steps
1. [ ] 取得 CI artifact：`visual-results-<run_id>`（需 admin token；若 403 则改走方案 B）
2. [ ] **方案 B（无 artifact 时）**：触发 `workflow_dispatch` 且 `visual_update_ref=true`，让视觉在**与基线同源环境**重生成，下载 `visual-reference-<run_id>`
3. [ ] 逐组二分：对每组图比对"旧基线 vs 新生成"与"页面实际内容"，分三类：
   - **A 真回归**：像素差异区域与 `ChatWidget`/数据无关，且在 1440/768/375 同步出现 → 修代码
   - **B 数据漂移**：差异集中在内容区高度/条目数 → 修 `seed-visual` 数据或 `counts.json`
   - **C 渲染噪声**：ratio ≤ 0.02 且跨路由随机 → 记噪声，重生成基线
4. [ ] 输出 `triage.md`：45 图 × (路由/宽度/ratio/判定/依据)
5. [ ] 按判定执行：A 修代码 → 重跑；B/C → CI 重生成基线并**逐张写理由**
6. [ ] 重跑 `visual` 至 **PASS**，把 CI run 链接入证据
7. [ ] 若最终判定"必须改前台样式" → **停止**，报 REQ-F-014 冲突给用户

## 验收标准
- [ ] `triage.md` 覆盖 45 图（15 路由 × 3 宽度），每组有判定与依据
- [ ] 归因结论为 A/B/C 之一，且**不得**用"看起来像噪声"代替证据
- [ ] 若重生成基线：必须来自 CI（非本机），且逐张理由入档
- [ ] CI `visual` job 最终 **PASS**，run 链接入证据
- [ ] 未手工编辑任何 `reference/*.png`（`git log -p -- tests/visual/reference` 可证）
