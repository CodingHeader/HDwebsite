## 二、逐条缺口

### G1 · 限频双源并存｜实现缺陷｜**高**

- **需求**：`REQ-F-009` §38「风控：每用户限频（默认 10 次/分钟）、黑名单、敏感词过滤」。
- **现状**：
  - `src/app/api/chat/stream/route.ts:22` — `const RATE_LIMIT_PER_MINUTE = 10;`，`:74-78` 按 `ipAddress` 查 `AIChatHistory` 近 60s 计数 → 超限 429。
  - `src/lib/llm/guard.ts:27` — `GUARD_DEFAULT_RATE_LIMIT = 20`，`:149-153` 按 `scene:identifier` 进程内滑窗 → 超限 429。
  - `src/lib/settings-registry.ts:162` — 后台键 `chatGuardRateLimitPerMin` 默认 `"20"`。
- **缺陷**：阈值不一致（10 vs 20）、粒度不一致（IP vs 会话）、**后台设置对 A 通道无效**。
- **影响**：管理员在设置页改限流不生效；NAT 下多用户共享 IP 会被误限；公众号（走 guard 单源）与官网（双源）行为不一致。
- **判定**：`存在缺陷`。**与"默认 10 还是 20"的裁决正交**，可先收口。

### G2 · e2e 构建新鲜度守卫在 win32 失效｜实现缺陷｜**高**（本轮已修）

- **需求**：`AGENTS.md` §6 完成定义——"自动测试或脚本可复现"。
- **原缺陷**：`tests/e2e/global-setup.ts:70` `if (!useStandalone) return null;` 早于 `:73` 新鲜度校验；`useStandalone = process.platform !== "win32"`（`:27`）→ Windows 永不校验。
- **实证**：`BUILD_ID` 17:54:31 < `chat-session.ts` 18:13:36 → e2e 出 1 failed；`npm run build` 后 **79/79**。
- **已处置**：校验前移（现 `:69-83`），报错含两侧时间戳。验证：`tsc`/`lint` 通过、e2e **79/79**。
- **判定**：`已修复`（待 `V13-REL-01` 归档）。

### G3 · `seed-visual --check` 口径会把本地脏库判成失败｜实现缺陷｜低

- **需求**：`AGENTS.md` §7 门禁可复现。
- **现状**：`prisma/seed-visual.ts` 按 `ID_BASE+200+i` 写 9201~9225（25 条）；`--check` 比对 `counts.json` 的 `Article: 25`。
- **缺陷**：本地 `dev.db` 存在人工残留 `9226 ('测试文章','draft')` → 实际 26 → `--check` exit 1（**非种子缺陷**，种子 25 条齐全 0 缺失）。
- **影响**：开发者在本地误判 visual 数据不可用；CI 全新库不受影响。
- **判定**：`存在缺陷`（低危）。

### G4 · a11y 门禁是孤儿测试｜守卫缺位｜**高**
