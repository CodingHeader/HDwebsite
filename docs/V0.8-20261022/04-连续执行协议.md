# 04 连续执行协议（执行者必读，优先级仅次于 AGENTS.md）

> 目标：执行者在没有人在场的情况下，**连续、不中断、不阻塞**地推进到 V8-REL-02。
> 人的裁决只会改变**部分卡**的走向，绝不允许让整条流水线停下来。

## 1. 主循环（每轮严格按此执行）

```text
LOOP:
  1. git fetch origin && git pull --ff-only origin upgrade        # 先拉；失败 → §5.1
  2. 读 docs/V0.8-20261022/state.json 和 08-风险与待裁决.md 的「裁决结果」栏
  3. 选卡：status ∈ {ready}，owner == 我，按 05-任务索引 的顺序取第一张
     ├─ 有卡 → 4
     └─ 无卡 → 若存在 blocked 卡且阻塞原因已解除，就改回 ready 并回到 3；否则 §6 收尾
  4. 认领：state.json 中该卡 status=running、started=<ISO+08:00>，提交 "chore(state): claim <ID>" 并推送
  5. 按卡片 Execution Steps 执行；只改「允许修改」中的路径
  6. 跑卡片验证命令和全量门禁；把原始输出写入证据目录 execution.md
  7. 结果：
     ├─ 通过 → status=done，commits 记下 SHA；push；所有依赖都 done 的后继卡改为 ready
     ├─ 失败 1 次 → 按日志修正，回到 5
     ├─ 失败 2 次 → 熔断：status=blocked，blocked_reason="2xFAIL: <摘要>"，升档位记入 08 返工清单；回到 1
     └─ 遇到卡片「阻塞条件」→ status=blocked，写明原因；**立即**回到 1 取下一张卡
  8. 心跳：在 EXEC-log.md 追加一行 "<时间> <ID> <状态> <SHA>"
  GOTO LOOP
```

## 2. 不阻塞规则

| 情况 | 执行者动作（不得原地等待） |
|---|---|
| 待裁决项（V8-Q1~Q4）尚未裁决 | 读 08 中的**默认方案**，标 `assumed-default`，继续做与该裁决无关的卡；只把依赖它的卡标 blocked |
| 需要凭证（微信/SMTP/Coze） | 做到 dry-run 为止，真实联调标 UNKNOWN，卡片按 dry-run 的验收标准关闭 |
| 跨所有权的修改 | 不改；在证据中写 `ccr-request.md`，指名归属卡，继续做本卡其余部分 |
| 环境缺失（Linux / Docker / 浏览器） | 交给 CI 去跑；本地标 UNKNOWN；卡片以 CI 结果为准 |
| 推送 403 / 网络失败 | 连续重试 3 次，间隔 30s；仍失败就继续本地提交，在 EXEC-log 记 `push-pending`，下一轮先推 |

## 3. state.json 规则

- 只有认领者可以改自己卡的 status。独立验证者只写 `verify` 字段。
- 状态机：`pending → ready → running → done | blocked`。`blocked → ready` 只在阻塞原因解除后发生。
- 每次修改都单独提交（`chore(state): …`），不要和代码提交混在一起，这样冲突时才好 rebase。
- 发生冲突时，以远端为准重放自己那一行，**绝不覆盖他人的行**。

## 4. 提交与推送纪律

- 只用 `upgrade` 分支。**禁止新建分支或 tag**，禁止 force push，禁止把 main 合并进来（main 与 upgrade 没有共同祖先）。
- 提交信息格式：`<type>(<卡ID>): <摘要>`。一张卡可以有多个提交。
- 推送前必须 `git pull --rebase origin upgrade`，然后跑全量门禁。
- 凭据只能用临时 askpass 或 credential helper，用完即删；remote URL 不得含 token。

## 5. 异常处理

1. **拉取失败**：重试 3 次。仍失败就基于本地 HEAD 继续工作，心跳记 `offline`。
2. **门禁在非本卡路径上变红**：先 `git log -1 -- <路径>` 找出引入的卡，在 08 返工清单登记。本卡验收以「本卡改动不新增失败」为准。
3. **npm audit**：一律加 `--registry=https://registry.npmjs.org`。镜像会返回 404，被解析为 0 漏洞，造成假阴性。
4. **测试数量下降**：视为失败，除非证据中逐条说明删掉的是调试探针。

## 6. 收尾条件

所有卡 ∈ {done, blocked}，并且每张 blocked 卡的原因都是**只有人能解除的外部条件**（授权或凭证）。满足后执行 V8-REL-02 的可执行部分，在 EXEC-log 写 `HALT: waiting <Q 编号列表>`，然后才可以停止。
