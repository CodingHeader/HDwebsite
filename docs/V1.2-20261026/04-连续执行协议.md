# 04 连续执行协议（V1.2）

> 沿用 V1.1 主循环/不阻塞/状态机/提交纪律；本轮特化如下。

## 1. 主循环（每卡）

```text
git pull --ff-only origin upgrade
读到 docs/V1.2-20261026/state.json
领一张 ready 卡 → 执行 → 卡内验证 → 门禁（lint/typecheck/相关单测）
→ 留证据（docs/design/06_validation/evidence/V12/<卡号>/execution.md）
→ 小提交推送 → 更新 state.json（done + commits）→ 心跳 EXEC-log
回到开头
```

## 2. 本轮特化

1. **无并行 lane**：V1.2 只有 7 卡且 E2E-01 改动面横跨 `ChatWidget`+`ApplyClient`+`chat-service`+session 路由，为免共享区冲突，主代理做完 E2E-01 后才派发 E2E-02（路径不相交可并行：E2E-02 只改 `tests/e2e/mobile-375.spec.ts` + 其夹具）。
2. **根因已取证，禁止盲改**：E2E-01 第一步写复现（单跑 apply-chat 红），第二步**服务端幂等签发**（有有效 cookie 复用 id），第三步客户端单签发点，第四步回归（apply-chat 绿 + SEC-04 劫持单测绿）。
3. **E2E-03 是全切片闸门**：E2E-01/E2E-02 各自单跑绿后，E2E-03 全量复跑（79 例 0 失败）才有资格推 CI；CI Linux E2E 绿 = 切片完成。
4. **Visual 纪律**：VIS-01 分诊表先出，**任何参照图变更必须走 `workflow_dispatch visual_update_ref`**；本机不动 `tests/visual/reference/**`。
5. **REL-01 收口**：核对 evidence/V11/REL-01 + release zip/sha 已存在 → 更新 V1.1 state REL-01 done → 本包 EXEC 终稿回填 → 双端 0 0。
6. **Q2 不乱替用户裁决**：V12-Q2-01 标记 blocked + 在 08 记录，等用户输入（10 保持 or 改 20）后按 K5 决定执行或关闭；卡挂起不影响其他卡。
7. **提交信息**：`fix(V12)` / `test(V12)` / `docs(V12)` / `chore(state)`；作者不改全局 git config。
8. **熔断**：同卡 2 次 FAIL → 停止改代码 → 改写任务卡/升档/标 blocked（禁换提示词硬撞第 3 次）。
