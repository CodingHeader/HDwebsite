## 4. 五个关键判断的双向论证

### J1 「apply-chat 400 = 多签发源竞态」成立吗？

- 支持：trace 网络实测 4 次并发 GET /api/chat/session、各 Set-Cookie、POST stream 400 且无重试成功记录；`ChatWidget`+`ApplyClient` 独立签发代码路径清晰；SEC-04 恰好改了这一带。
- 反对：400 也可能来自 cookie 过期/人机校验外的路径；浏览器对同键 Set-Cookie 的覆盖语义需与"body 用 localStorage 缓存"对照。
- 收敛：证据足够定位为竞态（同键覆盖 + 前端缓存滞后）；修复方案必须**消除多源独立签发**或**使签发幂等**（服务端已有 cookie 则复用签名、仅刷新 id 保留）——落 E2E-01 执行细节，执行时先写复现测试。

### J2 「mobile-375 = 测试断言竞态，非产品缺陷」成立吗？

- 支持：页面空态渲染正确（快照"还没有招生计划"）；空态容忍 `isVisible()` 是即时快照（不等待），先于空态渲染判 false → 20s 等待必超时；EnrollmentOffering seed 0 行是设计口径（v1.1 既有）。
- 反对：也许应该给 seed 加 EnrollmentOffering 数据让用例有意义？
- 收敛：两者不互斥。正确修法 = 断言改为"等空态或卡片任一出现"（Promise.race 语义），**不新增 seed 数据**（seed 变更 = 影响 visual 基线的数据面，风险高）；产品空态本身正确。若后续要覆盖招生数据渲染，另立数据造数卡（非本轮）。

### J3 「Visual 36/46 应先在 Linux 分诊再动基线」成立吗？

- 支持：Windows 字体/解码与原基线（Linux CI）不可比（V0.7 实证）；断点文档已确认 36 例非单点 flake 而是跨路由漂移；VP 语义：diff ratio 0.02 组与 0.5 组性质不同，需分诊。
- 反对：也许直接 CI 重生成基线更快？
- 收敛：重生成需 `workflow_dispatch visual_update_ref`（手动+人工核对 artifact）——这正是分诊流程的一部分；先本机产出分诊表（哪些疑似真回归、哪些噪声），CI 重生成 + 人工核对，才是最省時路径。

### J4 「REL-01 台账收口 = 文档活」成立吗？

- 支持：state.json REL-01 标 blocked 但双端 0 0、changelog 已有 V1.1（推送实际完成）；只差台账状态与 EXEC 终稿回填。

- 收敛：REL-01 收口 = 核对 evidence/V11/REL-01、更新 state done、EXEC-round1 终稿、无需再推代码。

### J5 「V1.2 不加功能」成立吗？
