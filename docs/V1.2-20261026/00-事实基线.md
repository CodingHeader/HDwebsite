## 3. 本地 e2e 两失败根因取证（2026-10-26 实测）

### U1a · apply-chat（`访客在 /apply 发送消息收到 AI 流式回复`）

- 现象：单跑必现失败；断言 `getByText(MOCK_REPLY)` 30s 超时；error-context 快照为管理页（Playwright 默认 page 快照，非 visitor，误导）。
- trace 网络取证（.cache/e2e trace 解包）：visitor context 中
  - **4 次并发 `GET /api/chat/session`**（07:04:23.270×2 / .327 / .347），全部 200，**各自 Set-Cookie（`chat_sid` 同键，值各异）互相覆盖**；
  - `POST /api/chat/stream` → **400**（会话无效/不匹配），且无第二次重试 POST 成功记录。
- 代码链：`ApplyClient.fetchOrReuseSessionId()`（mount effect + 发送时）+ `ChatWidget.ensureSessionId()`（同 SESSION_KEY，挂载于 `(web)/layout.tsx`）各自独立签发；服务端 `GET /api/chat/session` 每次生成新 sessionId + Set-Cookie 覆盖；`POST stream` 校验 `cookieSession === body.sessionId` → 前端 body 用 localStorage 缓存值，cookie 已被最后一次签发覆盖 → 400。
- 结论：**SEC-04 服务端会话改造引入的多签发源竞态回归**（V11 时因全量跑顺序掩盖，CI Linux 暴露）。

### U1b · mobile-375 招生批次（`375：招生批次移动端卡片可渲染`）

- 现象：单跑/全量均失败；`ul[aria-label]` 20s 超时；页面快照为**空态**"还没有招生计划"。
- 根因：e2e.db seed **无 `EnrollmentOffering` 数据（0 行）** → 页面空态；测试的空态容忍 `getByText(/暂无|没有/).first().isVisible()` 为**即时快照**（空态渲染前判 false），随后 20s 等卡片必超时。断言竞态，非产品缺陷。
- 关联：内容中枢用例在全量顺序中依赖前序用例造数（隔离运行也挂），同属空态容忍竞态家族。
