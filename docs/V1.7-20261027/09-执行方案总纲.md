## 1.3 契约变更裁决

| 缺口 | 裁决 | 理由 |
|---|---|---|
| G1 `display` 分组 | **修** | 1 行枚举，零风险，否则 AT1.4 无法注册键 |
| G2 `type` 补 `image` | **修** | 1 行枚举；`ImageField` 已实现，补契约即可用 |
| **G3 设置页塌缩** | **本轮修（新增 AT）** | 见下 |
| G4 `HomeCard.backgroundImage` | 延后 | 需 CCR，数据全空 |

### 为什么 G3 本轮必须修

**若不修**：本轮新增的 `wechatQrCode` 标 `type:"image"`，但设置页塌缩成文本框 → 运营只能手打 `/uploads/xxx.png` 路径。

**这与原版行为等价吗？**

| | 原版 | 新版（不修 G3） |
|---|---|---|
| DB 存的 type | `image` | `image`（补契约后） |
| 设置页渲染 | 文本输入（原版也不支持 image） | 文本输入 |
| ImageField 可用 | ❌ | ❌ |

→ **等价。** 原版也不支持。

**那为什么还要修？**

因为 `ImageField` 已经写好了（含上传 + 媒体库选择），只是被设置页的 4 分支映射挡住了。修它是**用现成能力换 9 个键的可用性**，成本 1 行代码：

```tsx
// 现状（:141）
type: (item.type === "number" ? "number" : item.type === "boolean" ? "switch" : item.type === "json" ? "textarea" : "text")
// 修后
type: (item.type === "number" ? "number" : item.type === "boolean" ? "switch" : item.type === "json" ? "textarea" : item.type === "image" ? "image" : "text")
```

**但**：这超出「能力对等」范围（原版也没有），属**增强**。

**裁决**：作为 **WP1 的可选 AT（AT2.6）**，标 `SHOULD` 而非 `MUST`。执行者若时间紧可跳过，不影响 WP1 主验收。
