# WP1 · 前台配置化复原

**目标**：恢复 9 个区块组件的 props 与 8 组配置键，使前台配置能力与原版对等。

**为什么必须双向做**：只补键无组件消费 = 死配置；只补 props 无键可传 = 硬编码。二者是同一缺陷的两端。

## ST2 · `userPrompt` 能力承接

### AT2.1 · 决策：放在哪

**两个选项**（需裁决，见 `06 §B1`）：
- **A**：`ChatScene` 加 `userPrompt` 字段（场景级）— 与 `systemPrompt`/`greeting` 同处，语义一致
- **B**：`LLMProvider.metadata` 里存（供应商级）— 无需改 schema

**默认 A**，理由：原版 `userPrompt` 是「按场景的对话模板」，与 `ChatScene` 同位；放 provider 会导致同一模型多个场景无法差异化。

**若选 A 需迁移** → 但迁移额度已用尽（7/7）→ **必须走 CCR**。见 `06 §B1`。

> **这是一个真 BLOCKING**：不动 schema 就只能选 B（能力弱化），动 schema 就要 CCR。
