### 逐项定性

| 路由 | 新版状态 | 定性 | 依据 |
|---|---|---|---|
| `/api/news` | 无 | **已替代** | News 并入 Article（ADR-001）；`/api/articles` 支持 `channel` 过滤（`route.ts:17,31`）；且新版**全仓无一处引用 `/api/news`**（`grep -rn "api/news" src/` 空） |

| 前台 `/news`、`/news/[id]` | 有且是 `permanentRedirect` → `/articles` | ✅ 对等 | 与 ADR-001 一致 |

> **辩证点**：`/api/news` 缺失**不是缺口** —— 因为有 ADR 决策、有 channel 替代能力、且无任何调用方。这类「看似缺失实则已废止」必须排除，否则会凭空造任务。

## 七、代码复用维度：两处退化

### showcase.ts 的过滤能力是否真的丢失

原版导出 14 项，核心是三组守卫：

| 能力 | 原版实现 | 新版 |
|---|---|---|
| `isBlockedShowcaseImage` | 拦截 `/images/gallery/`、`xgnedu` 等路径 | 无 |
| `hasToxicShowcaseText` | 拦截「xgnedu/新概念/四川师范大学」等词 | 无 |
| `hasBrokenShowcaseText` | 拦截乱码文本 | 无 |
| `resolvePartnerLogo` | 3 级兜底（logo → placeholder → 文字首字） | 新版 `partners/page.tsx:49` 仅 2 级（logo → 文字首字），无 placeholder 中间态 |

**但需辩证**：原版这些过滤函数的**实际调用点极少** —— `grep -rn "hasToxicShowcaseText" src/ | grep -v showcase.ts` 仅命中测试文件。说明原版的毒文本过滤**已不是主路径守卫**，而是历史遗留。

**结论**：
- `localImageExists` 重复 → **P1**（真实维护成本）
- showcase 过滤能力 → **P2**（原版也近乎未启用，且新版数据已洁净）

### 影响面判定

`showOverlay` 在原版的作用（以 NewsCenter 为例）：
```jsx
{showOverlay && (
  <div className="flex items-center justify-between mb-6">
    <h2>资讯中心</h2>
    <Link href="/news">查看更多</Link>
  </div>
)}
```
即**控制区块标题栏显隐**。新版恒显 —— 视觉上与「默认开启」等价，但**失去了配置能力**。

**这是关键区分**：
- 若用户从不关闭 → 视觉零差异，仅能力缺失（P1）
- 若用户需要关闭 → 功能缺失（P0）

## 九、文档/代码不一致（本轮最重要的元发现）

| # | 文档说 | 代码实际 | 定性 |
|---|---|---|---|
| D1 | `parity-matrix.md:50` A1「11 个区块组件全部存在」→ **present** | 组件确实存在，但 9 个中 8 个丢了 props，2 个丢了配置键 | **矩阵口径缺陷**：以「文件存在」代「能力对等」 |
| D2 | `parity-matrix.md` missing=0 | 至少 3 项真缺口（ai-config 页/userPrompt/HomeCard.backgroundImage） | **矩阵漏判** |
| D3 | `V1.4/06-验收体系` 写 Setting 键 85 | 实测 85（`grep 'def("'` 计数）✅ | 一致 |
| D4 | 无 ADR 记录组件 props 裁撤 | 实际裁撤 9 个组件的 showOverlay 等 | **变更无记录** |

> **D1/D2 是本轮最有价值的发现**：`parity-matrix` 由重构方自证，其判据是「组件文件是否存在」，而非「能力是否等价」。这个判据在纯新增场景有效，在**重构替换**场景会漏判。
