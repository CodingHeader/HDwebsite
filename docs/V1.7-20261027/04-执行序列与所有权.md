# 04 · 执行序列与所有权

## 一、依赖 DAG

```text
WP1-ST1 (配置键, 4 个 AT)
    │
    ▼
WP1-ST2 (组件 props, 5 个 AT)
    │
    ▼
WP1-ST3 (接线, 3 个 AT)
    │
    ▼
WP1-ST4 (回归, 2 个 AT)

WP2-ST1 (ai-config 页) ────┐
WP3-ST1 (localImageExists) ─┤  （三者与 WP1 无依赖，可并行）
WP2-ST2 (userPrompt) ──────┘  需裁决 B1

WP1 完成后 → WP4 (文档口径修正)
```

## 二、环检测

```text
WP1-ST1 → ST2 → ST3 → ST4 → (终结)
WP2-ST1 → (终结)
WP2-ST2 → 等待 B1 裁决 → (终结 或 blocked)
WP3-ST1 → (终结)
WP4-ST1 → 依赖 WP1-ST4 完成 → (终结)
WP4-ST2 → 依赖 WP1-ST4 完成 → (终结)
```

**无环。** 最长路径 = `WP1-ST1 → ST2 → ST3 → ST4 → WP4`（5 层）。

## 三、可并行组

### 组 A · WP1-ST1 内部（4 个 AT）

| 机械规则 | 满足 | 说明 |
|---|---|---|
| ① 无共享可变状态 | ⚠️ **部分** | 四者同改 `settings-registry.ts`，但**不同行段**（cards 段 / topbar+stats 段 / banner 段 / contact+display 段） |
| ② 契约已冻结 | ✅ | 本轮不改 `src/contracts/**` |
| ③ 文件所有权不相交 | ⚠️ **同文件** | 见下 |
| ④ 不共用迁移版本号 | ✅ | 0 迁移 |

**结论：建议串行**（同一执行者一次改完），而非并行下发。理由是同一文件多次编辑易冲突，串行成本仅多 10 分钟。

> **不掩盖薄弱环节**：这条不满足「所有权不相交」，按规划纪律本应标串行。我如实标出，不勉强凑并行。

### 组 B · WP1-ST1 ‖ WP2-ST1 ‖ WP3-ST1

| ④ 不共用迁移 | ✅ | — |

### 组 C · WP1-ST2 内部（5 个 AT）

| 规则 | 满足 | 说明 |
|---|---|---|
| ① 无共享可变状态 | ✅ | 5 个不同组件文件 |

## 五、档位分配

| WP | 档位 | 理由 | 禁止 |
|---|---|---|---|
| **WP1-ST1** | `sonnect` | 按表注册键，规则明确 | 不得改已有键的默认值 |
| **WP1-ST2** | **`opus`** | 9 个组件 props 恢复，须照原版逐行对齐，改错会破前台视觉（REQ-F-014 冻结面） | 不得改 className 值 |
| **WP1-ST3** | **`opus`** | 接线涉及 4 个入口文件，且要保证默认态不变 | 不得改变默认渲染 |
| WP1-ST4 | `sonnect` | 跑回归 + 看表单 | 不得重建基线图 |
| WP2-ST1 | `haiku` | 新建一个 redirect 页 | — |
| WP2-ST2 | **`opus`** | 需裁决 schema 变更（B1），涉及 CCR | 不得擅自改 schema |
| WP3-ST1 | `sonnect` | 提取函数 + 改 import | 不得改实现逻辑 |
| WP4 | `sonnect` | 改判据描述 + 写 ADR | 不得改其他 present 行 |

**默认档 = opus**。本轮 3 张 opus（ST2/ST3/WP2-ST2），在额度内。

## 七、熔断规则

```text
同一 AT 连续 2 次验收失败 → 停止
  → 重写 AT 定义 / 升档 / 标 blocked
禁止撞第 3 次
```

### 本轮重点防守

| # | 风险 | 防守 |
|---|---|---|
| 1 | **默认态被改变**：补 props 时改了默认值 | 所有新 prop 默认值必须与原版一致；ST4 用视觉回归验证 |
| 2 | **`className` 被改**：照抄原版时带入不同样式 | 只抄 props 与条件包裹，**不抄 className**（前台风格冻结 REQ-F-014） |
| 3 | **配置键成死键**：只补键不接线 | ST1 与 ST3 必须都做，验收含「管理端表单可见 + 前台生效」双向 |
| 4 | **基线图被重建**：视觉回归失败后图省事重建 | `git status tests/visual/reference` 必须为空 |

## 八、执行顺序建议

```text
第 1 步：WP1-ST1（一人串行改完 11 个键，约 1h）
第 2 步：并行 WP1-ST2（5 个 AT，可分发）+ WP2-ST1 + WP3-ST1
第 3 步：WP1-ST3（依赖 ST2）
第 4 步：WP1-ST4（回归）
第 5 步：WP4（文档口径，依赖 WP1 证据）
WP2-ST2：等 B1 裁决后单独排
```
