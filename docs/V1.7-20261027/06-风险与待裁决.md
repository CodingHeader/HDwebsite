# 06 · 风险 / 未决 / 待裁决

## 一、待裁决（BLOCKING）

### B1 · `userPrompt` 能力如何承接（影响 WP2-ST2）

| 项 | 内容 |
|---|---|
| **问题** | 原版 `AIConfig.userPrompt` 在新版无任何承接。要恢复它，放哪里？ |
| **现状证据** | 原版 `api/ai-config/route.ts:34,62` + `manager/ai-config/page.tsx:26` 有；新版 `grep -rn "userPrompt" src/` → **0 命中** |
| **阻塞点** | 迁移额度已用尽（`AGENTS.md §4`：P04/P06/P12 各 1 个，实测 7 个迁移目录） |

**选项 A（默认）**：`ChatScene` 加 `userPrompt` 字段
- 优点：与 `systemPrompt`/`greeting` 同处，语义一致（都是场景级对话模板）
- 缺点：**需改 schema → 需 CCR → 需新增迁移**
- 工时：+2~3h（CCR 流程 + 迁移 + 测试）

**选项 B**：存 `LLMProvider.metadata` JSON
- 优点：零 schema 变更，无需 CCR
- 缺点：**能力弱化** —— 同一供应商被多场景复用时无法差异化（原版是每场景一份模板）
- 工时：+1h

**共同部分**：都需要在管理端 UI 暴露编辑入口，都需要在 chat 调用链消费。

**分叉点**：是否值得为「每场景独立模板」付 CCR 成本。

**建议**：若原版运营实际使用过多场景差异化模板 → 选 A；若只用过默认值 → 选 B 并将 A 记入 backlog。

**不擅自决定**，等裁决。

### B2 · 8 个已删配置键的生产数据如何处置

| 项 | 内容 |
|---|---|
| **问题** | 若生产库 `Setting` 表存有 `showImageOverlays=false` 等键的非默认值，恢复键后这些旧值是否生效？ |
| **现状** | 本机仅 `e2e.db`（测试数据），无法判定生产实际 |
| **影响** | 若存在非默认值 → 恢复后前台外观会**变化**（用户曾关闭的区块标题栏仍然隐藏） → 可能被视为「重构改变了视觉」 |

**选项 A（默认）**：恢复键并**保留旧值**
- 正确性：尊重用户原配置
- 风险：视觉可能变化（但这是用户原本就想要的）

**选项 B**：恢复键但强制重置为默认值
- 正确性：保证视觉与当前一致
- 风险：丢失用户配置

**共同部分**：都要先 `SELECT key, value FROM Setting WHERE key IN (...)` 探查。

**建议 A**，但**执行前必须先查生产数据**。这是 `00 §九 D1` 那条「矩阵口径缺陷」的实际后果。
