# 05 · 验收与阶段体检

## 一、体检策略

```text
单张 AT 只跑它改到的测试。
每个 ST 做完，只给这个 ST 动过的模块体检一次。
全量（lint+typecheck+test+build+视觉）在 WP1-ST4 跑一次。
```

### 分阶段体检表

| 阶段 | 只跑 | 理由 |
|---|---|---|
| WP1-ST1 | `node -e` 读 registry 断言 11 键存在 | 只改一个文件，且是纯数据 |
| WP1-ST2 | `npx tsc --noEmit` + 逐组件 `grep` props | props 类型错误会立刻被 tsc 抓到 |
| WP1-ST3 | `tsc --noEmit` + 管理端表单目视 | 传参类型 + 表单渲染 |
| **WP1-ST4** | **四连串行 + 视觉回归** | 本轮唯一一次全量 |
| WP2-ST1 | 访问路由看跳转 | 单文件 |
| WP3-ST1 | `tsc` + `grep` 去重确认 | 提取函数 |
| WP4 | 文档自检 | 纯文档 |

## 二、核心验收判据（WP1）

### 2.1 「配置键到位」的判据

**必须是双向的**，只满足一端即为死代码：

| 端 | 判据 | 验证 |
|---|---|---|
| 注册端 | 键在 registry 且 group 正确 | `getSettingDefinition(k)` 返回非 undefined |
| 消费端 | 前台能读到并影响渲染 | 管理端改值 → 前台刷新后行为变化 |
| 管理端 | 表单自动出现该键 | `/manager/settings` 对应分组可见 |

**反例（判 FAIL）**：键存在但 `grep` 全仓无消费 → 死配置。

### 2.2 「props 恢复」的判据

| 端 | 判据 |
|---|---|
| 类型端 | 接口含该 prop，`tsc` 通过 |
| 默认值 | 与原版一致（`showOverlay`/`showContent` = true，`showExtraBtn` = false） |
| 行为端 | 关闭时该区域**不再渲染**（不是 `display:none`，是条件渲染） |
| 视觉端 | **不传该 prop 时，渲染与改动前逐像素一致** |

### 2.3 「视觉不变」的硬判据

这是 WP1 最大的风险点（REQ-F-014 前台风格冻结）。

| 检查 | 命令 | 期望 |
|---|---|---|
| `className` 值未变 | `git diff -U0 -- "src/components/web" \| grep -oE 'className="[^"]*"' \| sort \| uniq -c \| awk '$1%2==1'` | 空 |
| 基线图未重建 | `git status --short tests/visual/reference` | 空 |
| 阈值未放宽 | `git diff --exit-code playwright.config.ts` | exit 0 |
| 用例数未减 | `npx playwright test tests/visual --list \| tail -1` | 46 |
| 视觉回归 | `npm run test:visual`（需 Linux） | 46/46 |

> **原卡公式缺陷提醒**：不要用 `grep -c className`——A11Y-01 加 `aria-hidden` 时整行被 `+`/`-` 复制会导致假阳性（V1.4 已实证返回 2）。必须比对**值**。

## 三、门禁（WP1-ST4 跑一次）

```bash
# 必须串行（V1.3 教训：并行 build+test → Hook timed out）
npm run lint && npm run typecheck && npm test && npm run build
npm run check:assets && npm run check:root && npm run check:audit
node scripts/check-frozen.mjs
```

### 条件性门禁

| 门禁 | 何时跑 | 说明 |
|---|---|---|
| `npm run test:visual` | WP1 必跑 | 前台改动，是本轮核心风险 |
| `npm run test:e2e` | 若改了 `src/app/manager/**` 或 API | WP2-ST1 改了 manager 页面 → 需跑 |
| CI a11y / docker | push 后自动 | 不本机跑 |

### win32 限制

`next.config.ts:7` 在 win32 关闭 standalone。

| 命令 | win32 可否 | 绕行 |
|---|---|---|
| `lint`/`typecheck`/`test`/`build` | ✅ | — |
| `check:*` / `check-frozen` | ✅ | — |
| `test:visual` | ❌ | 需 Linux CI；本机记 `UNKNOWN(需 Linux CI)` |
| `test:e2e` | ❌ | 同上 |

**不许假装通过在 win32 跑过的结论。**

## 四、证据要求

每个 AT 完成后写：

```text
docs/design/06_validation/evidence/V17/<AT编号>/execution.md
```

必含：
1. **5W1H**
2. **改动文件清单**（精确到文件）
3. **验收逐条结果**（PASS/FAIL/UNKNOWN + 判据）
4. **命令输出摘要**（关键行，不要贴全量）
5. **默认态证据**：改动前后该区域截图或 DOM 对比（证明视觉不变）
6. **UNKNOWN 及原因**

### 关键：默认态证据的写法

❌ 不合格：
```
视觉未变
```

✅ 合格：
```
默认态对比（home-1440）：
改动前：TopBanner 高度 96px，含标题栏（Flame 图标 + 文案 + 电话）
改动后：同上，高度 96px，DOM 节点数 12 → 12
证据：git stash 前后各截图一次，diff = 0 像素
```

## 五、完成定义

```text
Done =
  所有权内 diff 符合 AT 定义
  ∧ 验收条目逐条有结果
  ∧ 默认态视觉未变（WP1 专用）
  ∧ 配置键双向可达（注册 + 消费 + 管理端可见）
  ∧ 守卫通过
  ∧ 未改冻结面（className 值 / 基线图 / 阈值 / schema）
  ∧ 证据可复现
```

## 六、WP2-ST2 的特殊验收

**若 B1 裁决为 A（改 schema）**：

```text
必须携带 CCR 编号，且：
  □ 新增迁移目录（仅 1 个，接在 20261014073639_p12_knowledge_base 之后）
  □ 迁移可 up/down（或明确标注不可逆 + 理由）
  □ 有对应 prisma generate
  □ 有测试覆盖新字段读写
  □ check-frozen 在 CCR 提交前缀下放行
```

**若 B1 裁决为 B（存 metadata）**：无 schema 变更，但需写清「能力弱化在何处」（同一供应商多场景无法差异化）。
