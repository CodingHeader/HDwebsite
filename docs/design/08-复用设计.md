## 1. 已建立的复用机制（做对了的）

### 1.1 注册中心模式（SSOT）
| 注册中心 | 文件 | 作用 |
| --- | --- | --- |
| settings-registry | `lib/settings-registry.ts` | 全部设置项唯一真相源：分组/类型/校验/默认值/UI 控件 → 动态表单 + 默认值合并 |
| block-registry | `lib/block-registry.ts` | 首页区块唯一真相源：code/type/dataSource/fields/defaultProps → 配置驱动渲染 |
| ManagerMenu 表 | DB | 后台菜单表驱动，脚本可编程增删（add-ai-menus.mjs） |

### 1.2 服务层复用
| 服务 | 复用点 |
| --- | --- |
| `upload-service.uploadFile()` | 所有上传入口统一（校验/命名/落盘/缩略图/入库 六步） |
| `api-response` success/error 系列 | 全部 API 统一响应包 |
| `api-auth.authenticateRequest` | 统一 401 处理 |
| `auth.ts` checkPermission 系列 | 权限判定单一实现 |
| `manager-fetch.ts` | 后台 fetch + 响应解包统一 |
| `settings.ts getSetting` | 前台读配置统一入口（React cache 去重） |
| `prisma.ts` 单例 | 避免连接泄漏 |

### 1.3 组件复用
- SchemaForm：一处实现，设置页/区块页全复用。
- Pagination / ImageUploader / RichTextEditor：跨管理页复用。
- ui/* 基础件：shadcn 体系统一。

## 2. 复用不足点（重构期必须收敛）

| # | 问题 | 证据 | 收敛方案 |
| --- | --- | --- | --- |
| R1 | `roleForCheck` 重复构造 | articles/users 等多个路由手写 `Role` 假对象再调 checkPermission | 统一改用 `requirePermission(request, perm)`（auth.ts 已有），删除路由内样板 |
| R2 | 25 个管理页 CRUD 样板重复 | 每页独立实现 列表/搜索/弹窗/表单/删除确认 | 抽 `CrudPage` 通用组件（schema 驱动：列定义 + 表单字段 + API 前缀），业务页只写差异 |
| R3 | zod schema 与 Prisma 模型双份维护 | 每路由内联 schema | 集中到 `lib/schemas/*.ts`，与类型同源 |
| R4 | 两版 CourseSection 并存 | CourseSection / CourseSectionNew | 择一保留，另一删除 |
| R5 | News/Article 双内容体系 | schema | 见 01-需求 C1 |
| R6 | 上传文件读取 `/api/file/[...path]` 无公共校验层 | 直读路径 | 加路径白名单 + 域校验工具 |
| R7 | 操作日志写入代码散落各路由 | 每路由手写 operationLog.create | 抽 `logOperation(request, user, module, action, title, content)` 工具 |

## 3. 重构期新增复用设计（N1–N11 落地约束）

| 复用资产 | 说明 |
| --- | --- |
| 统一队列/调度器 | 采集、自动发布、邮件重试共用同一调度基座（任务表 + worker） |
| 统一外部凭据管理 | 公众号 appid/secret、SMTP、LLM apiKey 全部走 Setting(isEncrypted) + 加解密工具，禁止散落硬编码 |
| 统一 Markdown 管线 | 文章/服务指南/知识库/公众号草稿共用同一 markdown 解析器 |
| 统一 AI 调用网关 | 官网客服、公众号客服、内容摘要/审核共用 `llm-gateway`（模型路由/降级/计费统计单点） |
| 统一通知网关 | 邮箱提醒单点实现，事件驱动（发布前/余额不足/报错） |
| 表单/表格 Schema 复用 | 新管理页（采集/发布/知识库/模型/提醒）一律基于 CrudPage + SchemaForm，不再手写整页 |
