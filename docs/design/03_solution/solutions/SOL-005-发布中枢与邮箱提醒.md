# SOL-005：发布中枢与邮箱提醒

## 1. 目标

统一发布队列驱动官网/公众号定时发布闭环；通知网关承接发布前提醒、余额、报错三类五事件邮件（异步、留痕、可重试）。

## 2. 覆盖需求

| 需求 | 覆盖点 |
| --- | --- |
| REQ-F-003 | PublishJob 状态机/定时执行/失败重试/采集转发布 |
| REQ-F-011 | Notify 三模型/SMTP 配置/五类事件/异步队列 |

## 3. 设计要点

### 3.1 发布队列

- **PublishJob**：contentType(article/info/service_guide/wechat)/targetId/action(publish/update/offline)/scheduledAt/status/attemptCount/errMsg/result
- 状态机：`draft → pending_review → approved → scheduled → publishing → published | failed | cancelled`（无 waiting_confirm，ADR-008；审核单级——SuperAdmin 一审终审，Q10 轮/ADR-017 补充）
- `publish.scan`（每分钟）：到点任务 → 渠道执行器：
  - website：写入 Article(contentType=markdown) / ServiceGuide；完成后生成 sitemap 刷新
  - wechat：委托 SOL-006 §3.2 微信发布执行器
- 失败重试：指数退避 ≤3 次 → failed + system_error(job_failed) 告警

### 3.2 发布前提醒（仅通知）

- `notify.scan`：距 scheduledAt ≤ 提前量（默认 30min，Setting 可配）→ 发 before_publish_* 邮件并标记已提醒
- 立即发布（scheduledAt=now）：即时"即将发布"通知
- 提前量必须 > 0 且 < 排期提前期，非法配置静默回退默认值

### 3.3 通知网关

- **NotifyRecipient**：name/email/groups[]/enabled；**NotifyRule**：event/enabled/groups/静默时段/templateId?；**NotifyTemplate**（Q10 轮定：可配置模板）：name/event 适用范围/subject/body（变量 {title,time,detail,link}）/isDefault；**NotifyRecord**：event/to/status(sent/failed/skipped)/retries/errMsg
- SMTP 走 Setting email 分组（ADR-004 后补 + 连接测试）；未配置 → skipped(smtp_not_configured)
- 事件：before_publish_news/info/wechat、llm_balance_low（SOL-003 填报检查触发）、system_error（job_failed/collect_failed 聚合，同类 10min 1 封）
- 发送异步（队列表驱动，不阻塞请求/任务主流程）；失败重试 3 次指数退避

### 3.4 管理界面

- 发布队列管理页（待发/已发/失败 Tab + 重试/取消）
- 提醒人管理 + 提醒规则 + 邮件模板 + 发送记录（4 页或 1 页多 Tab，实施微决策；模板可配置，Q10 轮定）

### 3.5 API 与页面

| API | 说明 |
| --- | --- |
| GET/POST /api/publish/jobs | 队列列表 / 新建排期 |
| PATCH/DELETE /api/publish/jobs/[id] | 编辑 / 取消 |
| POST /api/publish/jobs/[id]/retry | 失败重试 |
| GET/POST /api/notify/recipients | 提醒人 CRUD |
| GET/POST /api/notify/rules | 提醒规则 CRUD |
| GET/POST /api/notify/templates | 邮件模板 CRUD（Q10 轮增） |
| GET /api/notify/records | 发送记录（留痕查询） |
| POST /api/settings/email/test | SMTP 连接测试 |

页面：`manager/publish-jobs`（待发/已发/失败 Tab + 重试/取消）、`manager/notify`（提醒人/规则/记录三 Tab）。

### 3.6 技术选型（新增依赖声明，REQ-C-001）

| 依赖 | 用途 | 理由 |
| --- | --- | --- |
| nodemailer | SMTP 发送 | Node 事实标准、支持自定义 host/port/secure |

### 3.7 风险与缓解

- 邮件服务商限频/拒信 → 队列间隔发送（≥2s/封）+ 重试退避 + NotifyRecord 全留痕
- 提前量配置非法（≤0 或 ≥排期提前期）→ 保存时校验，非法回退默认 30 分钟

## 5. 关键取舍

- 邮件即唯一通知渠道（网关抽象预留短信/微信模板消息位）
- Setting 类站点信息"变更单定时生效"不做（16-新增 §3.3 二选项）

## 6. 验证方式（VAL 摘要）

- 定时任务到点自动发布成功（后台可见状态流转 published）
- 提前 30 分钟提醒邮件发出（凭证后）；立即发布即时通知
- 失败任务重试 3 次后 failed 且告警邮件到达
