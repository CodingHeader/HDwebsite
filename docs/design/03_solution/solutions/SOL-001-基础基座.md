# SOL-001：基础基座

## 1. 目标

为 S2~S6 提供公共底座：进程内调度循环、Markdown 渲染管线、统一净化入口、模型合并迁移，并清偿安全/SEO 基线欠账。

## 2. 覆盖需求

| 需求 | 覆盖点 |
| --- | --- |
| REQ-F-004 | contentType + MarkdownRenderer + 双模编辑器 + 自动 excerpt/首图 |
| REQ-NF-002 | sanitize 统一入口（services/[slug] 缺口闭合） |
| REQ-NF-003 | lang=zh-CN、sitemap/robots |
| ADR-001 | News→Article 迁移 |

## 3. 设计要点

### 3.1 调度基座（进程内）

- 启动即运行每分钟循环（setInterval + 单飞锁）；扫描 `CronJob` 表（name/cron 表达式/enabled/lastRunAt/lockedAt）
- 执行器接口 `Scheduler.execute(jobName)`；任务注册表（registry SSOT 模式，TN-007）：
  `collect.run` / `publish.scan` / `notify.scan` / `retry.failed` / `llm.balance-check`
- 锁与幂等：lockedAt 心跳（超 10min 视为僵死自动释放）；任务幂等设计（重跑不重复副作用）
- PM2 重启自动恢复（REQ-NF-004）；错峰：可配置每日窗口（REQ-C-003）

### 3.2 Markdown 管线

- `Article.contentType`（html 存量默认 / markdown 新增）；`ServiceGuide` 同管线
- `MarkdownRenderer`（服务端组件）：GFM 表格/任务列表/代码高亮/图片懒加载/锚点目录；输出经统一 sanitize
- 入库钩子：excerpt=纯文本前 200 字（可覆盖）、coverImage=首图（可覆盖）
- 编辑器双模：markdown（新）与 TipTap（存量 html）按 contentType 切换

### 3.3 净化与安全基线

- sanitize 白名单单点（复用 articles 现有净化扩展到 services/markdown 输出）
- 图片域名白名单：本站 uploads + 采集源域 + 微信域
- lang=zh-CN；`app/sitemap.ts` + `app/robots.ts`（Next 16 MetadataRoute）

### 3.4 News→Article 迁移（ADR-001）

- 迁移脚本：News → Article(channel=news)，保留 id/时间/浏览量；News 表下线
- 引用改造：sitemap 双源合一、前台新闻列表组件/路由、后台 News 管理页移除
- 验收：迁移前后计数核对（total/news channel/info）

### 3.5 API 与页面

- API：无新增对外接口；`/api/articles`、`/api/service-guides` 现有接口扩展 contentType/channel/excerpt/coverImage 字段（zod 同步）
- 页面/组件：现有 article、service-guide 编辑页改造为双模编辑器（markdown/TipTap 按 contentType 切换）；新增 `src/components/web/MarkdownRenderer.tsx`；新增 `app/sitemap.ts` + `app/robots.ts`；`instrumentation.ts` 承载调度循环启动钩子（见 TN-009）

### 3.6 技术选型（新增依赖声明，REQ-C-001）

| 依赖 | 用途 | 理由 |
| --- | --- | --- |
| react-markdown + remark-gfm | markdown → React 渲染 | RSC 生态原生、支持组件映射 |
| rehype-highlight | 代码高亮 | 与 react-markdown 管线兼容 |
| cron-parser | cron 表达式解析 | 纯解析无副作用，适配 DB 驱动调度 |

净化复用现有 `sanitizeHtmlServer`（扩展白名单），不引新净化库。

### 3.7 风险与缓解

- 调度循环与请求并发写冲突 → 事务短小 + busy_timeout 让步重试（RISK-007）
- 超长 markdown 文档渲染耗时 → 详情页缓存/ISR + 渲染耗时监控（REQ-NF-001）

## 4. 数据模型变更

| 模型 | 变更 | 字段要点 |
| --- | --- | --- |
| Article | +contentType（String，存量默认 html）、+channel（String，迁移写入 news/info） | 存量零迁移默认 html |
| ServiceGuide | +contentType | 同上 |
| CronJob（新增） | name（唯一）/cron/enabled/lastRunAt/lockedAt | 调度基座表驱动 |

## 5. 关键取舍

- 调度不引 BullMQ/Redis（REQ-C-003 单机约束），表轮询量级每分钟 1 次可忽略
- Markdown 渲染库选型（如 react-markdown+remark-gfm 或 marked）在实施 ADR 微决策，锁定"服务端渲染 + sanitize 输出"两点

## 6. 验证方式（VAL 摘要）

- build/编译通过；markdown 渲染快照用例；XSS 注入用例（script/事件属性）
- 迁移脚本 dry-run 计数核对 + 回滚脚本
