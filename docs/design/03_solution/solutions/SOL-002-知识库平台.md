# SOL-002：知识库平台

## 1. 目标

将单表 Knowledge 升级为"库 → 文件 → 切片"三级模型，承接人工维护与采集自动入库双流量，为 AI 检索提供质量与规模支撑。

## 2. 覆盖需求

| 需求 | 覆盖点 |
| --- | --- |
| REQ-F-007 | 三级模型 + 三类管理页 + 迁移 |
| REQ-F-006 | 采集入库位（pending/审核/回链） |

## 3. 设计要点

### 3.1 三级模型（12-知识库 §3 权威）

- **KnowledgeBase**：code/name/description/isDefault/vectorProvider（预留）
- **KnowledgeFile**：baseId → title/format(md/txt/docx)/content/source(manual/collect)/collectItemId（回链）/status(pending/active/rejected)/tags
- **KnowledgeChunk**：fileId → seq/content(≤800 字)/tags/priority/keywords/embedding（预留）

### 3.2 三类管理界面

- **库管理**：CRUD/默认库/统计（文件数、chunk 数、最近更新）
- **文件管理**：树/列表、markdown 在线编辑（MarkdownRenderer 预览）、导入 md/txt/docx、导出、批量启停、采集审核队列（REQ-F-006 流转）
- **其他管理**：标签管理、切片重建任务（挂调度基座）、检索测试工具（问题 → 命中 chunk 预览）、回收站

### 3.3 检索与注入

- ChatScene 绑定 baseId 列表（+ tags 库内过滤）
- Chunk 级检索：tags contains + priority 排序，take 6；注入格式 `[库名] 标题\n内容`
- 大文件(>1MB)与切片策略遵循 14-存储 S4（chunk ≤800 字）

### 3.4 存量迁移（K5）

- Knowledge 单表数据 → 默认库文件（source=manual），原 tag 降为文件标签
- 计数核对验收（文件数一致）

### 3.5 API 与页面

| API | 说明 |
| --- | --- |
| GET/POST /api/knowledge/bases | 库列表 / 新建（code 唯一） |
| PATCH/DELETE /api/knowledge/bases/[id] | 库编辑 / 删除（库内有文件时禁删） |
| GET/POST /api/knowledge/files | 文件列表（?baseId=&status=）/ 新建 |
| POST /api/knowledge/files/import | 导入（multipart：md/txt/docx） |
| PATCH/DELETE /api/knowledge/files/[id] | 编辑 / 启停 / 审核状态流转 |
| POST /api/knowledge/files/[id]/rebuild | 重建该文件切片 |
| GET /api/knowledge/files/[id]/export | 导出 markdown |
| GET /api/knowledge/search | 检索测试（?baseIds=&q=，返回命中 chunk） |

页面：`manager/knowledge-bases`、`manager/knowledge-files`（树 + 列表 + 在线编辑）、`manager/knowledge-tools`（标签 / 切片重建 / 检索测试 / 回收站）。

### 3.6 技术选型（新增依赖声明，REQ-C-001）

| 依赖 | 用途 | 理由 |
| --- | --- | --- |
| mammoth | docx → html | 主流稳定；复杂版式降级为纯文本提取 |

切片策略自实现（标题分节 + 800 字滑窗），不引分块库。

### 3.7 风险与缓解

- 采集流量下文件量持续膨胀 → 列表分页 + 检索走 Chunk 索引字段（tags/keywords），文件正文不参与检索
- 存量迁移丢数据（K5）→ dry-run 计数核对 + 迁移脚本保留原表只读一个版本

## 4. 数据模型变更

| 模型 | 变更 | 字段要点 |
| --- | --- | --- |
| KnowledgeBase（新增） | — | code（唯一）/name/description/isDefault/vectorProvider（预留） |
| KnowledgeFile（新增） | — | baseId→/title/format/content/source/collectItemId?/tags[]/status(pending/active/rejected)/priority |
| KnowledgeChunk（新增） | — | fileId→/seq/content（≤800 字）/tags[]/priority/keywords/embedding（预留） |
| Knowledge | 迁移后下线 | 数据无损迁入默认库（计数核对） |

## 5. 关键取舍

- 不引入向量检索（ICE-VEC 预留 embedding 字段；keyword+tag 检索先行，规模小时够用）
- docx 解析取正文为主（复杂版式不保证）

## 6. 验证方式（VAL 摘要）

- 迁移计数核对；检索测试工具命中预期文件；导入 3 格式样本各 1 份成功
- ChatScene 检索切换后 AI 回答对比回归（faq 场景问答 3 例）
