# ADR-002：公众号官方 API 设计、凭证后补

## 状态

accepted（2026-10-10 会话决策 C2，用户确认）

## 背景

公众号能力（自动发文、AI 客服）依赖认证服务号 appid/secret 与 IP 白名单，凭证当下不可用；若等凭证则 S6 无从开工，若留 mock 则交付风险后置。

## 决策

按官方 API 规范完成设计与开发（接口封装、验签、数据模型、管理页全部就绪）；凭证在 S6 交付前由运营补录（后台 WechatAccount 配置 + IP 白名单），届时插桩联调。

## 依据

- 用户问答确认（C2 ✅）
- 微信平台约束 REQ-C-002（规范公开、可先开发）

## 备选方案

| 方案 | 评估 | 结论 |
| --- | --- | --- |
| 等凭证到位再开发 | 阻塞 S6/M4 排期，交付不可预期 | 弃 |
| 自定义 mock 协议先行 | 与官方契约偏离，联调返工风险大 | 弃 |
| 按官方 API 开发 + 凭证后补联调 | 开发不阻塞，契约保真 | **选定** |

## 影响

- 开发不被 DEP-001 阻塞；联调/验收依赖凭证就绪（REQ-F-005/009 的真实发布验收项标记"凭证就绪后"）
- 设计严格按官方文档（draft/freepublish/客服消息），避免自造接口返工
