# ADR-024：用户对等要求与 ADR-012 复核

## Context（背景）

- ADR-012（2026-10-10 accepted）在新仓裁剪了 PageTemplate / ContentBlock / TemplateBlock / ElementConfig 四个模型与首页区块注册表（block-registry），理由是"建而未用"。
- 本轮用户硬约束："main 上的每个功能都必须在 upgrade 存在"（REQ-F-013）。P0 把两者的冲突登记为 K1 → 待裁决 U-B2（current-plan §3.3/§3.4），提出方案 A（恢复）/ 方案 B（维持裁剪、记为用户确认放弃）。
- main 事实（`origin/main@94dbbbb`）：
  - `prisma/schema.prisma` 含 `PageTemplate`(:334)、`ContentBlock`(:369)、`TemplateBlock`(:407)、`ElementConfig`(:565)，以及 `Navigation.templateId → PageTemplate`(:101-102)、`Navigation.elements ElementConfig[]`(:129)。
  - `src/lib/block-registry.ts`（192 行）定义首页 8 个区块（home-banner/home-topbar/home-stats/home-intro/home-courses/home-news/home-cta/home-partners）的类型、数据源、可配置字段与默认值，`getBlockRegistry/getBlockDefinition/getBlockDefaultProps`；main src 内无其他文件引用它。
  - `prisma/seed.ts:451-485` 种入 4 个 PageTemplate（list/article/partner-grid/course-list）与 4 个 ContentBlock（home-banner/news-list/sidebar-hot/course-recommend）；main 自带 `prisma/dev.db` 中 ContentBlock=4、PageTemplate=4、TemplateBlock=0、ElementConfig=0（本次 sqlite 查询）。
  - main 无对应管理页与 API。

## Decision（决策）

**2026-10-12 用户裁决：选方案 A——恢复首页区块配置与 ElementConfig，取代 ADR-012。**（来源：用户本轮答复"main 每个功能都要在 upgrade 存在"再次确认，并明确"homepage block config + ElementConfig restored"。）

落地口径（执行规格；表结构细节由 P04 按下列原则确定）：

1. **数据模型**：按 main 字段原样恢复 `PageTemplate`、`ContentBlock`、`TemplateBlock`、`ElementConfig` 四个模型，并恢复 `Navigation.templateId`（可空）与 `ElementConfig.navigationId`（可空）关联。只做加法（新表 + 可空列），不改动现有表的既有列。迁移随 P04 的唯一迁移 `p04_data_integrity` 一并提交（current-plan §5）。
2. **种子数据**：P04 seed 幂等写入 main 的 4 个 PageTemplate 与 4 个 ContentBlock（数据对等），并为首页实际区块写入"首页"模板及其 TemplateBlock 排序，**默认顺序与开关复现 main 首页原样**。
3. **注册表与接口**：P06 恢复 `src/lib/block-registry.ts`（以 main 文件为起点，区块定义与 upgrade 首页实际区块对齐），新增契约 `src/contracts/blocks.ts` 与 CRUD 接口（content-blocks / page-templates / template-blocks / element-configs，走通用 CRUD 工厂与权限点）。
4. **前台**：P06 让首页按区块配置决定区块的开关与顺序；**不改变任何区块组件的 JSX/className**；默认配置下 `npm run test:visual` 必须通过（REQ-F-014）。P02 先为首页每个区块提供稳定锚点（`data-block="<code>"`，不影响样式）。
5. **管理端**：P07 新增"首页区块配置"（拖拽排序/开关/字段编辑，字段表单由注册表 `fields` 生成）、"页面模板"、"交互点配置（ElementConfig）"三个管理页及菜单，遵守 REQ-F-015。
6. `PageTemplate.templateFile` 字段保留以保持数据对等；main 中它指向不存在的文件，upgrade **不**按该字段动态加载模板文件（记为已知限制，前台渲染仍由组件完成）。

## Alternatives（备选方案）

| 方案 | 内容 | 结论 |
| --- | --- | --- |
| A（采纳） | 恢复四模型 + 注册表，并接线为可用功能 | 满足 REQ-F-013；成本：1 个迁移的加法改动、3 个管理页、首页组合层 |
| A'（P0 曾建议的变体） | 用 Setting 分组 + 注册表实现区块开关/排序，不复活 4 张表 | 未采纳：用户要求恢复 ElementConfig 等 main 功能，数据层不对等 |
| B | 维持 ADR-012 裁剪，parity 记"用户确认放弃" | 被用户否决 |

## Consequences（后果）

- 正面：parity C9/C10 由 dropped-by-ADR 转为 missing（有归属方向）→ 最终 present；首页区块变为可配置。
- 代价：P04 迁移不再是"仅索引"，验证命令相应放宽为"仅加法"（见 P04 提示词）；P06 获得对 `src/app/(web)/page.tsx` 的一次性组合层修改权（只改区块的取舍与顺序）。
- 风险：区块配置被误改导致首页与 main 不一致 → 默认配置受 visual 门禁保护，管理页提供"恢复默认"（P07）。ElementConfig 在 main 中无数据、无使用方，upgrade 先提供 CRUD 与按 navigationId 关联的数据管理，不强行驱动前台交互（以免改变外观）——如需驱动前台，另立 ADR。
