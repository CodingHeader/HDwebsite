# ADR-036 · B-07 公众号发布闭环（2026-10-20）

> 状态：已采纳。执行卡：B-07（分支 `upgrade`，依赖 B-05）。范围：正文外链图转存、发布结果回写、60s 节流、多渠道一次发布（G1）、渠道状态 DTO 组装。

## 1. 背景

- 实测前提（卡输入）：`src/lib` 无 `uploadimg`；`ContentChannel.externalUrl` 永远为空；`wechat.ts:183` 注释称"发布间隔 ≥60s 由 publishScan 串行 + sleep 保证"但无持久化实现。
- V0.6 已冻结 `content-hub.ts` 契约（`channelStateSchema`、`CHANNEL_STATUSES`、`CONTENT_HUB_CHANNELS`）与 `publishJobCreateSchema.channels`（1~2、去重、与 `channel` 二选一）。

## 2. 决策

### 2.1 uploadimg 正文外链图转存

- `wechat.ts` 新增 `uploadContentImage(token, url)`：下载 → 判 ≥1MB 跳过（warning，不阻塞）→ magic bytes 判 png/jpg → `media/uploadimg`。
- `rewriteWechatImages(content, token)`：扫描 `<img src>`，仅非 `mmbiz.qpic.cn`/`mmbiz.qlogo.cn` 的绝对外链图转存；同 URL 只转存一次；相对路径与非外链保留原样；失败降级保留原外链。
- 在 `addDraft` 内调用（markdown 先 `mdToWechatHtml`）。

### 2.2 freepublish/get 轮询

- 新增 `getPublishResult(token, publishId, maxAttempts=5)`：指数退避 `2^i * 1000ms`；`publish_status 0/5` 成功取 `publish_task_info.article_detail[].url`；`2/3/4` 返回 failed；其余（1=发布中）继续；耗尽返回 timeout。
- `publishDraftToWechat` 提交成功后轮询，把 `url` 放进返回值，由 `channels/wechat.ts` 写 `ContentChannel.externalUrl`。

### 2.3 60s 节流（跨进程有效）

- 判据持久化于 `ContentChannel(wechat).publishedAt`（最近一条已发布）；间隔不足 60s 直接返回 `ok:false` 带"节流"文案。
- 理由：DB 字段跨进程有效，比内存 `sleep` 更可靠（原 `wechat.ts:183` 注释依赖 `publishScan` 串行，单进程才成立）。

### 2.4 G1 多渠道一次发布

- `POST /api/publish-jobs` 改为显式 withApi（permission `publish:create`）：
  - `channels` 优先，缺失回退 `[channel]`；去重；重复 → 400。
  - 每渠道校验：wechat 需 `status=active && freepublishEnabled` 的服务号，缺失整体 400（不落半套任务）。
  - 内容状态门禁：`approved/published` 之外 400（与 `executePublishJob` 一致，ADR-017）。
  - `prisma.$transaction` 批量创建多条 `PublishJob`，任一条失败整体回滚。
  - `scheduledAt` 缺失默认立即（`new Date()`）。
  - 响应 `{ list: jobs }`，HTTP 201。
- 契约保留 `channel` 单值字段（e2e `collect-publish` 兼容，ADR-034 D3）。

### 2.5 渠道状态 DTO 组装（ADR-034 §3 派生）

- 新文件 `src/lib/channels/content-hub-state.ts`（允许路径）：`buildItemChannels(rows)` → `Map<itemId, ChannelState[]>`。
- 派生规则：`status/accountId/externalUrl/errMsg` ← `ContentChannel` 最新行（id 最大）；`scheduledAt` ← 该渠道最近一条 `PublishJob.scheduledAt`（空回退 `createdAt`）；`publishedAt` ← `ContentChannel.publishedAt`（ADR-034 §3 表笔误写成 `PublishJob.publishedAt`，真实列在 `ContentChannel`；无值时回退 `PublishJob.finishedAt`）。
- 路由接入：`GET /api/content-items` 用 `mapList` 透传后合并；`GET /api/content-items/[id]` 用 withApi 显式实现等价 `crudGet` + channels。

## 3. 偏差登记

| # | 偏差 | 说明 |
|---|---|---|
| D1 | `publishJobCreateSchema` 的 refine 是 OR 逻辑，非 ADR-034 §2.2 写的"二者恰一" | 冻结契约不可改；服务端 `channels` 优先。测试改为断言"同传时 channels 优先" |
| D2 | 节流判据用 `ContentChannel.publishedAt`（发布完成时刻），非提交时刻 | 语义更贴近"上一条真正发出时间"；首次发布无行则不节流 |
| D3 | 未实现图片压缩（卡步骤 2"超限先压缩或跳过"取"跳过"分支） | 无图片处理依赖（sharp 属冻结依赖且 high 待裁决 K10）；跳过+warning 符合 ADR-030 降级原则 |
| D4 | `ContentChannel.publishedAt` 与 `PublishJob.finishedAt` 并存 | `publishedAt` 优先；`finishedAt` 仅兜底 |

## 4. 影响与验证

- 不新增迁移、不改冻结契约、不改 `package.json`。
- 门禁：`tsc`、`vitest` 两条 lane-b 测试（24 例）、相关回归（channels-registry/publish-state-machine/notify）、`npm test` 全量、`lint`、`build`。
- 真实公众号凭证缺失：联调记 UNKNOWN（不得写 PASS）。
