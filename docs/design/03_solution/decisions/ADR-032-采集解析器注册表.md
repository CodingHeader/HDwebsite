# ADR-032：采集解析器注册表（CollectParser Registry）

- 状态：已接受（D-12 实施）
- 日期：2026-10-20
- 背景：采集引擎 `src/lib/collect-engine.ts` 在 `runSource` 内直接 `if (source.type === "rss") { ... } else { ... }` 分支，解析逻辑与引擎耦合；试抓预览 `src/lib/collect-test.ts` 存在同样的硬判断。新增采集源类型时需同时改引擎、试抓预览、测试与 UI 白名单，易漏改、难扩展（REQ-NF-001 M-7）。
- 决策：引入单一解析器注册表 `src/lib/collect/parsers.ts`：
  - `ParserType` = `"html" | "rss"`，`getParser(type)` 返回 `ParserFn`，未知类型抛错。
  - 解析器只负责「文本/URL → `ParsedItem[]`」，不涉及入库、图片转存、去重、相似度。
  - `parseHtmlList` / `parseRss` 为内置实现；`fetchHtmlDetails` / `extractHtmlContent` 提供 HTML 详情页正文抽取复用。
  - 引擎与试抓预览均改走 `getParser(type)`，业务代码不再出现 `type === "rss"`。
- 影响：
  - 新增类型 = 在注册表加一行 + 新增解析器函数 + 更新 `collectSourceCreateSchema` 的 `COLLECT_TYPES`（契约）与 UI 白名单；三处改动收敛于注册表一处。
  - 图片 mime 白名单单一来源 `src/lib/storage.ts` 的 `COLLECT_IMAGE_TYPES` / `COLLECT_IMAGE_MAX_SIZE`，`collect-engine.ts` 与 `api/upload/route.ts` 不再各自维护 `image/jpeg` 映射。
  - `collect-test.ts` 移除 `rss-parser` / `cheerio` 依赖，改为注入 `fetchText` 给注册表解析器，行为与采集引擎口径一致。
- 关联：ADR-015（采集器 HTML 优先）、ADR-003（试抓预览）、D-09（storage 单一来源）、V0.6 `M-7` 登记项。
