# ADR-030：发布渠道注册表（PublishChannel Registry）

- 状态：已接受（2026-10-20）
- 所属卡：B-05（PublishChannel 注册表 + 发布后写失效）
- 影响范围：`src/lib/channels/**`、`src/lib/publish-executor.ts`、`src/lib/content-workflow.ts`

## 背景

原 `publish-executor.ts` 内以 `if (job.channel === "website") {...} else {...}` 硬编码分派渠道实现，`content-workflow.ts` 用 `channel === "wechat"` 决定是否绑定账号与默认 contentType。渠道种类枚举值（website/wechat）已在 `src/contracts/kinds.ts` 的 `CHANNEL_KINDS` 冻结，但**渠道实现的选取与能力判定散落在 executor 与 workflow 的字面量比较里**，新增渠道需同时改两处并承担漏改风险（P09 目标：发布渠道可扩展）。

## 决策

引入**发布渠道注册表** `src/lib/channels/registry.ts`：

1. 每个渠道一个实现文件：`src/lib/channels/website.ts`、`src/lib/channels/wechat.ts`，实现 `ChannelImpl` 契约（`publish(job)` + 能力字段 `requiresAccount` / `defaultContentType`）。
2. `getChannel(kind)` 返回注册实现；**未知 kind 抛明确错误**（含支持清单），不再静默回退（沿用 ADR-026 解析器注册表同款纪律）。
3. `isChannelKind(v)` 供配置校验/UI 复用，替代就地字面量比较。
4. executor 只做状态机/审核门/提醒/退避，发布动作统一 `await getChannel(job.channel).publish(job)`；内容/类型校验下沉到渠道实现。
5. content-workflow 用 `impl.requiresAccount` / `impl.defaultContentType` 决策，消除 `channel === "wechat"`。

## 行为等价性

迁移为**纯重构**，不做行为变更：

- `publishToWebsite` / `updateOrOfflineWebsite` / `publishToWechat` 函数体**逐行照搬**到 channels/website.ts、channels/wechat.ts，不改逻辑。
- executor 的审核门、发布前提醒、`publishing` 状态更新、`markFailed` 指数退避、`publishScan`/`retryFailedScan` 保持不变。
- 失败语义不变：渠道实现抛错 → executor `catch` → `markFailed`（含 3 次退避与 job_failed 通知）。
- 唯一新增行为：**官网发布成功/更新/下线后调 `invalidateWebContent(["web:articles", "web:home"])`**（B-05 目标的"发布后写失效"，对应 P10 写后失效）。

## 契约与冻结面

- 未修改任何 `src/contracts/**`、`prisma/schema.prisma`、`package.json`、vitest/Playwright 配置。
- 复用 `contracts/kinds` 的 `CHANNEL_KINDS`/`ChannelKind`（冻结面只读）。
- 缓存标签 `web:articles` / `web:home` 复用 `cache-tags.ts` 的 `WEB_TAGS`（冻结面标签，只读）。

## 验证

- 验收1：`grep -n 'channel === "' src/lib/publish-executor.ts src/lib/content-workflow.ts` → 空。
- 单测：`publish-state-machine.test.ts` / `notify-before-publish.test.ts` / `content-review.test.ts` 全通过；新增 `lane-b/channels-registry.test.ts` 覆盖未知 kind 报错、能力字段、isChannelKind、注册表与 CHANNEL_KINDS 一致。
- 门禁四连：lint / typecheck / test / build 全部 exit 0。
- e2e：`collect-publish.spec.ts` 通过。

## 后果

- 正向：新增渠道（如小红书）只需新增 `channels/xxx.ts` + 注册表一行 + 契约 `CHANNEL_KINDS` 加值（加值走契约变更流程）；executor 与 workflow 零改动。
- 反向：`ChannelImpl` 接口若需新增能力字段，会改动所有已注册渠道；当前仅 2 个渠道，风险可控。
- 未决：`invalidateWebContent` 在非 Next 运行时（单测/脚本）静默忽略，符合 `cache-tags.ts` 既有语义，不阻塞写操作。
