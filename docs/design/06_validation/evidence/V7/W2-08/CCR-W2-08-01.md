# CCR-W2-08-01 · 路由内 zod 请求体定义（apply）

> 提出者：W2-08 执行者（主代理）｜任务卡：W2-08（ESLint 边界规则）
> 状态：**待裁决**（本条是 W2-08 的「唯一已知存量违例」，卡交付时已按规程阻断该子项，未越界修改）

## 需要改的文件与精确改动

`src/app/api/apply/route.ts`（当前第 9-15 行）：

```ts
// 现状（违规）
import { z } from "zod";
const applySchema = z.object({
  name: z.string().min(1, "请填写姓名").max(50),
  phone: z.string().min(5, "请填写有效电话").max(20),
  courseId: z.coerce.number().int().positive().nullable().optional(),
  message: z.string().max(1000).nullable().optional(),
  sessionId: z.string().max(64).optional(),
});
```

建议改动（两步，缺一不可）：

1. 在 `src/contracts/resources.ts` 新增（**冻结面，需契约员执行**）：

```ts
/** POST /api/apply：公开报名提交（保 M1 中文文案，故 message 内置而非靠 parseBody 默认文案） */
export const applySubmitSchema = z.object({
  name: z.string().min(1, "请填写姓名").max(50),
  phone: z.string().min(5, "请填写有效电话").max(20),
  courseId: z.coerce.number().int().positive().nullable().optional(),
  message: z.string().max(1000).nullable().optional(),
  sessionId: z.string().max(64).optional(),
});
```

2. `src/app/api/apply/route.ts` 删除本地 `applySchema` 与 `import { z }`，改为：

```ts
import { applySubmitSchema } from "@/contracts/resources";
const parsed = applySubmitSchema.safeParse(body);
```

## 为什么现有契约不够（证据）

- `grep -rn "const .*Schema = z\." src/app/api --include=route.ts` → **仅 1 处命中**：`src/app/api/apply/route.ts:9`。
- `src/contracts/resources.ts` 中无 apply/报名提交的请求体 schema（`grep -rn "apply" src/contracts/*.ts` 只命中 `link: z.string().max(300).default("/apply")`，是**响应侧默认跳转路径**，非请求体）。
- 该路由用 `safeParse` 且刻意取 `issues[0].message` 保留 M1 中文文案（"请填写姓名"/"请填写有效电话"），不能用通用 `parseBody` 的 "参数校验失败" 兜底 —— 所以**不能简单删掉 schema 改走 parseBody**，必须把 schema 迁到契约层并保留内置 message。

## 影响哪些线

| 线 | 影响 |
|---|---|
| 契约（`src/contracts/**`） | 需新增 1 个导出；属冻结面，须契约员最小提交 |
| B 线（路由所有权） | `src/app/api/apply/route.ts` 属 B-03 迁移范围，改 import 属 B 线动作 |
| W2-08 | 规则一旦去掉 `apply` 的豁免，本卡 lint 门禁即可全 error 覆盖，无需保留白名单 |

## 不改的替代方案及代价

| 方案 | 代价 |
|---|---|
| A. 保持现状 + eslint 豁免 `src/app/api/apply/route.ts`（**本卡当前做法**） | 规则对 1 个文件失效；后续若有人照抄该文件写法，规则不会拦。已在 `eslint.config.mjs` 注释与本文件登记，可追溯 |
| B. 规则降为 `warn` | 等于没有门禁（W2-08 明确要求 error），不可接受 |
| C. 直接在本次改契约+路由 | 越界（同时违反「卡片允许修改路径」与「冻结面需 CCR」两条纪律），不采纳 |
| D. 删掉 applySchema 改走 `parseBody` | 用户可见文案从「请填写姓名」变成「参数校验失败」，破坏 M1 对等（REQ-F-013），不采纳 |

## 建议裁决

批准。理由：改动面极小（新增 1 个 schema 导出 + 改 2 行 import），收益是**让边界规则 100% 生效且无豁免**，符合 W2-08「直接 error」的原始意图。批准后执行顺序：契约员先提 `feat(CCR-W2-08-01)` 加 schema → B 线改 route import → W2-08 删掉 `eslint.config.mjs` 中的 `ignores: ["src/app/api/apply/route.ts"]` 与该文件专属 `no-restricted-syntax: off` 块，并把本条状态改为「已落地」。
