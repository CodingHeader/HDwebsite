## 1. 路由结构（Next.js 16 App Router）

```
src/app/
├── layout.tsx            # 根布局（html/body、全局样式）
├── (web)/                # 前台路由组（共享前台 layout）
│   ├── layout.tsx        # 前台布局：Navbar + Footer + FloatingContact
│   ├── page.tsx          # 首页 /
│   ├── about|contact|learning|party/page.tsx
│   ├── courses/{page,[id]/page}.tsx
│   ├── articles/{page,[id]/page}.tsx
│   ├── news/{page,[id]/page}.tsx      # 详情重定向到 /articles/:id
│   ├── partners|gallery|campus/page.tsx
│   ├── apply/{page,ApplyClient}.tsx   # 服务端取场景数据 + 客户端表单/AI
│   ├── services/[slug]/page.tsx       # 服务指南详情（markdown/html）
│   ├── error.tsx | loading.tsx | not-found.tsx
├── manager/              # 后台（无路由组，独立 layout）
│   ├── layout.tsx        # 后台布局（ManagerLayoutClient + Sidebar + Header）
│   ├── login/page.tsx
│   └── <module>/page.tsx × 25（另含 login/page.tsx，共 26 个页面文件）
└── api/                  # 后端路由（见 03-后端设计）
```

- URL 规范化：`next.config.ts` 用 redirects 把历史路径（`/news/*` 十个子分类、`/courses/*` 十个学科、`/about/:slug+`、`/partners/:slug+`）统一收敛到列表页。
- `/uploads/:path*` rewrite 到 `/api/file/:path*`，上传文件经 API 读取（支持 standalone 部署）。

## 2. 渲染与数据获取模式

| 模式 | 位置 | 说明 |
| --- | --- | --- |
| Server Component 直查 DB | 各页面 `page.tsx` | 页面直接 `await` Prisma 查询（经 lib 封装），无需 fetch 自身 API |
| 客户端交互组件 | `ApplyClient.tsx`、AI 聊天、表单 | 页面拆"服务端数据壳 + 客户端交互叶" |
| React `cache()` | `lib/settings.ts` | `getSettings` 请求级去重缓存 |
| 动态渲染 | 全站 | SQLite 直查 + 管理后台实时性 → 未使用 ISR/静态化 |

## 3. 状态管理

- **zustand**：`src/store/authStore.ts`（后台登录态、用户/角色信息）、`src/store/index.ts`。
- **server state**：不引入 react-query；列表页用 `lib/manager-fetch.ts` 封装 fetch + 统一响应解包。
- **hooks**：`src/hooks/useSettings.ts`（前台读取公开 Setting）。

## 4. 样式体系

| 项 | 内容 |
| --- | --- |
| Tailwind CSS v4 | `@tailwindcss/postcss`，utility-first，无全局内联样式 |
| 设计令牌 | oklch 色彩体系（shadcn 约定） |

## 5. 类型组织


## 6. 后台 UI 架构

- `ManagerLayoutClient.tsx`：登录校验（token 无效跳 `/manager/login`）+ 布局骨架。
- `Sidebar.tsx`：读取 `/api/manager-menus`（ManagerMenu 表）渲染动态菜单，按 permission 过滤。
- `Header.tsx`：用户信息、退出登录。
- 通用件：`Pagination.tsx`、`ImageField.tsx`、`ImageUploader.tsx`、`RichTextField.tsx`、`fields/RichTextEditor.tsx`（TipTap v3：image/link/placeholder/text-align/underline 扩展）、`runtime/SchemaForm.tsx`（Registry 驱动动态表单）。

## 8. 错误与加载

- `(web)/error.tsx` / `loading.tsx` / `not-found.tsx` 路由级兜底。
- 客户端请求失败经统一响应 `message` 提示。

## 9. 重构期前端关注点

| 主题 | 建议 |
| --- | --- |
| Markdown 渲染 | 新增需求 N4：详情页需支持 markdown 渲染管线（`react-markdown` 或构建期转换），与现有 TipTap HTML 内容共存（`contentType` 区分） |
| 公众号预览 | N1/N5：后台需增加"公众号样式预览"组件 |
| AI 客服挂载 | N9：官网端聊天组件抽离为独立可挂载 widget（现嵌在 apply 页 + FloatingContact） |
| 管理页样板 | 25 个管理页存在大量重复 CRUD 样板，重构期以 SchemaForm + 配置驱动收敛（见 08-复用设计） |
| 图片域名 | `images.remotePatterns` 放开 `https://**`，重构期应收紧为白名单 |
| XSS 净化缺口 | `services/[slug]/page.tsx:81` 用 `dangerouslySetInnerHTML` 渲染 ServiceGuide.content，未经 `sanitizeHtmlServer`（articles/[id]、courses/[id] 均已净化）——重构期补齐统一净化 |
| SEO 基建缺失 | 无 `sitemap.ts`/`robots.ts`；根布局 `lang="en"`（layout.tsx:47）应为 `zh-CN`；各页 metadata 已齐，补 sitemap/robots 即可 |
| 埋点接线 | UserAction 管线未接线、ElementConfig 零引用（详见 05 §4）——重构期定夺接线或移除 |
