# HDwebsite 部署与恢复手册（D-14）

> 适用版本：`upgrade` 分支（Next 16 + React 19 + Prisma 7 libsql/SQLite + Tailwind v4）
> 适用环境：宝塔（BT Panel）+ PM2 单机部署；Node.js ≥ 24
> 目标验收：全新 Linux 机 ≤30 分钟从备份恢复出可登录的 `/manager`；PM2 restart 后定时任务自动继续

---

## 0. 文档范围与前提

- 本手册不含任何真实密钥。所有凭证在部署机 `.env.local` 中配置，不进代码库、不进镜像、不进日志。
- 数据库：单机 SQLite（libsql driver adapter），备份以 `VACUUM INTO` 生成一致性快照，归档为 `backups/yyyymmdd/<dbname>.tar.gz`（含 `db/` + `uploads/` + `kb/`）。
- 运行时数据目录由 `DATA_DIR` 决定（缺省 `./data`）：`data/uploads`、`data/kb`、`data/db`、`data/backups`。
- 生产入口：`node scripts/start-next.mjs`（Linux 下自动启动 `.next/standalone/server.js`；首次启动自动 build）。

## 1. 环境与前置

| 项 | 要求 |
|---|---|
| OS | 64 位 Linux（Ubuntu 22.04 / CentOS 7.9 等宝塔支持版本） |
| Node.js | ≥ 24（`engines.node = ">=24"`；建议 24.14.x LTS） |
| 内存 | 建议 ≥ 2 GB（`next build` 峰值约 1.5 GB） |
| 磁盘 | 系统盘 ≥ 20 GB；数据盘挂载到 `DATA_DIR`（含上传/备份） |
| 进程管理 | PM2（`pm2 start node scripts/start-next.mjs --name hdwebsite`） |
| 反向代理 | 宝塔 Nginx 站点，`80/443` 反代到 `127.0.0.1:6789` |
| 时区 | `Asia/Shanghai`（调度 cron 与备份目录 `yyyymmdd` 均按本地时间） |

**必须的 `.env.local` 键**（复制 `.env.example` 生成）：

```
JWT_SECRET=<≥32 位随机串，缺失启动即 FATAL>
ENCRYPTION_KEY=<可选，默认派生自 JWT_SECRET；建议显式设置>
DATABASE_URL="file:./prisma/dev.db"
PORT=6789
HOSTNAME=127.0.0.1
DATA_DIR=/opt/hdwebsite/data
APP_DOMAIN=www.hd1994.com
APP_ORIGIN=https://www.hd1994.com
WECHAT_MP_VERIFY_TOKEN=<公众号服务器校验 token，可选>
SMTP_HOST=<可选>
...
```

> **安全提示**：`JWT_SECRET` 必须 ≥32 字符，否则 `assertProductionEnv` 在启动时直接退出。生成方式：
> `openssl rand -base64 48 | tr -d '\n'`

## 2. 首次部署

### 2.1 安装 Node 24

```bash
# Ubuntu 22.04（使用 nodesource）
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
sudo apt-get install -y nodejs
node -v   # 应输出 v24.x
```

### 2.2 拉代码

```bash
sudo mkdir -p /opt/hdwebsite && sudo chown $USER /opt/hdwebsite
cd /opt/hdwebsite
git clone -b upgrade https://github.com/CodingHeader/HDwebsite.git .
```

### 2.3 安装依赖并构建

```bash
npm ci --no-audit --no-fund
cp .env.example .env.local
# 编辑 .env.local 填入真实值（见第 1 节）
npx prisma generate
npm run db:deploy      # prisma migrate deploy：不生成新迁移，只应用已有
npm run db:seed        # 初始管理员 admin/admin123（上线前必须修改）
npm run build
```

> **Prisma 7 说明**：`@prisma/client` 已无 postinstall generate 脚本，必须显式 `npx prisma generate`。
> **首次 build 需要 `DATABASE_URL` 可访问**：build 阶段不执行 `instrumentation.register()`，但页面静态生成若读库需要 DB 存在。

### 2.4 启动（PM2）

```bash
npm install -g pm2
pm2 start node scripts/start-next.mjs --name hdwebsite
pm2 save
pm2 startup          # 开机自启
```

`scripts/start-next.mjs` 的行为：

- 读取 `.env.local`（`@next/env` 按 Next 优先级加载）；
- 若 `.next/BUILD_ID` 缺失或 `src/public/prisma/schema/package.json` 等监视项变更，自动重跑 `next build`；
- Linux 下启动 `.next/standalone/server.js`（自动复制 `.next/static` 与 `public` 到 standalone 目录）；
- 启动时 `instrumentation.register()` → `assertProductionEnv()` 校验环境变量 → 注册 6 个 job → `startScheduler()` 每分钟扫描 cron。

### 2.5 反向代理（宝塔 Nginx）

```
location / {
    proxy_pass http://127.0.0.1:6789;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 20m;    # 上传上限（UPLOAD_MAX_SIZE 见 src/lib/storage.ts）
}
```

## 4. 备份

### 4.1 自动备份

调度器已注册 `backup` job，默认每日 `03:00` 执行：

- 用 `VACUUM INTO` 生成数据库一致性快照（避免直接 cpSync 活跃库文件撕裂）；
- 归档 `db/<dbname>` + `uploads/**` + `kb/**` 为一个 tar.gz（`src/lib/jobs/tar.ts` 手写 ustar，零新增依赖）；
- 按天目录排序，只保留最近 14 份（`KEEP_COUNT = 14`）；
- 失败不阻塞站点（任务注册为 `scheduledJobNames` 之一，异常仅 `console.error`）。

备份产物：`$DATA_DIR/backups/yyyymmdd/<dbname>.tar.gz`

### 4.2 手动备份

```bash
cd /opt/hdwebsite
# 触发一次调度扫描（等 backup 到点，或临时调整 cron 到当前分钟后 1 分钟）
node scripts/start-next.mjs   # 正常启动即可，backup 到 03:00 自动跑
# 或直接用 sqlite 快照 + tar 手工打：
sqlite3 prisma/dev.db "VACUUM INTO '/tmp/dev.db.snap'"
tar -czf /opt/hdwebsite/data/backups/$(date +%Y%m%d)/dev.tar.gz \
  -C /tmp dev.db.snap \
  -C $DATA_DIR uploads kb
```

## 5. 还原（restore.mjs）

`scripts/restore.mjs` 解析 `backups/yyyymmdd/<name>.tar.gz`（内联 ustar 解析，与 `src/lib/jobs/tar.ts` 同格式），还原回 `DATA_DIR`。

### 5.1 dry-run（默认，只校验不落盘）

```bash
node scripts/restore.mjs
# 输出：DRY-RUN 备份：<path>；条目 N 项：db=... uploads=... kb=...
# 不会修改任何文件
```

### 5.2 实际还原

```bash
# 前提：目标 DATA_DIR 的 uploads/ 与 data/kb/ 为空（或已清理）
node scripts/restore.mjs --apply
# 覆盖非空目录需显式 --force（会先清空 uploads/ 与 data/kb/，仅限明确授权）
node scripts/restore.mjs --apply --force
# 或指定归档文件
node scripts/restore.mjs --apply /opt/hdwebsite/data/backups/20261020/dev.tar.gz
```

还原路径映射：

| 备份内条目 rel | 落盘位置 |
|---|---|
| `db/<dbname>` | `$DATA_DIR/data/db/<dbname>`（数据库文件） |
| `uploads/**` | `$DATA_DIR/uploads/**` |
| `kb/**` | `$DATA_DIR/data/kb/**`（注意：备份内前缀是 `kb`，实际落 `data/kb`，`restore.mjs` 内部自动重映射） |

还原完成后：

```bash
# 数据库文件已就位，执行迁移（确保与代码版本匹配）
cd /opt/hdwebsite
npx prisma generate
npm run db:deploy
pm2 restart hdwebsite
pm2 save
```

### 5.3 还原完成标准

- `/manager` 页面可登录（`admin` 账号；首次部署若为默认密码则必须修改）；
- 上传媒体可正常访问（`/uploads/**` rewrite 到 `$DATA_DIR/uploads`）；
- 知识库文件可查询；
- 调度日志显示 cron 继续执行（见第 7 节）。

## 6. 回滚

回滚 = 停服务 → 还原上一个备份 → 切代码版本 → 重跑迁移 → 重启：

```bash
pm2 stop hdwebsite
cd /opt/hdwebsite
git checkout <上一个稳定提交或 tag>
npm ci --no-audit --no-fund && npx prisma generate
node scripts/restore.mjs --apply --force
npm run db:deploy
npm run build
pm2 restart hdwebsite && pm2 save
```

> **回滚注意**：`restore.mjs --force` 会清空 uploads/ 与 data/kb/，执行前务必确认备份完整。数据库文件是回滚的根依据——先 `VACUUM INTO` 快照一次当前状态再回滚。

## 7. 调度连续性验证（PM2 restart 后）

调度基座由 `src/instrumentation.ts` 的 `register()` 钩子启动：

1. 进程启动 → `assertProductionEnv()` → `import("@/lib/jobs")`（注册 6 个 job）→ `startScheduler()`。
2. `startScheduler()` 设 `setInterval(..., 60000)`，每次 `scanOnce()` 遍历 `scheduledJobNames` 中到期的 job。
3. PM2 `restart` 会重新拉起进程 → 重新走 `register()` → 调度器自然续跑。

**验证方式**（在日志中观察）：

```bash
pm2 logs hdwebsite
# restart 前的最后一条：应为某个 job 的执行日志（如 [backup] 已归档 ... 或 collect.run 触发）
pm2 restart hdwebsite
pm2 logs hdwebsite
# restart 后的第一条：应为 [scheduler] 调度基座已启动（每分钟扫描） + 随后 60 秒内某 job 的扫描日志
```

> 若备份任务 cron 未到点，可临时改数据库 `cron` 字段到当前分钟 + 1 观察一次执行，再改回。

## 10. 30 分钟恢复演练模板（全新 Linux 机）

> 演练时逐行记录耗时，目标 ≤ 30 分钟。以下步骤假设备份 tar.gz 已拷到本机 `/tmp/backup.tar.gz`，`DATA_DIR` 已挂载。

| 步骤 | 预估耗时 |
|---|---|
| 1. 安装 Node 24 + PM2 | ~5 分钟 |
| 2. `git clone -b upgrade` | ~1 分钟（视带宽） |
| 3. `npm ci --no-audit --no-fund` | ~3 分钟 |
| 4. 写 `.env.local` | ~1 分钟 |
| 5. `npx prisma generate` + `npm run db:deploy` + `npm run db:seed` | ~1 分钟 |
| 6. 设 `DATA_DIR=/opt/hdwebsite/data`，`node scripts/restore.mjs --apply /tmp/backup.tar.gz` | ~2 分钟 |
| 7. `npm run build` | ~5 分钟 |
| 8. `pm2 start node scripts/start-next.mjs --name hdwebsite` + 反代 | ~1 分钟 |
| 9. 浏览器访问 `/manager` 登录验证 | ~1 分钟 |
| 10. 观察日志确认调度续跑 | ~5 分钟（等下一次 cron） |
| **合计** | **≤ 25 分钟**（留 5 分钟缓冲） |

**演练结论记录方式**：开始时间 → 每一步完成时间 → `/manager` 登录成功时间；差异记入 `docs/design/06_validation/evidence/V7/D-14/`。
