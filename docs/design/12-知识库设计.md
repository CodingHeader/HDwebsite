# 知识库设计提取与升级方案

> 现状基准：`Knowledge` / `ChatScene` 模型 + `chat/completion` 检索实现；升级部分对应新增设计 N2/N6/N7/N8。
> 文档体系关联：三级模型方案 ↔ REQ-F-007/SOL-002；采集默认入库 ↔ REQ-F-006｜总索引：README.md §0

## 1. 现状（As-Is）

### 1.1 数据模型
| 字段 | 说明 |
| --- | --- |
| Knowledge.title | 检索结果预览标题 |
| Knowledge.content | markdown 纯文本正文 |
| Knowledge.tags | 逗号分隔标签（zikao/chengkao/kaifang/fee/enrollment…） |
| Knowledge.source | local / notion / feishu / web |
| Knowledge.externalId / externalUrl | 外部源元信息 |
| Knowledge.priority | 越大越优先注入 prompt |
| Knowledge.status | active / inactive |

### 1.2 检索机制
```
ChatScene.knowledgeTags（tag 白名单） + useKnowledgeBase 开关
  → findMany(status=active, tags contains 任一)
  → orderBy priority desc, updatedAt desc
  → take 6
  → 拼 "[i] title\ncontent" 注入 system
```

### 1.3 管理界面
- `/manager/knowledge`：单表条目 CRUD（新增/编辑/停用/标签维护）。

## 2. 现状局限

| # | 局限 | 影响 |
| --- | --- | --- |
| K1 | 单表扁平，无"库/文件"层级 | 无法按业务域隔离知识 |
| K2 | contains 全表 LIKE | 量大后慢且召回粗糙 |
| K3 | 整条注入（不切片） | 长 doc 撑爆 token 或被截断 |
| K4 | 无采集接入位 | N6（采集默认入库）无处安放 |
| K5 | 无导入/导出/批量操作 | 运营效率低 |

## 3. 升级设计（To-Be）

### 3.1 三级模型
```
KnowledgeBase（知识库）
  id / code / name / description / vectorProvider? / embeddingModel?
  status / isDefault / createdAt

KnowledgeFile（文件/条目）
  baseId → KnowledgeBase
  title / format(markdown|html|text) / content 全文
  source(collect|manual|import|api) / sourceUrl / externalId
  collectItemId? ← 采集产物回链（N6）
  status(pending|active|disabled)   ← 采集默认 pending，审核后 active
  version / createdAt / updatedAt

KnowledgeChunk（切片）
  fileId → KnowledgeFile
  seq / content(≤800 字建议) / tags / priority
  keywords / embedding(JSON, 预留)
  status
```

### 3.2 管理后台（对应 N7 三类管理）
| 页面 | 能力 |
| --- | --- |
| 知识库管理 | 库 CRUD、默认库指定、向量模型配置（预留）、库统计 |
| 文件管理 | 文件树/列表、markdown 在线编辑、导入（md/txt/docx）、导出、批量启停、审核采集产物 |
| 其他管理 | 标签管理、切片重建（重新切片任务）、检索测试（输入问题→预览命中 chunk）、回收站 |

### 3.3 检索机制升级（分两期）
- **一期（随重构落地）**：Chunk 级检索，tags contains + priority + 更新时间，take 6；每 chunk 注入带 `[库名] 标题` 前缀。
- **二期（预留）**：embedding 字段 + 向量库（libsql vector / sqlite-vec / 外部服务），混合检索（关键词 + 语义）。

### 3.4 采集 → 知识库默认链路（N2+N6）
```
CollectItem(去重通过) → 自动创建 KnowledgeFile(status=pending, source=collect)
  → 归属规则: 采集源配置 targetBaseId + 自动 tags
  → 后台审核 → active → 可被 AI 检索
```

### 3.5 与大模型的关系（N8）
- ChatScene 增加可绑定"知识库"（baseId 列表，替代单一 tag 白名单；tags 保留为库内过滤）。
- LLMProvider/应用配置中可声明默认知识库与注入 token 上限。

## 4. 补充（2026-10-10 第二轮实测）

### 4.1 知识种子实测（12 条，seed-knowledge-scenes.mjs）
- tag 体系全集：`school` `about` `contact` `zikao` `chengkao` `kaifang` `exam` `enrollment` `process` `policy` `fee` `major` `discount`（多数条目 2–4 个 tag 组合）。
- 覆盖主题：学校介绍与联系方式、自考/成考/开大三模式报名与考试流程、费用与优惠、政策、专业选择。
- 注入通道为本地 HTTP API（需 dev 启动 + admin 登录），与 seed.ts 直连 DB 双通道并存 → 重构期统一。

### 4.2 检索测试端点（新增设计补充，配套 §3.2"其他管理"）
```
POST /api/knowledge/test-search
  { query, baseIds?, tags?, topK=6 }
  → 命中 chunk 预览（得分 / 来源文件 / 前缀标识）
```
供后台"检索测试"面板与 llm-gateway 调试复用；上线向量检索后同一端点返回混合检索结果。

### 4.3 ChatScene 绑定关系实测
现存三场景（apply/float/guide）均配置 knowledgeTags 白名单 + useKnowledgeBase 开关；三级模型落地后 ChatScene 增加绑定的 baseId 列表，tags 降级为库内过滤（→ §3.5）。

## 5. 方向转向：外部知识库对接（2026-10-10，ADR-020）

> **本节为最新权威方向，§3 三级模型方案转为备选留档。**

- **决策**：知识库采用外部平台（选型未定：Dify / FastGPT / 内部服务候选），**项目内不部署**知识库。
- **新架构**：
```
应用（AI 客服 / 采集 / 发布）
  └─ KBAdapter 适配层（统一接口）
       ├─ search(query, topK)          # 检索
       ├─ pushFile / upsertFile / remove # 入库/更新/删除
       ├─ 实现A: DifyClient   （后补）
       ├─ 实现B: FastGPTClient（后补）
       └─ 实现C: LocalFallback  # 本地 Knowledge 表 contains 检索兜底（双轨保留）
```
- **路由策略**：外部库可用 → 优先外部检索；外部库异常/未配置 → 自动降级 LocalFallback（现有 Knowledge 链路原样保留）。
- **采集入库（N6 变更）**：CollectItem 审核通过 → 经 Adapter pushFile 到外部库；本地不再建 KnowledgeFile，仅留 CollectItem 原文。
- **管理后台（N7 变更）**：知识库页瘦身为三块——外部库连接配置（endpoint/key/库标识）、检索测试（调 Adapter.search 预览命中）、本地兜底条目管理（现有 /manager/knowledge 保留）。
- **影响**：S2 工期下降；12 章 §3 三级模型、§4.2 test-search 端点设计保留为"若回归自建"的备选方案。
