## 1. 数据库选型与运行时

| 项 | 内容 |
| --- | --- |
| 引擎 | SQLite（单文件 `prisma/dev.db`） |
| ORM | Prisma 7（`prisma-client-js` 生成器 + `@prisma/adapter-libsql`） |
| 配置 | `prisma.config.ts`（`DATABASE_URL="file:./dev.db"`；.env 不会被 Prisma 自动加载，走 config 显式管理） |
| 迁移 | `npx prisma migrate dev`；历史 `.sql` 备份在 prisma/ 下（8 个） |
| 种子 | `prisma/seed.ts`（`npx prisma db seed`）：角色/用户/菜单/首页配置/AI 场景/知识条目/服务指南等 |
| 持久化 | docker volume `./prisma:/app/prisma`，容器重建数据不丢 |

## 2. 模型全景（按 Phase 分层）

### 权限层（Phase 1.1.1）
- **Role**：name/slug/permissions(JSON 字符串)/isSuper/status
- **User**：username/passwordHash(bcrypt)/email/个人资料/roleId/登录统计（lastLoginAt/Ip、loginCount）

### 结构层
- **Navigation**（Phase 1.1.2）：自关联无限级（parentId/level）、linkType(internal/external/dropdown)、模板与分类绑定（templateId/categoryId/contentType）、显示配置（sort/isVisible/isNav）、元数据 JSON（badge/hoverEffect/clickAction/activeIndicator）、SEO 三件套
- **Category**（Phase 1.1.3）：自关联多级、type(article/course/partner)、模板 code（templateList/templateDetail）、SEO、isNav
- **ManagerMenu**（Phase 3.4）：后台菜单树（code/label/icon/path/parentId/level/permission/sort/badge）

### 内容层
- **Article**（Phase 1.1.4）：slug 唯一/content/excerpt/coverImage/authorId/categoryId/tags 多对多/status(draft/published/archived)/isTop·isRecommend·isHot/viewCount·likeCount/SEO/publishedAt
- **Tag / ArticleTag**：多对多（复合主键，Cascade 删除）
- **News**：简化新闻表（title/content/cover/views/status）→ ⚠ 与 Article 重叠（冲突 C1）
- **Course**：title/price/duration/outline/cover/categoryId → 挂 Student
- **Student**：报名线索（name/phone/courseId/message/status=pending）
- **Partner / Campus / CampusImage / Gallery / Banner**：展示资源
- **HomeCard / HotMajor / ServiceGuide**：首页区块内容（icon/gradient/link/sort/status；ServiceGuide 带 slug+content 生成详情页）

### 模板层（Phase 2.1）
- **PageTemplate**：code/name/layout(default/sidebar/fullwidth)/contentType/templateFile/thumbnail/config JSON/isDefault
- **ContentBlock**：code/type(hero/banner/list/grid/sidebar)/数据源(static/query/api)+query/limit/style/interactions
- **TemplateBlock**：模板↔内容块多对多（sort/config）
- **ElementConfig**（Phase 3.1）：页面元素级配置（elementId="001-001"、layer 1-14、selector、normal/hover/active 三态 JSON、interactions JSON）——"712 交互点"体系

### AI 层（Phase 3.2）
- **AIConfig**：apiEndpoint/apiKey(注明加密存储)/model/systemPrompt/userPrompt/greeting/temperature/maxTokens/rateLimit(60/min)/dailyQuota(1000)/allowedDomains/isActive
- **AIChatHistory**：sessionId/conversationId/ip/ua/role/message/model/temperature/tokensUsed/responseTime/pageUrl/pageTitle/metadata
- **Knowledge**（Phase 3.2.1）：title/content(markdown)/tags(逗号分隔)/source(local/notion/feishu/web)/externalId/externalUrl/priority/status
- **ChatScene**（Phase 3.2.2）：code/name/greeting/systemPrompt/knowledgeTags/starters JSON + 前台渲染文案（pageTitle/pageSubtitle/headerTip/sidebarTitle/processSteps/promiseList/contactCardTitle）+ useKnowledgeBase 开关

### 统计与审计层
- **UserAction**（Phase 3.3）：actionType(click/view/submit)/actionTarget(phone/wechat/qq/apply)/sessionId/ip/ua/pageUrl/referrer/metadata
- **ViewStats**：contentType+contentId 维度日统计（pageViews/uniqueVisitors/source/referrer）
- **OperationLog**（Phase 3.4）：userId/username/module/action/title/content({before,after} JSON)/ip/ua

### 配置与媒体层
- **Setting**（Phase 1.1.5）：key 唯一/value/type(string/number/boolean/json)/group(basic/contact/seo/social…)/isPublic/isEncrypted
- **Media**（Phase 2.3）：filename/path/url/mimeType/size/type(image/video/document)/category/uploaderId/metadata(缩略图 JSON)

## 3. 数据建模模式与约定

| 模式 | 说明 |
| --- | --- |
| JSON-in-String | SQLite 无原生 JSON，所有灵活结构（permissions/metadata/interactions/starters/query/style/config）以 String 存 JSON，读取侧 try/catch 容错 |
| 自关联树 | Navigation/Category/ManagerMenu 统一 parentId + level |
| 枚举即字符串 | status/type/linkType 等用 String + 注释约定，无 DB 级约束 |
| 软删除 | 未实现；删除即物理删（ArticleTag 例外用 Cascade） |
| 时间戳 | createdAt/updatedAt 全覆盖；发布类字段 publishedAt 可空 |
| 索引 | 高频过滤列均有 @@index（status/sort/slug/parentId/type/createdAt 等）；复合索引仅 ViewStats(contentType,contentId) |

## 4. 关系图（文字版）

```
Role 1─n User 1─n Article/ Media / OperationLog
Category 1─n Article n─n Tag（经 ArticleTag）
Category 1─n Course 1─n Student
Navigation n─1 PageTemplate / n─1 Category

AIConfig 1─n（逻辑上）AIChatHistory（无外键，仅字段记录）

```

## 6. 数据安全与合规

- 密码 bcrypt(10)；JWT_SECRET 必配（缺失启动即抛 FATAL）。
- AIConfig.apiKey 当前明文存储（schema 注释"加密存储"未落实）→ 重构必改。
- 上传文件名安全化（时间戳+随机），路径穿越由 `/api/file` 需在重构时校验（当前 `[...path]` 直读，需加白名单校验）。

### 7.2 新增冲突 C9：Setting key 双体系（⏳ 待确认）
- **seed 旧体系**：点分 key（`site.title`、`contact.phone1`、`seo.title`）+ 旧分组（basic/school/contact/seo/social）。
- **Registry 新体系**：扁平 key（`siteName`、`contactPhone`、`seoTitle`）+ 新分组（site/topbar/banner/stats/company/contact/seo/cards/footer/other）。
- `/api/settings` GET 合并时**两套 key 同时返回**，消费方各取所需 → 同一事实两份 key 易漂移（实例：seed"新概念学历教育" vs Registry 默认"弘道教育"双品牌名并存）。
- 建议方案（→ 待 ADR-009）：统一为 Registry 体系；写迁移脚本转换存量 DB 值；seed 更新为新 key；废弃点分 key。

### 7.3 建模补充
- seed 绝大多数 upsert 的 update 分支为空 `{}`——重跑**不覆盖**手工修改；**例外：HomeCard**（existing → 用种子值覆盖）。
- ContentBlock.query JSON 直接内嵌 Prisma 查询意图，运行期无消费方闭环（与 ElementConfig 同属"建而未用"，→ 01 §9 演进结论）。
