## 2. 认证与授权链路

```
login → bcrypt.compare → generateToken(JWT_SECRET, 7d)
     → 前端保存 token → 请求带 Authorization: Bearer <token>
     → authenticateRequest(request)            # lib/api-auth.ts：统一 401 响应
     → checkPermission(role, "module:action")  # lib/auth.ts
```

- 权限匹配顺序：`isSuper` → 精确匹配 → `module:*` → `*`。
- 现存重复：多个路由各自把 `SessionUser.role` 重建为 `Role` 对象（`roleForCheck` 样板），重构期应下沉为 `requirePermission(request, permission)` 一步到位（`lib/auth.ts` 已有该函数但路由未统一使用）。

## 3. 统一响应与校验

- 响应包：`{ code, data, message }`（`lib/api-response.ts`：success/error/unauthorized/notFound/forbidden/serverError）；HTTP 状态码与业务 code 并行设置。
- 入参校验：zod schema（每路由内联定义，如 articleSchema）→ `safeParse` → 400 返回首个 issue。
- 错误处理：try/catch + `console.error` + 500 统一兜底；敏感信息不外泄。

## 8. 补充（2026-10-10 第二轮实测）

### 8.1 /api/settings 路由实测（v1 兼容层）
- **GET**：公开无鉴权——查 `isPublic=true` 的 Setting，合并 Registry 默认值，返回扁平对象 `{key: value}`。
- **POST**：仅需登录（authenticateRequest），**无 `setting:*` 权限点校验**——任何有效登录者可改全站公开配置（安全缺口，重构期必须补 `setting:edit`，与 REQ-NF-002 呼应）。
- POST 走 Registry 批量校验（validateSettings）→ 按 Registry 元数据 upsert（type/group/isPublic/isEncrypted 自动补齐）。

### 8.2 权限字符串体系实测全集（ManagerMenu.permission）
`course:list` `news:list` `student:list` `article:list` `banner:list` `category:list` `navigation:list` `tag:list` `media:list` `partner:list` `gallery:list` `campus:list` `service:list` `user:list` `role:list` `setting:list` `log:list` `content:edit`
> 菜单可见性与 API checkPermission 共用同一 `module:action` 体系；重构新模块沿用：`collect:edit` `publish:edit` `kb:edit` `llm:edit` `notify:edit` `wechat:edit`。

### 8.3 认证补充
- `/api/auth/refresh` 存在，但前端无自动续期调度（7 天到期即登出）→ 重构期补静默续期或滑动过期。
