## 1. 官网和官方公众号统一管理（N1）

**目标**：一处创作/采集，官网与公众号两渠道分发，状态可视。

### 1.1 渠道模型
```
WechatAccount（公众号账号）
  id / name / type(服务号|订阅号) / appid / appSecret(isEncrypted)
  verifyToken / encodingAESKey(isEncrypted)
  tokenCache(accessToken, expiresAt)   # 缓存，过期前5分钟刷新
  status / createdAt

ContentItem（内容中枢，一稿多发的源）
  id / title / contentType(markdown|html) / content / excerpt / coverImage
  authorId / tags / status(draft|pending_review|approved|published|offline)
  createdAt / updatedAt

ContentChannel（渠道分发记录）
  itemId → ContentItem / channel(website|wechat) / channelId?(WechatAccount)
  externalId(微信 publish_id / media_id) / externalUrl
  status(unsent|scheduled|publishing|published|failed) / errMsg
  publishedAt
```

### 1.2 统一管理页
- 内容中枢列表：一稿多渠道状态列（官网 ✓ / 公众号 ⏳）。
- 编辑器：markdown 为主（N4），右侧"渠道预览"Tab（官网样式 / 公众号样式）。
- 操作：发布到官网 / 发布到公众号 / 同时发布 / 定时发布（N3/N5）。

## 2. 自动采集子系统（N2）

### 2.1 数据模型
```
CollectSource（采集源）
  id / name / type(rss|html|wechat_mp|api) / url
  parser(选择器/规则 JSON：listSelector,titleSelector,contentSelector,时间格式…)
  targetBaseId → KnowledgeBase   # 采集默认入的知识库
  autoTags                       # 自动打标
  schedule(cron) / enabled
  lastRunAt / lastStatus / errMsg

CollectTask（运行记录）
  id / sourceId / startedAt / finishedAt
  stat(fetched/created/duplicated/failed) / status(running|done|failed)

CollectItem（采集条目）
  id / sourceId / url(唯一 hash 去重) / urlHash
  title / rawContent / contentMd(清洗后 markdown) / images JSON
  publishTime / status(new|dedup|reviewed|rejected|converted)
  knowledgeFileId?  → KnowledgeFile   # 转知识库回链
  createdAt
```

### 2.2 采集流程
```
调度器(cron) → CollectTask 创建 → 拉取源(rss/html)
  → 解析器抽条目 → 清洗正文为 markdown（去脚本/样式，图片转存可选）
  → 去重（urlHash 主 + 标题相似度阈值 0.9 辅）
  → CollectItem(status=new) → 自动生成 KnowledgeFile(status=pending, source=collect)
  → 后台审核列表 → 通过→active / 拒绝→rejected
```

### 2.3 管理页
- 采集源管理：源 CRUD + 立即执行 + 运行历史。
- 采集条目：审核队列（通过/拒绝/编辑后入库）。
- ⚠ 待确认 C3：学校/部门源清单由运营后台维护，系统不预置。

## 3. 自动更新与发布官网信息/新闻（N3）

### 3.1 发布任务模型
```
PublishJob（发布任务）
  id / itemId → ContentItem / channel(website|wechat) / accountId?
  action(publish|update|offline)
  scheduledAt / startedAt / finishedAt
  status(pending|reviewing|scheduled|publishing|published|failed|cancelled)
  preNotify(true 默认) / result JSON / errMsg
```

### 3.2 状态机
```
draft → pending_review → approved → scheduled
  → [scheduledAt 到点 / 手动立即] → publishing
  → 发布前 N 分钟 → 邮箱提醒（N11，preNotify）
  → website: 写入 Article(status=published, contentType=markdown)
    wechat: 草稿箱 →（可选延时）freepublish
  → published | failed(→邮件告警→可重试)
```

### 3.3 官网自动更新范围
- 新闻/文章：CollectItem 审核通过 → ContentItem → PublishJob（website）→ Article。
- 站点信息类（Setting）：支持"变更单"模式（可选二期）：修改暂存 → 定时生效 → 变更邮件通知。
- 定时器：调度基座每分钟扫描 scheduled 到点任务。

## 4. Markdown 发布管线（N4）

### 4.1 存储与渲染
| 层 | 设计 |
| --- | --- |
| 存储 | Article/ContentItem 增加 `contentType`（html=存量 TipTap 内容 / markdown=新内容）；markdown 原文入 content 字段 |
| 渲染 | `MarkdownRenderer` 组件：markdown → HTML（GFM 表格/任务列表/代码高亮/图片懒加载/锚点目录） |
| 摘要 | 入库时自动截取纯文本前 200 字为 excerpt（可覆盖） |
| 封面 | 正文首图自动提取为 coverImage（可覆盖） |
| 服务指南 | ServiceGuide.content 同管线下沉支持 markdown（现状已标注 markdown/html） |

### 4.2 兼容策略
- 存量内容零迁移（contentType=html 原样渲染）。
- 编辑器双模：markdown 编辑器（新）+ TipTap（存量编辑），按 contentType 切换。
- 图片语法 `![](url)` 走站内 uploads 或外链白名单。

## 5. 自动发布公众号文章（N5）

### 5.1 依赖与前提
- **已认证服务号/订阅号** + IP 白名单（服务器出口 IP）+ appid/secret（C2 待用户提供）。
- 接口：`/cgi-bin/token`（access_token）、`/cgi-bin/draft/add`（草稿）、`/cgi-bin/freepublish/submit`（发布）、素材上传 `/cgi-bin/material/add_material`。

### 5.2 发布流程
```
PublishJob(wechat, scheduledAt 到点)
  1. 取 accessToken（WechatAccount 缓存，过期前刷新）
  2. 正文内图片上传 → 得 url 替换（微信域）
  3. coverImage → 永久素材 media_id
  4. draft/add（title/content/thumb_media_id/author/digest）
  5. 可选：立即 freepublish 或人工在公众平台点发布（配置开关）
  6. 回写 ContentChannel.externalId/externalUrl/status
  7. 失败 → 邮件告警（N11）+ 任务可重试（指数退避，最多 3 次）
```

### 5.3 管理页
- 公众号账号管理（appid/secret 加密录入、token 状态测试）。
- 发布队列：待发/已发/失败列表 + 重试按钮。
- 频控：发布间隔 ≥60s、每日上限可配（默认 20 篇）。

## 6. 知识库平台（N7）→ 详见 `12-知识库设计.md`

- 三级模型：KnowledgeBase → KnowledgeFile → KnowledgeChunk。
- 管理三块：**库管理**（CRUD/默认库/统计）、**文件管理**（导入 md/txt/docx、在线编辑、审核采集产物、批量启停、导出）、**其他管理**（标签、切片重建、检索测试、回收站）。
- 采集默认入库（source=collect, status=pending）。

## 7. 大模型配置与使用（N8/N10）

### 7.1 多模型模型
```
LLMProvider（替代/升级 AIConfig）
  id / name / endpoint / apiKey(isEncrypted) / model
  temperature / maxTokens / topP?
  priority Int          # 对话优先级，小值优先（1 最高）
  isDefault Boolean     # 默认模型（新会话首选，唯一）
  isFallback Boolean    # 兜底模型（全部失败后必用，唯一）
  status(active|inactive)
  # 余额/配额监控
  balance Float? / balanceCurrency? / balanceCheckedAt
  balanceThreshold Float?    # 低于阈值触发邮件（N11）
  dailyQuota / rateLimit
  metadata JSON（供应商备注等）
```

### 7.2 路由策略（llm-gateway 单点）
```
chat(messages, scene)
  1. 取 isDefault 且 active → 调用（超时可配，默认 30s）
  2. 失败(网络/5xx/超时/429) → 按 priority asc 逐个尝试其余 active
  3. 全部失败 → isFallback 必试
  4. 每次：记录 tokensUsed/耗时/成败 → 汇总到统计
  5. 余额检查（定时任务按供应商余额接口或人工填报）→ 低于阈值 → 邮件
```

### 7.3 应用配置
- ChatScene：systemPrompt/greeting/knowledgeTags/知识库绑定/token 上限（N8"提示词及其他参数"）。
- 管理页：模型列表（拖拽调 priority、设默认/兜底）+ **连通性测试**（一键发测试消息，返回延迟与回复）+ 对话优先级可视化 + 用量统计（按模型/日）。

## 8. AI 客服（N9）

### 8.1 官网端
- 复用 `/api/chat/completion` → 升级走 llm-gateway。
- ChatWidget 组件：全局悬浮/页面嵌入两种挂载；多场景（ChatScene）。
- 升级点：SSE 流式输出；会话续传（sessionId 存 localStorage）。

### 8.2 公众号端
```
微信服务器 → /api/wechat/callback（GET 验签 / POST 消息）
  → 被动回复"正在为您查询…"（5 秒限制）
  → 异步调 llm-gateway（含知识检索）
  → 客服消息接口补发答案（48h 窗口内）
  → 超长答案截断 + 引导官网
```
- AI 客服开关：WechatAccount.aiEnabled + 绑定 ChatScene（默认 faq 场景）。
- 风控：每用户限频（如 10 次/分钟），黑名单，敏感词过滤（复用 xss-filter 思路）。

## 9. 邮箱提醒（N11）

### 9.1 数据模型
```
NotifyRecipient（提醒人）
  id / name / email / groups JSON(["publish","ops"]) / enabled

NotifyRule（提醒规则）
  id / event / enabled / templateId? / recipients组 / 静默时段?
  # event 枚举：
  #   before_publish_news      发布新闻前
  #   before_publish_info      发布信息前
  #   before_publish_wechat    发布公众号文章前
  #   llm_balance_low          大模型余额不足
  #   job_failed               任务失败
  #   system_error             报错（未捕获异常/上游持续失败）
  #   collect_failed           采集失败

NotifyRecord（发送记录）
  id / ruleId / event / toEmails / subject / content / status(sent|failed)
  retries / errMsg / sentAt
```

### 9.2 SMTP 配置（Setting 分组 email）
host/port/secure/username/password(isEncrypted)/from；连接测试按钮。

### 9.3 触发点接线
| 事件 | 触发位置 |
| --- | --- |
| 发布前三类 | PublishJob 进入 publishing 前提醒（提前量可配，默认提前 30 分钟；立即发布则为"即将发布"即时邮件）|
| 余额不足 | 余额检查定时任务 |
| 报错 | 全局 error 边界 + API catch 钩子（聚合限频：同类错误 10 分钟内只发 1 封）|
| 任务失败 | 调度基座任务 failed |

### 9.4 发送机制
- 异步队列（不阻塞主流程）、失败重试 3 次（指数退避）、NotifyRecord 全留痕、管理页可查。
- 邮件模板：变量 {title, time, detail, link}，默认简洁 HTML 模板。

## 10. 调度基座（公共服务）

```
Job 表: type(collect|publish|notify|balance_check|backup)
        payload JSON / cron? / status(idle|running|done|failed)
        lastRunAt / nextRunAt / retries
Worker: setInterval 每分钟扫描 nextRunAt ≤ now 的任务
        执行 → 写回状态 → 失败告警（N11）
```
- 附带 `backup` 内置任务：每日 03:00 备份 dev.db + uploads 到 `backups/yyyymmdd/`，保留 14 份。
