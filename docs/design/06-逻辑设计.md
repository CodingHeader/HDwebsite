## 1. 认证逻辑

```
login(username, password)
  → prisma.user.findUnique(username) + include role
  → 校验 isActive && status==='active'
  → bcrypt.compare
  → generateToken({userId, username, roleId, roleName}, 7d)
  → 更新 lastLoginAt/lastLoginIp/loginCount + OperationLog(login)
```

- `verifyToken` 失败一律返回 null → 401。
- `getCurrentUser`：token → DB 实时校验（角色被禁用立即失效）→ 解析 permissions JSON（容错空数组）。

## 2. 权限判定逻辑（lib/auth.ts）

```
checkPermission(role, "article:create")
  1. role.isSuper → true
  2. permissions.includes("article:create") → true
  3. permissions.includes("article:*") → true
  4. permissions.includes("*") → true
  5. else false
```

辅助：`checkAnyPermission`（任一满足）、`checkAllPermissions`（全部满足）。

## 3. 设置合并逻辑（SSOT 模式）

```
getSettings()  [React cache 请求级缓存]
  = Registry 默认值 (settings-registry.getDefaultValues)
  ⊕ DB Setting 表实际值（覆盖）
getSetting(key)
  = DB 值 || 调用方 defaultValue || Registry 默认值
```

- Registry 定义：key/label/type/group/defaultValue/isPublic/isEncrypted/zod 校验/options/colSpan。
- 分组：site/topbar/banner/stats/company/contact/seo/cards/footer 等，按 order 排列。

## 4. 区块渲染逻辑（block-registry）

```
首页区块 = BLOCK_REGISTRY 定义(code/type/dataSource/fields/defaultProps)
  ⊕ ContentBlock DB 配置 / Setting 值
dataSource 类型: static | query(如 home-banner 查 Banner 表) | api | settings
```

## 5. 上传逻辑（upload-service 六步）

```
uploadFile(file, uploaderId, category)
  1. 校验类型（jpeg/png/gif/webp）
  2. 校验大小（≤5MB）
  3. 校验扩展名
  4. 安全文件名 = timestamp + 6位随机 + ext；落盘 public/uploads/yyyymm/
  5. sharp 生成 thumb(100²,80)/small(300×200,85)/medium(800×600,90)
  6. Media 入库（metadata 存缩略图 URL）→ 返回 {id,url,mediaId,thumbnails}
```

缩略图失败不阻断主流程（降级仅存原图）。

## 6. AI 对话逻辑（chat/completion）

```
POST {messages[≤40], sceneCode?, sessionId?}
  1. 取 isActive 的 AIConfig（updatedAt 最新）→ 无则 503
  2. sceneCode → ChatScene（可空）
  3. 知识检索：scene.useKnowledgeBase && knowledgeTags
     → tags 逗号拆分 → knowledge.findMany(status=active, tags contains 任一, priority desc, updatedAt desc, take 6)
     → 拼接 "[i] title\ncontent"
  4. system = AIConfig.systemPrompt + scene.systemPrompt + 知识段（"---" 分隔）
  5. 转发 endpoint/chat/completions（Bearer apiKey，temperature/maxTokens 取配置）
     超时 88s；5xx → 15s 短重试 1 次
  6. 返回 reply/model/tokensUsed/responseTime/scene/knowledgeHit
```

> 重构期（N10）路由策略：default 模型 → 失败/超时 → 按 priority 降序尝试备用 → 兜底模型；余额不足触发邮件提醒（N11）。

## 7. 发布逻辑（现状）

- 文章：draft → published（publishedAt 补 now）→ archived；slug 唯一；置顶/推荐/热门三开关影响排序（isTop > publishedAt > createdAt）。
- 浏览计数：详情页 viewCount+1（Article）与 ViewStats 聚合并行。
- 报名线索：pending 起，后台可改状态。

## 8. 日志逻辑

- 写操作（create/update/delete/login）→ OperationLog：module/action/title/content({before,after})/ip(x-forwarded-for)/ua。
- 读取接口不记日志（仅查询类 logs API 供后台翻看）。

## 10. 重构期新增逻辑（对应 16-新增设计）

| 逻辑 | 概要 |
| --- | --- |
| 采集调度 | 定时器（cron 表达式）→ 逐源抓取 → 解析 → 去重（URL hash + 标题相似）→ CollectItem → 默认生成知识库文件 → 待审核 |
| 自动发布 | PublishJob 状态机：pending → reviewing → scheduled → publishing → published/failed；到点执行官网落库 / 公众号草稿+发布；发布前先触发邮箱提醒（N11） |
| markdown 管线 | 入库存 markdown 原文 → 渲染时转 HTML（含代码高亮/图片懒加载）→ 同步生成 excerpt |
| 模型路由 | priority 排序 + isDefault 命中 + 失败降级链 + isFallback 兜底 + 余额阈值监控 |
| 邮件提醒 | 规则引擎（事件→模板→收件人组）→ SMTP 异步发送 → NotifyRecord 留痕 + 失败重试 |

## 11. 补充（2026-10-10 第二轮实测）

### 11.1 block-registry 完整区块清单（8 个）
`home-banner`(hero, query→Banner 表) / `home-topbar`(banner, settings) / `home-stats` / `home-intro` / `home-courses` / `home-news` / `home-cta` / `home-partners`
> 与 DB ContentBlock 种子（home-banner/news-list/sidebar-hot/course-recommend）**并非同一集合**：Registry 面向首页渲染（代码 SSOT），DB 种子面向 PageTemplate 组合（表驱动）——两套"区块"概念并存，重构期须合并为"Registry 定义 + DB 覆盖值"单轨（→ 08-复用设计 R8）。

### 11.2 客户端设置合并逻辑（useSettings，实测）
```
useSettings() ["use client"]
  初始 = Registry 默认值（getDefaultValues 构建期注入）
  mount → GET /api/settings（公开合并结果，扁平对象）
  合并：Registry 默认 ⊕ 服务端值
  getSetting(key, dv) = 服务端值 ?? Registry 默认值 ?? dv
```
- 兼容两种响应格式（数组 `[{key,value}]` / 对象 `{key:value}`）→ 契约不严格（→ 13-响应设计 §7）。
- 每个挂载组件独立 fetch，无共享缓存/去重（→ 10-性能设计 P8）。

### 11.3 种子幂等语义（运维须知）
- 绝大多数 seed upsert 的 update 分支为空 `{}`：重跑**不覆盖** DB 中已修改的值（仅补缺失）。
- **例外：HomeCard**——existing 时用种子值整体覆盖（重跑会重置首页卡片）。
- seed-knowledge-scenes.mjs 走本地 HTTP API（需 dev 启动 + admin 登录），与 seed.ts 直连 DB 双通道并存 → 重构期统一为 seed 单通道。
