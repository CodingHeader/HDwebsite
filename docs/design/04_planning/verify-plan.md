## 4. 执行方法与修复流程

1. 每阶段：浏览器真实操作（截图留证）→ API 探针核对 → 问题登记（P0/P1/P2）
2. 修复：立即修复 P0/P1（diff 最小化）→ **复测该用例 + 相邻用例回归** → 证据落盘
3. 熔断：同一问题修复 2 次未过 → 停手登记 blocked，不硬撞
4. 证据：`06_validation/evidence/EVD-VERIFY/`（截图 + 探针输出 + 问题台账）
5. 独立校验：轮末由子代理复审修复 diff 与证据链

## 5. 范围与 MUST NOT

- 不做：真实邮件投递（无 SMTP）、真实公众号调用（无凭证）、Coze 答案生成（PAT 过期）——验证降级路径为准
- 不引入新依赖；不改冻结契约语义；不重排数据基线
- 测试账号：admin/admin123（本地 dev 库）
