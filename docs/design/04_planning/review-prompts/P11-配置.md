## 目标
生产启动按优先级加载 `.env.production.local > .env.local > .env.production > .env` 并在启动时用 zod 校验；main 的设置键与重定向全部对等；Docker 部署件可构建运行；构建无配置警告。

## 输入
- 文档：11-配置设计.md、ADR-009/021
- 契约：`src/contracts/setting.ts`（SettingDefinition）
- 前置任务：P10
- 前置状态：`scripts/migrate-setting-keys.mjs` 映射表（9 键）可读

## 输出（新增/修改文件）
- `src/lib/env.ts`（新）：zod `envSchema`（JWT_SECRET≥32、ENCRYPTION_KEY 可选≥32、DATABASE_URL、PORT 默认 6789、APP_ORIGIN url、CRON_SECRET 可选、WECHAT_MP_VERIFY_TOKEN 可选）；`instrumentation.ts` 启动时校验，失败打印缺失键并退出
- `scripts/start-next.mjs`：启动 standalone 前用 Next 自带 `@next/env` 的 `loadEnvConfig(projectRoot)` 加载 env 并传入子进程（不复制密钥文件到 standalone 目录）
- `.env.example`：补全键说明（与 envSchema 一一对应）
- `src/lib/settings-registry.ts`：补齐缺失键（默认值取 main `settings-registry.ts` 原值；品牌按 ADR-010"弘道教育"）；`scripts/migrate-setting-keys.mjs` 映射表补对应旧键
- `next.config.ts`：恢复 main 全部 redirects（`/news/:id` 指向 `/articles/:id`、`/news` → `/articles` 保持 upgrade 写法）；移除 `cssChunking`
- `Dockerfile`、`docker-compose.yml`、`.dockerignore`（基于 main 版本，改为 node:24-alpine、standalone 输出、挂载 `prisma/`（仅 db）、`uploads/`、`backups/` 卷，健康检查 `/api/health`）
- 测试：`src/lib/__tests__/env.test.ts`、`src/lib/__tests__/settings-parity.test.ts`（main 键集合 ⊆ upgrade 键集合，main 键表以 fixture 形式存于测试目录）、`src/lib/__tests__/redirects.test.ts`（导入 next.config 断言 redirects 覆盖 main 清单）
