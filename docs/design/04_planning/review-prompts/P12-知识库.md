## 目标
1. 新增 KnowledgeBase / KnowledgeFile 实体：KnowledgeBase 映射 Coze 文本知识库（`cozeDatasetId`），KnowledgeFile 映射 Coze document（`cozeDocumentId`、`cozeStatus` 0/1/9、进度）。
2. 文件上传：白名单 `.docx/.doc/.md/.markdown/.txt`，扩展名 + MIME + 文件头三重校验；PDF（`%PDF`）与图片（image/* 或 PNG/JPEG/GIF/WEBP/BMP 等文件头）返回 400，中文提示"仅支持 Word（.docx/.doc）、Markdown（.md）、TXT 文件，不支持 PDF 和图片"；单文件 ≤10MB。
3. Coze 同步：`POST {apiBase}/open_api/knowledge/document/create`（Header `Authorization: Bearer <PAT>`、`Content-Type: application/json`、`Agw-Js-Conv: str`；body `dataset_id`、`document_bases[{name, source_info:{file_base64, file_type}}]`（每批 ≤10）、`chunk_strategy`（必传，默认 `{chunk_type:0}`）、`format_type:0`）；file_type 映射 docx→`docx`、doc→`doc`、txt→`txt`、**md/markdown→`txt`**（Coze 文本库本地文件仅支持 pdf/txt/doc/docx）；进度查询与删除走 Coze 对应接口（实现时以 https://docs.coze.cn 当前文档为准并在证据中记录 URL）；新建库可选"在 Coze 创建 dataset"（`POST /v1/datasets`，需 `space_id`、`format_type:0`）或"绑定已有 dataset_id"。
4. 本地兜底：上传时解析为纯文本并切分（≤800 字/块，重叠 100 字）生成 Knowledge 条目（`baseId/fileId/chunkIndex`）；txt/md 直接读取；docx 使用新增解析依赖（候选 `mammoth`，证据中说明体积/许可证/安全影响）；doc 若无可接受的纯 JS 解析依赖 → 本地 `localParse=skipped`，仅 Coze 侧解析，后台明示。本地检索改为：按库过滤 → 中文二元分词（bigram）+ 关键词 + 标题加权的 BM25 风格打分（纯 TS），SQLite 侧 `LIKE` 预筛候选 ≤500。
5. ChatScene 绑定：`knowledgeBaseIds[]`、`providerIds[]`（场景内优先级，空则走全局 default→priority→fallback）、`systemPrompt`、`temperature/maxTokens/topP` 覆盖；provider kind=coze 时由绑定了 dataset 的 Coze 智能体回答（知识在 Coze 侧），其他 provider 注入本地兜底检索结果；chat-service 两渠道共用。
6. 采集入库：采集源可指定目标库（默认"采集资讯"库，seed 创建）；P06 autoToKb 钩子在写本地条目后，把条目 Markdown 以 `txt` 推送到该库的 Coze dataset（无凭证/无权限时只写本地并记录原因）。
7. 凭证：Coze PAT 复用 kind=coze 的 LLMProvider（加密存储），知识库同步使用的 provider 与 `space_id` 进 Setting（新键 `kbCozeProviderId`、`kbCozeSpaceId`，后者加密/脱敏）；PAT 缺 `createDocument` 等权限 → 返回明确的权限提示（Coze 错误码 4013 等），本地兜底仍可用。
