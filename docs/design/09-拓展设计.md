## 1. 现有拓展点

| 拓展点 | 机制 | 拓展方式 |
| --- | --- | --- |
| 页面模板 | PageTemplate（code/layout/contentType/templateFile） | 新增模板记录 + 模板文件即可上新页面形态 |
| 内容区块 | ContentBlock + TemplateBlock + block-registry | 新区块 = 注册 code + 组件，模板插拔组合 |
| 元素级配置 | ElementConfig（layer 1-14 / 三态样式 / interactions） | 交互点可配置化登记（712 交互点体系） |
| 导航/分类无限级 | 自关联 parentId + level | 树形自然扩展 |
| 设置项 | settings-registry 增项即生效（动态表单） | 加 definition 即新增后台配置，无迁移（Setting KV） |
| AI 场景 | ChatScene 行级配置 | 加一行 = 新咨询入口（欢迎语/提示词/知识 tag） |
| 知识源 | Knowledge.source（local/notion/feishu/web） | 预留外部同步标识 |
| 内容多态 | Category.templateList/templateDetail | 分类绑定不同模板 |

## 2. 拓展性短板

| 短板 | 影响 |
| --- | --- |
| next.config redirects 硬编码 20+ 条 | 路由变更需改配置重发布 → 应改为 DB 驱动或动态捕获 |
| 大模型单激活（AIConfig.isActive 单选） | 无法多模型/降级（N10 解决） |
| 知识检索为 LIKE contains | 语义检索不可拓展（12 章解决） |
| 无多站点概念 | 公众号等新渠道无承载模型（N1 解决） |
| 定时任务缺失 | 无法定时发布/采集（N2/N3 解决） |

## 3. 重构期拓展架构（新增设计的通用基座）

### 3.1 渠道抽象（N1）
```
ContentItem（内容中枢）
   ├─ WebsiteChannel   → 官网 Article/页面（markdown→网页）
   ├─ WechatChannel    → 公众号草稿/文章
   └─ KnowledgeChannel → 知识库文件（采集默认入库）
```
新增渠道（如抖音号/头条号）= 实现一个 Channel Adapter。

### 3.2 任务调度基座（N2/N3/N5/N11）
- `Job` 表：type（collect/publish/notify）/ payload JSON / cron / status / lastRunAt / nextRunAt。
- 单 worker 进程轮询到期任务；失败指数退避 + 邮件告警。

### 3.3 模型路由（N10）
- LLMProvider 行级注册 → 任意 OpenAI 兼容端点即插即用。
- 路由规则：默认模型 → 优先级链 → 兜底模型，全部 DB 配置。

### 3.4 检索拓展预留（N7）
- Chunk 表结构预留 `embedding BLOB/JSON` 字段与 `vectorProvider` 配置位；当前用关键词检索，向量检索为增量升级不改表结构。

## 4. 部署拓展

- 现状：宝塔单机 + SQLite + standalone；docker-compose 就绪。
- 拓展预留：SQLite → PostgreSQL 仅需换 datasource + adapter（Prisma 7 已抽象）；文件落盘 → OSS/S4 同样收敛在 upload-service 单点内。

## 5. 补充（2026-10-10 第二轮实测）

- **区块双体系待合并**：block-registry（8 个首页区块，代码 SSOT）与 ContentBlock 表种子（4 个，模板组合用）是两套"区块"概念 → 统一为"Registry 定义 + DB 覆盖值"单轨（→ 06 §11.1）。
- **菜单即拓展入口**：新功能模块只需 ManagerMenu 加行（code/label/icon/path/permission）+ API 对应权限点，Sidebar 自动渲染——采集/发布/知识库/模型/提醒等新模块无需改前端框架代码。
- **seed 幂等模式平移**：新增设计的初始化数据（默认知识库、默认提醒规则、LLMProvider 占位）沿用"update 空分支 upsert"模式，避免覆盖运维配置。
