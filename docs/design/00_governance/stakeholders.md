# Stakeholders（角色与责任）

## 1. 角色定义

| 角色 | 承担者 | 职责 | 核心诉求 |
| --- | --- | --- | --- |
| 产品所有者 | 用户（项目决策人） | 提出需求、确认决策（C1~C8 先例）、验收里程碑、把控业务方向 | 决策成本低、进度可视、风险提前告知 |
| AI Agent | 辅助开发智能体 | 设计提取、方案设计、代码实现、验证执行、文档维护；无上层事实修改权 | 事实源唯一、任务边界清晰、验证口径明确 |
| 运营 | 待定（产品所有者指派） | 采集源维护、采集内容审核、知识库运营、提醒收件人维护、内容发布操作 | 操作全后台化、审核高效、少手工排版、不漏发 |
| 站长/开发 | 待定 | 线上部署、宝塔运维、备份核验、故障处置 | 部署简单、可回滚、异常有邮件告警 |

> 运营为重构后新增岗位预期：系统内暂无对应 RBAC 角色（见 §3 建议，随 SOL-002/004 落地评估）；审核操作权限 SuperAdmin 独享（`review:edit`，ADR-017），Editor 仅起草。

## 2. 关键流程责任矩阵（R=负责 A=批准 C=知会）

| 流程 | 产品所有者 | AI Agent | 运营 |
| --- | --- | --- | --- |
| 新需求提出与批准 | A | C（分析归档） | R（可提出） |
| 技术决策（ADR） | A | R（起草） | — |
| 采集内容审核入知识库 | — | — | R |
| 内容发布（官网/公众号） | A（策略级） | — | R（逐篇操作/定时任务监护） |
| 发布前提醒 | 知会 | 实现 | R（收件并关注） |
| 里程碑验收（M1~M4） | A | R（验证执行与证据） | C |

## 3. 系统内账号角色（RBAC，与上表区分）

| 角色 | slug | 用途 |
| --- | --- | --- |
| SuperAdmin | super-admin | `["*"]` 全权限，默认账号 admin（上线必须改密） |
| Editor | editor | 内容管理（按 permissions JSON） |
| Viewer | viewer | 只读 |

> 重构期建议：新增"运营"专用角色，收敛到内容/采集/知识库权限（随 SOL-002/004 落地评估）。
