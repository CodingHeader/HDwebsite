# 05 · 风险与待裁决

## 一、BLOCKING（须用户裁决，不得假设）

### B-1 · 推送凭据（状态更新：remote 已被改为 CodingHeader）

**实测现状**（2026-10-29 复核）：

```bash
$ git remote -v
origin  https://github.com/CodingHeader/HDwebsite.git (fetch/push)

$ GIT_TERMINAL_PROMPT=0 git push origin upgrade
fatal: could not read Username for 'https://github.com': terminal prompts disabled
```

**已排除的误判**：
- 不是网络问题：`http.proxy = http://127.0.0.1:10808` 已配置且可用（`ls-remote CodingHeader` 匿名成功返回）
- 不是仓库不可达：`CodingHeader/HDwebsite` 匿名可读，`upgrade` 分支 HEAD = `5f92871`

**根因**：仓库为私有写权限，HTTPS 推送需凭据，本机无 credential helper（全局 `manager` 不可用，`~/.ssh/id_ed25519_aideanew` 未授权该仓库）。

**当前阻塞的具体范围**：仅 `47e3c43`（V2.1 规划提交）1 个提交未推送；`5f92871` 及之前均由执行会话推送成功。

**方案**：

| 方案 | 做法 |
|---|---|
| **A** | 用户提供 PAT，经临时环境变量 + 内联 credential helper 使用，用后即清（执行会话已用此法成功推送过） |
| **B** | 授权 `~/.ssh/id_ed25519_aideanew` 到该仓库后改 SSH |
| **C** | 维持本地提交，双端暂不一致 |

### B-4 · visual job 现阻断主门禁，且基线未随前台改动重建（本轮新发现）

**实测事实**：

```bash
$ awk '/^  visual:/{f=1} f&&/^    runs-on:|^    continue-on-error:/{print} f&&/^    steps:/{exit}' .github/workflows/ci.yml
    runs-on: ubuntu-latest
    continue-on-error: false  # V9-VIS-03 收口：…visual 失败自此刻阻断主门禁

$ git log -1 --format=%ad --date=short -- tests/visual/reference/
ad4cf70e 2026-10-27          # 基线最后一次更新

$ git log --oneline ad4cf70e..HEAD -- tests/visual/reference/
（空 —— 基线未随后续前台改动更新）
```

**矛盾点**：`ci.yml` 里有两层互相矛盾的注释。

| 位置 | 原文 | 状态 |
|---|---|---|
| 第 4 行 | 「不跑 visual：参照机是 Windows，Linux 字体渲染会出现 11 处固定差异」 | **已过期**（V0.7 时期） |
| 第 13-15 行 | 「V9-VIS-03：基线重生成入口。参照图只能在与 CI 相同的 Linux 环境重生成…重生成走 CI 而非本机」 | **现行** |

**实际配置**：visual job 存在，`runs-on: ubuntu-latest`，`continue-on-error: false`（**失败即阻断主门禁**），并配 `workflow_dispatch` 的 `visual_update_ref` 开关用于重生成基线。

**风险推演**：

| 时间 | 事件 | 对 visual 的影响 |
|---|---|---|
| 10-27 | 基线 `ad4cf70e` 更新 | — |
| 10-29 | `88e72d69` 改前台 `FloatingContact.tsx` / `Navbar.tsx`（含 375 视口差异） | **375 基线应失配** |
| 10-29 | M3-01 改 `src/components/manager/**` | 无影响（visual 只覆盖 15 个前台路由，`grep manager` = 0） |

**结论**：`88e72d69` 之后如果 CI 跑过 visual，**极可能已失败并阻断主门禁**。但执行报告描述的是「本地 win32 视觉 40 FAIL → 交 Linux CI 重建」，**没有验证过 CI 上 visual 的实际状态**。

**需裁决**：是否立即触发 `workflow_dispatch`（`visual_update_ref=true`）重生成基线？若 CI 确实红着，所有后续提交都在破窗状态。

**不自行判断**：需用户确认 CI 当前是否失败（需要 Actions 权限或用户告知）。
