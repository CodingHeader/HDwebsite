# 03 · 垂直切片与任务卡

## 一、切片划分

本项目不是从零建设，而是**在既有系统上核查与修补**。因此切片不是"新功能端到端"，而是**端到端的可验证行为链**。

| 切片 | 名称 | 可演示的最终行为 | 任务卡 |
|---|---|---|---|
| **S1** | 启动链路自证 | 任何人执行 `npm start` 后，能确定打开的是 HDwebsite，且数据可用 | ENV-01、ENV-02 |
| **S2** | 前台差异审计 | 能逐组件回答"这个差异是合规/有据/无据" | AUD-01、AUD-02 |
| **S3** | 功能对等复核 | 能回答"origin/main 的每个功能在 HEAD 是否都在" | PAR-01、PAR-02 |
| **S4** | 收口 | V2.1 全部结论可查、双端一致 | E1 |

**为什么这样切**：用户的核心诉求是"检查未被实现的需求和异常部分"。三组切片分别对应**环境异常（S1）**、**视觉异常（S2）**、**功能异常（S3）**，互不重叠，可并行。

**第一刀为什么是 S1**：用户报告的是"启动后看到的界面"，说明问题出在启动链路。若 S1 不先澄清（打开的是哪个项目），S2/S3 的结论可能全部建立在错误前提上。

### ENV-01：启动契约固化

## 归属
- 所属切片：S1
- 来源需求：M-4（能正常启动）、M-5（端口不混用）、I-2（一条命令跑起来）
- 来源方案：`02-契约与不变量.md` §二

## 目标
`npm start` 后服务可用，且缺少必需条件时**在监听端口之前**明确失败，不出现"能打开但报错"。

## 输入
- 文档：`docs/V2.1-20261029/02-契约与不变量.md` §二
- 契约：启动契约 L-1~L-4、数据库契约 D-1/D-2
- 前置任务：无
- 前置状态：无

## 输出
- `scripts/start-next.mjs`：env 校验前置到 spawn 之前
- `scripts/start-next.mjs`（或新建 `scripts/check-db.mjs`）：DB 迁移状态检测
- `.env.example`：补齐 `ENCRYPTION_KEY`、`APP_ORIGIN` 与最小长度说明
- `docs/design/06_validation/evidence/V21/ENV-01/{execution.md,before-after.json}`

## Execution Steps
1. [ ] 读 `src/lib/env.ts`，确认校验函数是否可独立调用（不依赖 Next 运行时）
2. [ ] 在 `start-next.mjs` 的 spawn 之前插入 env 校验，缺失则 `console.error` + `process.exit(1)`
3. [ ] 新增 DB 检测：`production` 下连 `DATABASE_URL`，查 `sqlite_master` 是否含 `CronJob`/`Setting` 等关键表
4. [ ] 缺表时输出可复制的修复命令（`npm run db:deploy && npm run db:seed`）后退出
5. [ ] 补 `.env.example`
6. [ ] 三情形实测：正常启动 / 缺 env / DB 未迁移

## 验收标准
- [ ] 缺 `ENCRYPTION_KEY` 时进程退出码 ≠ 0，且**端口未被监听**
- [ ] DB 未迁移时进程退出码 ≠ 0，输出含 `db:deploy` 字样
- [ ] 正常情形服务 200
- [ ] `.env.example` 含 4 个必需键
