# 01 · 需求复核与冲突

## 一、复述与拆解

### 1.1 项目要解决的核心问题

HDwebsite 是**弘道教育的官网 + 管理后台**。`upgrade` 分支（当前主线）是对 `origin/main@94dbbbb`（旧站）的**技术栈重建**（Next 16 + React 19 + Prisma 7 + Tailwind v4），要求：

> **功能对等**（main 每个功能都必须存在）+ **前台视觉不变**（红横幅风格逐字一致）+ **管理端顶级体验**。

用户本次报告的问题：启动后看到移动端布局、设计与导航全变 —— **即"前台视觉不变"这条核心要求可能被破坏**。

### 1.2 用户 / 管理端 / 系统边界

| 角色 | 边界 |
|---|---|
| 访客（前台） | `src/app/(web)/**` + `src/components/web/**`，16 个页面 |
| 管理员（后台） | `src/app/manager/**`，43 个页面，需登录 + 角色权限 |
| 系统边界内 | 本仓库代码、`prisma/` 数据、`public/` 资源 |
| 系统边界外 | Aidean / AideanBot 等其它项目（**同机同端口冲突是本次问题的关键**） |

## 三、冲突清单

### 3.1 MUST 之间

| 冲突 | 分析 | 处置 |
|---|---|---|
| M-1（视觉一致）× M-4（正常启动） | 无冲突。启动问题在数据层，视觉在渲染层 | 分别处理 |
| M-1 × M-5（端口隔离） | **无冲突但有关**：若用户误开 3000，会把 Aidean 的外观误判为"HDwebsite 视觉被改"，从而触发错误的修复方向 | **必须先澄清 URL**（BLOCKING B-2） |

### 3.2 MUST × MUST NOT

| 冲突 | 分析 |
|---|---|
| M-1（视觉一致）× N-1（不改视觉） | 表面矛盾。实际：M-1 是**验收标准**（要求现状符合），N-1 是**改动约束**（不许为了"看起来对"而改）。二者一致：若发现偏离，应**审计归因**而非直接改回 |

### 3.3 非功能 × 功能复杂度

| 项 | 分析 |
|---|---|
| 性能（LCP 2.5s）× 视觉保真 | V2.0 的 LCP-01 已裁定以真实浏览器为准（136ms PASS），不构成冲突 |

### 3.4 需求 × 技术约束

| 冲突 | 分析 |
|---|---|
| M-5（端口隔离）× 同机多项目 | 本机同时存在 Aidean（3000）、AideanBot（3333）、HDwebsite（6789）。用户的项目清单里 Aidean 分配 3000-3100、HDwebsite「按原配置」= 6789。**技术上无冲突，但用户认知上易混** |

## 四、未知登记册

### 4.1 BLOCKING（必须由人裁决，不得假设）

| # | 未知项 | 为何阻塞 | 条件方案 |
|---|---|---|---|
| **B-2** | **用户访问的是哪个 URL？** | 决定根因是"开错项目"还是"HDwebsite 真缺陷"，两者修复方向完全不同 | **方案 A**：若为 `:3000` → 无需改代码，加端口守卫（ENV-02）即闭环<br>**方案 B**：若为 `:6789` → 需用户提供截图，按实际现象重新定位，本轮规划的 AUD/PAR 卡仍有效<br>**共同部分**：ENV-01（启动契约 + DB 初始化）在两方案下都需要<br>**分叉点**：是否新增"前台视觉修复"卡 |
| **B-1** | `git fetch`/`push` 的凭据如何提供 | 无法拉取最新远端、无法推送（用户已要求双端一致） | **方案 A**：用户提供 HTTPS PAT（经临时环境变量，不落盘）<br>**方案 B**：改用 SSH（`git@github-aideanew:nevermeetagain/HDwebsite.git`）<br>**共同部分**：本地提交可先完成，推送延后 |

## 五、隐含要求与前置条件

### 5.1 隐含要求（用户没说但显而易见必需）

| # | 要求 | 依据 |
|---|---|---|
| I-1 | 启动后**不会**被其它项目的界面误导 | 本次问题本身就是被误导 |
| I-2 | 新接手的人能一条命令跑起来 | 当前需手工补 2 个环境变量 + 初始化 DB |
| I-3 | 前台视觉差异有据可查 | 否则下次独立验证无法判断"这是授权例外还是违规" |

### 5.2 未说明但必需的前置条件

| # | 前置 | 当前状态 |
|---|---|---|
| P-1 | `ENCRYPTION_KEY` ≥32 位 | **缺失**（`[env] FATAL` 实测） |
| P-2 | `APP_ORIGIN` | **缺失**（同上） |
| P-3 | `JWT_SECRET` ≥32 位 | 已有（`.env.local`） |
| P-4 | `DATABASE_URL` 指向已迁移的库 | `dev.db` 0 字节 → **未迁移** |

### 5.3 可能产生歧义的表述

| 表述 | 歧义 | 我的解读 |
|---|---|---|
| "界面呈现的是移动端" | 是浏览器视口窄？还是布局落到了移动分支？还是打开了移动端项目？ | **三者都可能是**。实测排除前两者（≥768px 正常），故指向第三者 |
| "功能都发生了大变化" | 是功能缺失，还是入口位置变了，还是打开了别的产品？ | 已确认文件零丢失；"大变化"更符合"打开了 Aidean" |

### 5.4 可能造成失败的边界条件

| # | 边界 | 影响 |
|---|---|---|
| E-1 | 3000 被 Aidean 占用 | 用户默认 3000 → 必然误判 |
| E-2 | `dev.db` 0 字节 | 首页 200 但内容退化，易误判为"设计变了" |
| E-3 | win32 下 `output: standalone` 关闭 | 生产启动脚本回退 `next start`（已在 `next.config.ts` 处理） |

### 5.5 与其他模块的依赖

| 依赖 | 说明 |
|---|---|
| Aidean（同机 3000） | **直接冲突源**，但不属本项目范围，只能规避不能修改 |
| AideanBot（3333） | 无冲突 |
| 共享 SQLite 文件 | 无共享，各自独立 |
