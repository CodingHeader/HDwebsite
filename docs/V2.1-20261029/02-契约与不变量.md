## 二、新增契约 ①：启动契约

### 2.1 定义

**唯一源**：`scripts/start-next.mjs` + `package.json` 的 `scripts` 字段。其它文档（README、AGENTS.md）只能引用，不得另立数值。

### 2.2 必须成立的四条

| # | 契约 | 当前值 | 验证方式 |
|---|---|---|---|
| L-1 | dev 端口唯一 | `6789`（`package.json` `"dev": "next dev -p 6789"`） | `grep '"dev"' package.json` |
| L-2 | start 默认端口唯一 | `6789`（`scripts/start-next.mjs:17` `process.env.PORT \|\| "6789"`） | `grep 'PORT ||' scripts/start-next.mjs` |
| L-3 | 必需环境变量可枚举 | `JWT_SECRET`、`ENCRYPTION_KEY`、`APP_ORIGIN`、`DATABASE_URL` | `src/lib/env.ts` 的校验表 |
| L-4 | 缺变量时**报键名不报值** | 已实现（实测输出 `[env] FATAL: … - ENCRYPTION_KEY - APP_ORIGIN`） | 起服务观测 |

### 2.3 L-3 的实测缺口

```bash
$ PORT=6789 NODE_ENV=production node scripts/start-next.mjs
- Local: http://127.0.0.1:6789
✓ Ready in 199ms
[env] FATAL: 以下环境变量缺失或不符合要求，拒绝生产启动（只列键名，不显示值）：
  - ENCRYPTION_KEY
  - APP_ORIGIN
```

**问题**：进程已 `Ready` 后才报 FATAL，端口已监听但服务不可用 → 用户看到"能打开但报错"或"打不开"，难以定位。

**契约要求（ENV-01 修正）**：env 校验须在**监听端口之前**完成，缺失即退出（exit code ≠ 0）。

### 2.4 数据库初始化契约

| # | 契约 | 当前 |
|---|---|---|
| D-1 | 存在单条命令完成 建库+迁移+种子 | 部分（`npm run db:deploy` + `npm run db:seed` 两条） |
| D-2 | 启动前检测 DB 是否已迁移 | **缺失**（dev.db 0 字节仍启动成功，运行时才报 `no such table`） |

**契约要求（ENV-01）**：启动脚本在 `NODE_ENV=production` 下检测关键表是否存在，缺失则打印明确指引并退出。

## 三、新增契约 ②：端口契约（多项目共存）

### 3.1 本机实际端口分配（实测）

| 端口 | 归属 | 证据 |
|---:|---|---|
| 3000 | **Aidean**（AI 模型天梯图平台） | PID 14304 命令行 `E:\Code\Aidean\...\next@15.5.28...\start-server.js` |
| 3333 | AideanBot（记忆记载） | 未实测 |
| **6789** | **HDwebsite** | `package.json` dev + `start-next.mjs` |

### 3.2 契约条款

| # | 条款 |
|---|---|
| P-1 | HDwebsite 的端口为 **6789**，不得改为 3000（会与 Aidean 冲突） |
| P-2 | 任何文档、脚本、`.env.example` 中出现 HDwebsite 的端口，必须是 6789 |
| P-3 | 无法修改其它项目，只能让本项目**自证身份**（ENV-02） |

### 3.3 ENV-02 的自证方案（防误认）

启动后在控制台输出：

```
[HDwebsite] 弘道教育官网 · 管理后台
  URL   http://127.0.0.1:6789
  前台  /            后台  /manager
  校验  http://127.0.0.1:6789/api/health → {"app":"hdwebsite"}
```

并把 `app` 标识加入 `/api/health` 响应（若已有则复用，不新增端点）。

**契约要求**：`GET /api/health` 返回体含 `app: "hdwebsite"` 与 `port` 字段，使任何人可用一条 curl 确认"我打开的是哪个项目"。

## 四、新增契约 ③：前台差异审计口径

### 4.1 问题

`git diff origin/main..HEAD` 中，前台有大量"看起来变了"的行，但大部分是**缩进变化**（JSX 包裹层）而非 className **值**变化。

### 4.2 审计契约（唯一口径）

```
差异 = className 属性的「值集合」之差
     ≠ 行数之差（受缩进/换行影响）
```

**提取方式（可复跑）**：

```bash
# main
git show origin/main:src/components/web/<C>.tsx | grep -oE 'className="[^"]*"' | sort -u > main.txt
# HEAD
grep -oE 'className="[^"]*"' src/components/web/<C>.tsx | sort -u > head.txt
comm -23 main.txt head.txt   # main 独有（被删除/改写的值）
comm -13 main.txt head.txt   # HEAD 独有（新增/改写的值）
```

### 4.3 三档定性

| 档 | 判定条件 | 处置 |
|---|---|---|
| **合规** | HEAD 独有值为**新增**（main 的值全部保留），且属 `emptyAction`/`showOverlay` 等 A3 卡片能力 | 记录，不阻断 |
| **有据例外** | main 的值被替换，但**有 ADR 或卡片引用**（如 ADR-039、V10-Q1 用户授权） | 记录 + 引用出处 |
| **无据改写** | main 的值被替换，**无任何 ADR/卡片记录** | **FAIL，须 AUD-02 归因** |

### 4.4 当前审计结果（实测）

| 组件 | main 独有值 | HEAD 独有值 | 定性 |
|---|---:|---:|---|
| StatsBanner | 0 | 0 | ✅ 完全一致 |
| TopBanner | 0 | 1 | ✅ 合规（新增包裹层，原值保留） |
| Banner | 0 | 2 | ✅ 合规（新增 extraBtn 按钮类） |
| Navbar | 1 | 2 | ⚠️ **有据例外**（V10-Q1 用户 2026-10-24 授权，源码注释可查） |
| FourCards | 2 | 2 | ❌ **无据改写**（`relative flex-1` → `absolute inset-0 …`） |

**FourCards 的无据改写明细**：

```
main 独有：
  className="grid grid-cols-1 sm:grid-cols-2 md:grid-cols-3 gap-4 max-w-5xl mx-auto"
  className="relative flex-1"
HEAD 独有：
  className="absolute inset-0 bg-black/40 group-hover:bg-black/30 transition-colors"
  className="absolute inset-0 bg-cover bg-center transition-transform duration-300 group-hover:scale-105"
```

**注意**：`grid grid-cols-1 … max-w-5xl mx-auto` 在 HEAD 变为模板字面量 `` `grid ... ${gridAlignClass}` ``，值本身保留（`gridAlignClass` 默认为空），故第一项属**提取方式导致的假阳性**。真正的问题是第二项：`relative flex-1` → `absolute inset-0 …`。
