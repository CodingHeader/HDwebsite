## 二、本轮新发现的三个事实（改变了工作量估算）

这三条是上一轮规划时**没有**掌握的，直接决定颗粒度。

### 事实 1：375px 已有 4 个 e2e 用例，但只覆盖 3/42 个路由

**证据**：
- `tests/e2e/mobile-375.spec.ts` 存在，含 4 个 `test(` 调用
- 其中"整页无横向溢出"用例（`:57`）遍历的路径是：
  ```
  ["/manager/articles", "/manager/content-hub", "/manager/enrollment-offerings"]
  ```
  **只有 3 条**

**影响**：
- **可复用**：`scrollWidth ≤ 375` 的断言口径已存在，M1 不必从零设计（`mobile-375.spec.ts:61-62` 是现成的实现参考）
- **不可直接复用**：覆盖面 3/42 = 7.1%，剩余 39 个路由必须新采

**规划处置**：`V15-MOBILE-375-01` 的 M1 采用"扩展既有 spec"而非"另写脚本"，复用其断言写法。

### 事实 2：42 页可按实现方式分成 27 + 15 两类

**证据**（逐文件 `grep -q CrudPage`）：

| 类 | 数量 | 特征 |
|---|---|---|
| **A 类** | **27** | 走 `CrudPage`，五态由 CrudPage 统一提供（`CrudPage.tsx:333` Forbidden、`:370` PageHeader） |
| **B 类** | **15** | 自定义实现：`articles`、`chat-history`、`collect-items`、`content-hub`、`home-blocks`、`knowledge-bases`、`llm-providers`、`login`、`media`、`news`、`notify-rules`、`manager`、`publish-jobs`、`settings`、`wechat-accounts` |

**影响**：A 类 27 页的五态判定可**共用同一套判据**（因为渲染器是同一个），B 类 15 页必须逐页单独看。

**规划处置**：三张验收卡都按 A/B 两类分批，A 类批量核、B 类逐页核。这把 126 格的工作量压到"27 个复用判据 + 15 个独立判据"。

### 事实 3：B 类 15 页中，2 页无 PageHeader 但合理

**证据**：
```
login   pageHeader=0    ← 用 <h1>欢迎回来</h1>，登录页范式
news    pageHeader=0    ← 纯 redirect 到 /manager/articles
其余 13 页 pageHeader≥1
```

**影响**：`V15-UX-STATES-01` 判 login 的"成功态"时，它没有列表/表单，只能 N-A。news 是空白 redirect，全部 N-A。

**规划处置**：在判据表里为这 2 页预置 N-A 依据，避免执行者纠结。
