# 03 · 执行单元分解（三级以上完整大纲）

> 本文是 V1.6 的核心。层级定义：
> **L1 = Work Package（一张卡）** → **L2 = 阶段** → **L3 = 批次** → **L4 = 单步动作**
> 每个 L4 都必须是"做完能立刻判断对错"的动作。

---

## L1-1 · V15-UX-STATES-01（五态 42 页）

**目标**：42 页 × 5 态 = 210 格，每格判 `PASS` / `FAIL(现象)` / `N-A(依据)`，无"待核"。

### L2-1.1 · A 类 27 页批量核（共用 CrudPage 判据）

**为什么能批量**：这 27 页都 `return <CrudPage spec={...} />`，五态由 `CrudPage.tsx` 统一提供（`:333` Forbidden、`:370` PageHeader、文件头注释声明五态）。

#### L3-1.1.1 · 批次 A1：标准列表页 18 页

**清单**（从 27 页中去掉只读与配置类）：
`banners`、`campus`、`categories`、`chat-scenes`、`collect-sources`、`collect-tasks`、`courses`、`element-configs`、`enrollment-offerings`、`gallery`、`home-cards`、`hot-majors`、`knowledge`、`majors`、`notify-recipients`、`notify-templates`、`page-templates`、`partners`、`service-guides`、`students`、`tags`、`user-actions`、`users`、`wechat-accounts`
（以实际 `find` 结果为准，分批只为减少认知负担，不硬编码）

**L4 动作**（每页 5 步）：
- L4-1：空态 —— 在搜索框输入不可能命中的关键词（如 `zzz-no-match-zzz`），截图 → 判是否出现"无结果 + 下一步动作"
- L4-2：加载态 —— DevTools 设 Slow 3G，刷新 → 判是否出现骨架屏（非白屏）
- L4-3：错误态 —— DevTools 拦截 `/api/<resource>` 返回 500，触发一次列表请求 → 判是否有错误说明 + 重试按钮
- L4-4：无权限态 —— 用 `e2e-viewer` 登录（密码在 `tests/e2e/global-setup.ts`），访问需 EDITOR 的写操作 → 判是否出现 `Forbidden`
- L4-5：成功态 —— 完成一次写操作（新建→保存）→ 判 toast 文案是否具体（非"操作成功"）
- L4-6：把 5 格写入 matrix.md，每格附"做了什么 + 看到什么"

#### L3-1.1.2 · 批次 A2：只读页 5 页

**清单**（无写操作，成功态应 N-A）：`logs`、`notify-records`、`publish-jobs`、`chat-history`、`collect-items`

**L4 动作**：
- L4-1~L4-4：同 A1（空态用筛选条件构造 0 条）
- L4-5：成功态记 `N-A(纯只读页，无写操作)` + 依据（页面无新建/编辑按钮，`grep -c "新建\|编辑" <file>` 为 0）
- L4-6：落 matrix.md

#### L3-1.1.3 · 批次 A3：配置类 4 页

**清单**：`roles`、`navigations`、`settings`、`home-blocks`

**L4 动作**：
- L4-1~L4-5：同 A1，但注意 `settings`/`home-blocks` 有分组表单，错误态要拦截保存接口而非列表接口
- L4-6：落 matrix.md

### L2-1.2 · B 类 15 页逐页核（独立判据）

**为什么必须逐页**：这 15 页自定义实现，五态各写各的，不能共用判据。

#### L3-1.2.1 · B1 子批：内容域 5 页

`articles`、`media`、`knowledge-bases`、`content-hub`、`collect-items`

**L4**：每页 5 态 + 1 个"页面特有态"（如 `content-hub` 的"审核中"、`knowledge-bases` 的"上传失败"）

#### L3-1.2.2 · B2 子批：配置域 4 页

`settings`、`llm-providers`、`notify-rules`、`wechat-accounts`

**L4**：每页 5 态；`llm-providers` 额外验"无可用供应商时的兜底提示"

#### L3-1.2.3 · B3 子批：3 页特殊页

| 页 | 特殊性 | 预置判据 |
|---|---|---|
| `manager`（仪表盘） | 只展示统计，无 CRUD | 成功态 N-A；错误态验统计接口失败时的降级 |
| `news` | 纯 `redirect("/manager/articles")` | **5 态全 N-A**，依据：文件仅 2 个 import + redirect，无 UI |
| `login` | 登录页，非列表范式 | 空态/列表态 N-A；错误态 = 密码错误提示；成功态 = 跳转 |

#### L3-1.2.4 · B4 子批：2 页图表/预览页

`home-blocks`（区块排序）、`publish-jobs`（状态机可视化）

**L4**：额外验"排序/状态的空数据表现"

### L2-1.3 · 汇总与自检

- L3-1.3.1：matrix.md 计数自检（42 行 × 5 态，无空、无"待核"）
- L3-1.3.2：写 execution.md（5W1H + 判据说明 + PASS/FAIL/N-A 汇总）
- L3-1.3.3：FAIL 项单独列"缺陷清单"（现象 + 复现步骤），**不修代码**（本轮禁止改 src）

## L1-2 · V15-KEYBOARD-01（键盘 K1~K4）

**目标**：42 页 × 4 项 = 168 格。

### L2-2.1 · 全站共性验证（4 项，一份结论，避免重复劳动）

**为什么先做共性**：K3（Esc）、K4（焦点可见）由**共享组件**决定，不是每页各写一套。先验容器，再把结论套用到 42 页。

#### L3-2.1.1 · K3 · Esc 关闭弹窗

**L4 动作**：
- L4-1：静态确认 —— `grep -nE "Escape|onKeyDown" src/components/manager/ui/dialog.tsx`（98 行，预期无命中）
- L4-2：静态确认 —— 同命令查 `FormDialog.tsx`、`feedback/ConfirmDialog.tsx`
- L4-3：**运行时验证**（不可省）—— 打开"新建"弹窗，按 Esc，观察是否关闭
- L4-4：结论落地 —— 若 Dialog 无 Esc，则凡使用 Dialog 的页面 K3 均 FAIL，**在 matrix 里注明"共用同一 Dialog，同一缺陷"**，不重复 42 次相同描述

#### L3-2.1.2 · K4 · 焦点可见

**L4 动作**：
- L4-1：抽查 5 类元素（Button / Input / Select / 链接 / 卡片操作）
- L4-2：Tab 到每个元素，观察是否有可见 focus ring
- L4-3：检查 `outline: none` 是否无替代（`grep -rn "outline-none\|outline: none" src/components/manager | head`）
- L4-4：结论套用到 42 页

### L2-2.2 · 逐页 K1/K2

#### L3-2.2.1 · K1 · Tab 顺序（42 页）

- L4-1：每页从浏览器地址栏开始 Tab，记录焦点序列
- L4-2：判是否与视觉顺序一致（无跳跃/回跳）
- L4-3：落 matrix

#### L3-2.2.2 · K2 · 主操作可聚焦（42 页）

- L4-1：Tab 到"新建/保存/提交"
- L4-2：按 Enter，判是否触发
- L4-3：落 matrix

### L2-2.3 · 汇总

- L3-2.3.1：matrix.md（42 × 4）+ execution.md
- L3-2.3.2：若 K3 全站 FAIL → 单独一节说明影响面（涉及多少个 Dialog 使用者）+ 建议（转 V1.7 开卡修）
