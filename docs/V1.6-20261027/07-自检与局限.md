## 三、局限（自我否定）

### L1 · "第一刀是步行骨架"不适用

指令要求第一刀是"健康检查 + 鉴权写接口 + 一张表 + 一次迁移 + 前端打到真实 API"的最小闭环。V1.4 已完成该骨架，本轮无功能开发。强行造新骨架 = 伪造任务。**已改为"投入产出比最高"（A 类 27 页批量核）。这是偏离，显式登记。**

### L2 · 工时估算可能仍偏低

`03 附录` 估 16~20 小时（546 格）。依据是"每格约 2 分钟"，但实际含环境准备、截图、重复操作，可能达 24 小时以上。**这是估算不是承诺。**

### L3 · B1 未裁决，KEYBOARD-01 结论有作废风险

若裁决为完整集，42 页 K3/K4 需重判，且结论从"部分 PASS"变"全 FAIL"。**这是本规划唯一可能整卡作废的部分。**

### L4 · Dialog Esc 结论基于 grep，未经运行时验证

`dialog.tsx` 98 行，`grep -nE "Escape|onKeyDown"` 无命中。但 Esc 可能由父级 `onKeyDown` 或全局监听处理（如 `AppShell`）。**已登记 U2，由 S2-3 实测确认。不得仅凭 grep 写进最终报告。**

### L5 · 观察者偏差

本规划由 main-agent 写，S2 判定也由 main-agent 做。V1.4 代码由外部助手完成，故属"非同一人"。但仍在同一会话内，无法完全排除先验偏见。**已登记，不宣称"绝对客观"。**

### L6 · win32 限制使部分门禁本机不可跑

`test:e2e` / `test:visual` 需 Linux。本轮 S3 的全量门禁中，e2e 与 visual 实际无法在本机执行。**处置**：e2e 记 `UNKNOWN(需 Linux CI)`，visual 本轮不跑（0 前台改动）。**不假装跑过。**

### L7 · 546 格判定无法在单次会话内完成

按 L2 估算，三卡需 16~24 小时。单次会话不可能完成。**处置**：规划已按 L1→L2→L3→L4 拆分，每批次可独立产出证据，中断后可从未完成的 L3 继续。这是刻意为之 —— 与 V1.5 "一次做完"的假设不同。
